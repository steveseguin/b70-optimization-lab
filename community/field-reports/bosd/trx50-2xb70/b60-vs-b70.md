# Arc Pro B60 versus B70 on one contributor host

> **Evidence: `community-reported`; not run in the reference lab.** Numbers and
> environment below were supplied by bosd. Maintainer review checked the table
> arithmetic but did not reproduce the benchmark or inspect raw run artifacts.

Pinned contributor write-up:
[`results/b60-vs-b70.md`](https://github.com/bosd/trx50-arc-b70-benchmarks/blob/fda0d86c47ff02d8e36f813a8e0121a2152d4478/results/b60-vs-b70.md).

## Reported setup

- Host: ASRock TRX50 WS, Threadripper 9960X.
- GPUs: one Arc Pro B60 G21, 24 GB, versus one Arc Pro B70 G31,
  32 GB; tested one card at a time in the same host.
- Fedora Server 44, kernel 7.0.10, `xe` driver.
- SYCL: oneAPI 2026.0 and NEO 26.18.38308.1; Vulkan: Mesa 26.0.7.
- Workload: `llama-bench` prompt length 512 and generation length 128.
- Exact llama.cpp commit, model revisions, repeats, dispersion, and raw logs:
  not supplied in the pinned snapshot.

## Maintainer review

For the three rows with both GPUs measured:

- B60 generation is **69.3–88.0%** of B70, not 78–88%; the omitted low point
  is Qwen3-4B Vulkan.
- B60 prompt processing is **68.2–72.6%** of B70.
- Reported B60 card power is **52.2–62.5%** of B70.
- Using the reported card-power values, B60 generation per joule is
  **1.24–1.57×** the corresponding B70 value.

The B60 POST/console behavior is a useful observation about this contributor's
specific motherboard, firmware, and cards, not a general platform guarantee.
The recommendation against a mixed B60/B70 layer split is plausible but was
not measured in this table.

These data support a narrow statement: on the three contributor-measured
single-card comparisons, B60 traded absolute throughput and VRAM for lower
reported card power. They do not establish expected performance for other
models, builds, firmware, or hosts.
