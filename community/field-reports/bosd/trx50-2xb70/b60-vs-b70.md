# Arc Pro B60 versus B70 on one contributor host

> **Evidence: `community-reported`; not run in the reference lab.** Numbers and
> environment below were supplied by bosd. Maintainer review checked the table
> arithmetic but did not reproduce the benchmark or inspect raw run artifacts.

Pinned contributor write-up:
[`results/b60-vs-b70.md`](https://github.com/bosd/trx50-arc-b70-benchmarks/blob/fda0d86c47ff02d8e36f813a8e0121a2152d4478/results/b60-vs-b70.md).

## Reported setup

- Host: ASRock TRX50 WS, Threadripper 9960X.
- GPUs: one Arc Pro B60 G21, 24 GB, versus one Arc Pro B70 G31,
  32 GB; tested one card at a time in the same host.
- Fedora Server 44, kernel 7.0.10, `xe` driver.
- SYCL: oneAPI 2026.0 and NEO 26.18.38308.1; Vulkan: Mesa 26.0.7.
- Workload: `llama-bench` prompt length 512 and generation length 128.
- Exact llama.cpp commit, model revisions, repeats, dispersion, and raw logs:
  not supplied in the pinned snapshot.

## Reported mixed B60 + B70 layer split

A separate run supplied in
[PR #17](https://github.com/steveseguin/b70-optimization-lab/pull/17)
adds a mixed-split measurement absent from the single-card table above. The
contributor identifies the workload as Llama-3.3-Nemotron-Super-49B (dense,
Q4_K_M, 28 GiB) across a B60 + B70 pair with llama.cpp `-sm layer`:

Pinned contributor write-up:
[`results/nemotron-b60.md`](https://github.com/bosd/trx50-arc-b70-benchmarks/blob/fda0d86c47ff02d8e36f813a8e0121a2152d4478/results/nemotron-b60.md).
It reports llama.cpp build `b50-5aba536`, the SYCL backend, a 512-token prompt,
128 generated tokens, and summed active power from both cards.

| Config | pp512 | tg128 | Active W (both cards) |
| --- | ---: | ---: | ---: |
| 49B dense, B60 + B70 mixed `-sm layer`, SYCL | 388 tok/s | 13.4 tok/s | 178 |

The exact model variant and source revision, GGUF hash, complete command and
layer allocation, resolvable upstream llama.cpp commit, repeats/dispersion, and
raw output were not supplied.

The contributor interprets the result as B60-paced and attributes it to the
slower card plus the 24/32 GB asymmetry. Neither a B60-only nor uniform 2× B70
control for the same model was supplied, so the evidence establishes one
reported mixed-pair point, not the cause of its throughput or a controlled A/B
against either card configuration.

## Maintainer review

For the three rows with both GPUs measured:

- B60 generation is **69.3–88.0%** of B70, not 78–88%; the omitted low point
  is Qwen3-4B Vulkan.
- B60 prompt processing is **68.2–72.6%** of B70.
- Reported B60 card power is **52.2–62.5%** of B70.
- Using the reported card-power values, B60 generation per joule is
  **1.24–1.57×** the corresponding B70 value.

The B60 POST/console behavior is a useful observation about this contributor's
specific motherboard, firmware, and cards, not a general platform guarantee.
The recommendation against a mixed B60/B70 layer split was not measured in the
single-card table. The later mixed-pair point above is relevant, but without a
same-model single-B60 or uniform-pair control it still does not establish the
recommendation through a controlled comparison.

These data support a narrow statement: on the three contributor-measured
single-card comparisons, B60 traded absolute throughput and VRAM for lower
reported card power. They do not establish expected performance for other
models, builds, firmware, or hosts.
