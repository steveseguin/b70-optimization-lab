Multi-row verifier screen — October 28, 2026
CPU source and archived-route review only. No GPU requests or native edits.

Current execution
StageRing::execute admits one row ticket and causal parent, captures its checkpoint, and calls EngineBackend::execute, which invokes half_step. main.cpp and p49d_mix.hpp explicitly describe M=2 as two serial calls on the same owner state.

The existing prefill executor instead processes multiple rows through each layer. It provides useful arithmetic building blocks: GDN and convolution advance rows in order, QSA operations preserve each row's causal bound, and QSA attention already admits one to four rows. This is not a ready-made transactional verifier API.

Smallest useful kernel screen
Start with stateless dense projections at widths two, three, and four. Reuse reuse2::Op and the scalar references in research/prefill-reuse/evidence/cputest/test_reuse2.cpp. Compare every output bit against the same number of sequential production calls using actual registered matrix shapes and formats: expanded Q6_K/Q8_0, packed Q4_K/Q5_K/IQ4_XS, and BF16.

Large prefill defaults use tiles of 8–32 rows and may waste work at these small widths. Screen one explicit T2/T4 configuration rather than a broad tile sweep. The theoretical shared-weight traffic reduction is at most 1 - 1/B for width B; arithmetic and output stores remain. The prior 32-row dense prefill improvement from 3.52 to 1.10 ms per row is not a prediction for verifier widths two to four.

Routed expert reuse is limited
The archived 24-layer, 4,096-position canonical prompt trace gives these reductions in T4 weight-row decode counts relative to separate calls:
- Width two: 3.46%.
- Width three: 6.26%.
- Width four: 8.82%.
This is a canonical prompt trace, not speculative acceptance data. Actual shapes are gate/up 640 × 2,560 and down 2,560 × 640, with 512 experts and top-10 routing. An older decode profile measured routed work at 3,016 of 14,982 microseconds per half. Scaling all that work by the width-four decode reduction gives a generous 266-microsecond, or 1.8%, half-stage ceiling for this mechanism alone. It is not a current endpoint forecast and does not bound dense reuse or fewer launches. Expert bucketing overhead at only 20–40 slots may erase the gain.

Main integration obstacle
Prefill retains final recurrent banks. Ring verification must restore every intermediate tentative prefix. GDN/convolution banks, pooled QSA state, parity, extent, token history, stream outputs, and host metadata must therefore be saved at each logical row boundary. Saving only the start and end of a batch cannot handle accepting row zero and rejecting row one.

A layer-major implementation could construct each row's checkpoint image as it advances through every layer, but this requires substantive transactional execution changes. Do not call prefill_chunk and assume rollback parity. Width four also exceeds the current pending capacity of two or three unless the policy explicitly includes a canonical row or changes capacity.
