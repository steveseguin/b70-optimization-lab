Purpose and scopes
Stage0 ROW reply busy minus native half is an enclosing0.80/0.83s budget on
retained512-output cases, not isolated checkpoint time. This candidate adds
six steady_clock wall sums inside the existing CheckpointRingFor owner:
- capture_total_ms includes idle/guard/inventory/slot selection/position read,
  host metadata and output preservation, optional hashes, prepare and flatcopy.
- capture_prepare_ms includes existing descriptor construction/upload/drain.
- capture_flat_copy_ms includes existing inventory/submit/completion drain.
- restore_total_ms includes existing idle/guard/inventory, metadata/bank/extent
  restore, descriptor preparation, flatcopy, output restore and optional hashes.
- restore_prepare_ms and restore_flat_copy_ms are nested scopes as above.
Never add prepare/copy scopes to totals; subtract their sum only to describe
remaining enclosing host work, not GPU time or a proven removable cost.
Capture/restore call counts reuse existing successful-operation counters.
Constructor preparation and cold-reset reconstruction are not timed. The six
sums clear at existing reset_after_owner_zero, alongside those counters.
Attestation emits checkpoint_wall_timing under each request's ring receipt.
Flag OFF emits null and performs no clock reads. Flag ON is diagnostic only;
full12 fair timing must use OFF, with matched binary/source identity.

Behavior preservation
Only host stack clock scopes and six doubles are added. No callback hooks,
new drains, device queries, SYCL event timing, compute, device/arena allocation, state copy,
restore ordering or source exclusions. The original prepare/copy calls stay
