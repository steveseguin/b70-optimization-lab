Minimal owner
SparseRows owns a fixed16-byte Entry array and one contiguous packed-byte
allocation. Constructor's total_bound includes sizeof(SparseRows), index and
payload; owned_bytes() reports their exact requested bytes. Allocator internal
metadata, existing loader mappings and existing Weights::read return vectors
are outside that owned-byte count, not represented as zero physical RSS.
No extra dynamic staging scratch, hash map, growth or dual replacement cache.
Callers supply a bounded span of actual IDs, indexed(table,row); IDs are sorted
and deduplicated in place. Each table ordinal must be assigned in admitted
(shard file order, tensor data offset) order; row order then equals file-offset
order within that tensor. Adjacent selected rows coalesce up to4MiB, with no
gap reads. The two actual tables are on separate admitted shards; the CPU
fixture reuses two synthetic shards. Table numbering is placement, not math.

Every stage replaces/evicts the previous chunk, verifies backing before and
after reads, and publishes only after its final check. Overlarge submitted key
lists, payload/index exhaustion and unknown IDs explicitly refuse without
publication. Capacity refusal is a configuration/fixture error: integration
must use a fixed admitted chunk size or choose unstaged backing, never silently
retry a failed command. Reads spanning any missing row fall back entirely to
exact admitted backing. Hits and misses retain bounded vector<byte> output;
gsq::element stays unchanged. Backing identity checks still bracket the owner
command result, including staged hits. No pointer into replaceable staged
storage escapes; Weights::read returns owned bytes before replacement.
