Minimal next native history capture (proposal only; no implementation)

Existing hooks: RetainSteps accepts positive labels1–1024 and currently snapshots only streams AFTER .ffn.combine into per-layer captures. half_step gates those copies with request.fixture, not token position. The existing target-only244-prefix controller uses fixture0 for prefix rows, so --retain-steps1-244 alone does not capture their L4 intermediates. Relabeling all prefix rows as positive fixtures would also execute skipped final-head work; avoid that silent schedule change. The existing correction_exchange hook is a BF16 miss-only communication surrogate, not an F32 diagnostic recorder. Existing DUMP4 can retain intermediates but repeating whole sealed dumps244 times would write tens of GB unnecessarily.

Preferred small opt-in extension: within the existing rank half_step launch loop, after enqueue of exact label blk.4.gdn.recurrence, copy the three already-live INPUT buffers blk.4.gdn.conv, blk.4.gdn.a and blk.4.gdn.b through the existing synchronized readback path. At this point their values are still the current row, and the next ROW has not overwritten them. Trigger only in a separate explicit diagnostic opt-in on the target-only rank0/F32/context4096/244-input case. Index by request.position0–243 independently of fixture labels, preserving all original ROW/fixture values. No new command/shared-memory ABI, no kernel arithmetic or launch-schedule rewrite, and no draft/speculative path. Do not overload ordinary retain_steps behavior.

Exact payload is (40,960+192+192)*244 =10,087,936 bytes. Store one bounded sidecar with position/label/dtype/shape/extents/SHA per row plus final seal. Enforce increasing unique positions, exactly244 records, no speculative rows, and exclusive fresh output. On any missing/duplicate/out-of-order row or write/read error, preserve partial incident data and fail; never continue with an apparently complete history. Native conv already includes SiLU. a/b are raw projections; compare normalized q/k, log-decay and sigmoid beta only after running the exact source-defined stage0 with model ssm_a/ssm_dt and packed-head/F32 flags. Their full payload is384 bytes, available through the existing validated tensor-offset extraction method.

Why raw buffers first: stage0 scratch belongs to lower-level prepared submission/cache internals, not the stable Engine buffer map; exposing it requires a new lifetime/ownership bridge. Capturing existing named conv/a/b buffers is smaller and avoids guessing which scratch allocation survives. It will allow same-input stage0 tests and different-history comparisons without another CPU model load. It does NOT establish actual GPU scratch equality unless separately checked.

Before any new full run, use a tiny source/fixture gate for position identity and bounds, then one existing244/1 cold target-only native case. Require unchanged token6343 and byte equality of existing final target source-buffer state/layer captures against the qualified03e4fdaf diagnostic; no exclusions or tolerance changes. Record diagnostic overhead and do not use its wall time as speed evidence. If a new temporary readback allocation enters the compared inventory, resolve that contract explicitly rather than excluding it to force a pass. Main-path timing has priority; no implementation/build/model/GPU now.
