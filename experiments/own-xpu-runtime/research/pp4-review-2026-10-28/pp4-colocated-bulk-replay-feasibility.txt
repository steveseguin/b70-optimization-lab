Smallest explicit design, no generic framework:
- New opt-in colocated-only chunk command (opcode allocation must be checked;
  dedicated OP28 currently belongs only to dedicated runtime, not ring dispatcher).
  Preserve current OP9 default and existing OP15 native model arithmetic.
- Reuse provider_only/prefill.hpp Prompt, Record, immutable pinned prompt SHA,
  readonly map ownership and Witness capture semantics. Enable actual OP15 record
  publication for colocated bulk via a NARROW separate flag. Do NOT set
  pipeline_external_provider: it suppresses colocated prefill_replay ownership
  and changes target/provider admission semantics.
- Stage0 already owns consumed token vectors from actual OP15 completions. Bind
  chunk start/count/parity, real seed/final OP15 command sequences, roles/stages,
  epoch/request, prompt SHA, before/after prefix, lookahead, full source-record
  hashes and raw final F32 hidden SHA. Native-check immutable prompt tokens against
  the real stage0 queue before any arithmetic. Final publisher must record raw
  final reverse chunk SHA. Current colocated target maps have room for records,
  but publish is currently gated on pipeline_external_provider and must be adapted.
- Readonly final-map peer plus stage0 own-map source validation; copy bounded
  <=256*stream hidden bytes into native-owned Witness before use. Do not pass a
  mutable host reverse-slot pointer into a chunk loop. Existing map/header
  identity/inode/geometry/publication-before-after checks remain mandatory.
- Reuse actual mtp36::DraftRuntime::live_step for every row. Its partitioned borrow
  saves/restores target engine bindings; legacy optional run() catches errors and
  returns-1, while live_step deliberately fails closed. A new chunk must poison
  on arithmetic failure and forbid retry/reset of partial advancement.
- Prevalidate every no-head Row on a copied real Sequence, then for each completed
  arithmetic row advance the actual Sequence and depth0 counter exactly once.
  Keep provider_pending_borrows conservation equal actual serial; never increment
  provider_commands by chunk count. Consume native prefill_replay only for actual
  successful rows, and fail the owner on partial chunk failure. No forged ROW
  tickets, accepted SeedRecord, target commits or OP27 trace entries.
- Stage0 target OP15 and draft replay share ONE owner/socket/GPU: scheduler must
  serialize both commands. Keep max2 unfinished chunks and both parity sources
  leased until full replay ACK. No early-capture ACK needed for first version.
  ACK can reuse bounded source-bound bulk fields but reply must have actual
  colocated rank/stage identity (not dedicated rank-1); audit metadata slot1024
  against colocated live/proposal/reset/capture regions before choosing it.
