Smallest practical reuse:
- Keep exact Engine::prefill_chunk/target OP15 arithmetic, existing F32 prefill
  shadows, checkpoint-owned shadow exclusion, and target StageRing::prefill.
  Generalize only the current Python four-target guard to explicit2/3 targets.
  Native rank0/other-rank output region convention remains unchanged.
- MTP here has no qualified batched GEMM-prefill path: use existing
  DraftRuntime::live_step(head=false) and real Sequence::prefill per raw row.
  Target chunk batching is the initial performance lever. No precision change.
- Existing Dispatcher::prefill_complete unconditionally queues stage0's local
  prefill_replay FIFO even with provider=null; simply enabling external OP15
  would hit its two-chunk limit and leave shutdown/reset borrow accounting
  pending. Branch explicit external ownership: no colocated replay FIFO entry;
  a separate bounded chunk-publication lease lasts until dedicated completion.
  Never release/zero queues just to make FINISH pass.

Minimal explicit source publication, not counterfeit accepted row journals:
- OP15 commits a chunk in one command. Existing Handoff requires a real distinct
  commit_sequence>row_ticket, so ordinary FinalRecord/SeedRecord cannot represent
  each bulk row. Add a dedicated chunk record with source role, publication
  sequence, epoch/request, start/count/parity, stream extent, exact prefix
  before/after and digest. Stage0 publishes the exact consumed token copy;
  final target publishes the SHA of actual final reverse rows after device
  completion. Provider reads both maps readonly with existing inode/publication
  checks, captures owned raw bytes and verifies the full final chunk SHA.
- Reuse existing prefill map's header page without moving row regions: Header
  consumes16+256*4=1040 bytes; two fixed1280-byte records fit at1536 and2816 and
  end exactly4096. Each may use256 metadata bytes plus256 copied source tokens;
  final-role unused token bytes must be zero. Exact fields/layout still require
  CPU tests before adoption. Marker invalidate/write/release-publish follows
  current native journal convention. Two parity slots carry explicit leases.
- Pair position p consumes target hidden at p-1 and confirmed prompt[p]. Last
  pair of every chunk needs the next token (and final bulk pair uses the seam
  lookahead prompt[bulk]), which stage0 has not yet executed. Bind a fresh
  immutable prompt-i32 file plus SHA to native provider startup; verify every
  consumed stage0 token against it and take lookahead from it. This is explicit
  authenticated no-head prefix replay, NOT a claim that lookahead was accepted
  by a target. Do not reuse Owner::canonical's accepted-seed contract for this.
- Add one explicit provider chunk-replay operation (32-byte role/version framing
  retained), with count/start/parity and independent command sequence. Native
  owner checks cold, contiguous prefix, no head, serial/start alignment, source
  publication IDs and complete prefix before arithmetic. Build real non-
  tentative prefix rows for Sequence::prefill; run existing live_step then
  advance Sequence only after success. Any partial failure poisons owner; no
  retries/reset recovery. ACK reports consumed count/provider serial and binds
  actual source record SHA; traces record actual hidden/token pair hashes.

Bounded allocation/scheduling:
- Reuse target existing four-region prefill maps (40MiB+4KiB each at256rows,
  40960bytes/stream) and target shadow allocations; no target plan on provider.
  Provider opens stage0/final maps readonly; owns at most one captured raw
  chunk256*40960=10MiB plus small token metadata. No provider target checkpoint.
- Start sequential: complete all target stages for chunk k, replay provider k,
  then allow parity reuse. Stage0 copies its single-buffer token header BEFORE
  another OP15 can overwrite it. Generalize existing two-chunk wave only after
  parity; dedicated device can overlap replay k with target chunk k+1 without
  colocated stage0 contention. Retain final reverse parity until capture/full
  completion ACK; never let k+2 overwrite k while provider reads it.

  ACK serial=bulk, no pending chunk leases. Existing target seam remains two
  canonical rows: next_seed=bulk+1; normal target rowbulk then publishes a real
  final ACCEPT, enabling first OP27 for seedbulk+1. No fabricated per-row chunk
