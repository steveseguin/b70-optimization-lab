1. FUSED COMPRESSED EXPERT READS: LARGE POTENTIAL, CURRENT IMPLEMENTATION FAILS OUR EXACTNESS BAR
Primary behavior/kernel guide:
https://github.com/Niko1221/Strata/blob/5e8a4cca7d690ac60ca37eb09e7d0e010099ad6d/docs/INTEL_INT8_EXPERTS.md
Code:
https://github.com/Niko1221/Strata/blob/5e8a4cca7d690ac60ca37eb09e7d0e010099ad6d/sycl/src/prefill/esimd_moe.dp.cpp
Demonstrated by authors: ESIMD register decode to s8 DPAS avoids an FP16 expert intermediate (2.1 MB compressed read vs 9.8 MB materialized FP16 expert). Uses q8_1 activation quantization; grouped expert launches; per-device/driver/format/shape crossover timing. Explicit quality classification: DIFFERENT OUTPUT BITS, not exact against FP16. Reported teacher-forced top-1 agreement99.7%, mean KL0.0002 over6002positions; integer dot exactness is conditional on already-quantized activations and is NOT whole-model losslessness. Edge notes include unaligned-block overreads and compiler indexing faults: implementation details matter.
Our hypothesis/test: first use existing operator harness to measure dequantize writes/reads vs multiplication for actual IQ3_S expert shapes. Prototype compressed register decode while retaining our FP32 arithmetic/order, then run full operator bitwise invariance census before an endpoint gate. Do not adopt q8_1 activation conversion as a speed default. If exact fused math cannot be achieved, close this implementation rather than relabel near-lossless as lossless.

2. TWO-CARD EXPERT PARALLEL: LOCAL COMPUTE INSTEAD OF REMOTE WEIGHT STAGING
https://github.com/Niko1221/Strata/pull/1798
https://github.com/Niko1221/Strata/pull/2205
API checked: BOTH PRs open/unmerged. Head SHAs #1798=68c5ad51a9b62a072a646db397682bb629abbf39; #2205=4805fa9a15dded5b9aee0a343e7470787c3e4325.
#2205 author reports two B70s executing their own routed experts during prefill, removing host GGUF reads; measured hot prompt improvements12-50%, larger cold-pagecache improvements. The report uses IQ3_XXS and INT8 KV, so its throughput cannot compare to our IQ3_S/16-bit-KV lane. Its cache-drop experiment is evidence, not authorization to reproduce host cache changes here. Combiner/copy time grows; benefit is not free.
Our test: CPU derive per-layer expert load and output-transfer bytes from our routing traces, compare EP2/EP3 target placement against PP4. Preserve selected-expert output order and identical reduction order; plan memory before any launch. Potentially combine EP within a target partition with a separate existing MTP provider. This is a separate architecture lever, not a small PP4 tweak.

3. PIPELINED PROMPT CHUNKS AND VERIFY WINDOWS
https://github.com/Niko1221/Strata/blob/5e8a4cca7d690ac60ca37eb09e7d0e010099ad6d/docs/MULTI_GPU.md
Demonstrated/documented: calibrated prompt chunk choice via --prefill-pipe; --pipeline-windows2 starts next verify window before prior final stage finishes, restoring first-stage state if full-accept/bonus-token prediction fails. Draft goes on stage0 with pipeline enabled. Reports gains on AMD and selected NVIDIA mixed-GPU systems; page is NVIDIA/AMD oriented, NOT proof of B70 gains. Their stated token equivalence allows CPU rounding; our gate remains stricter. Costs include a second window and recurrent-state backups.
Our test: finish current two-chunk prefill parity/timing first. Then use existing measured stage timing to choose chunk size/inflight depth from bottleneck, keeping FIFO hidden ancestry and partial-tail semantics. For decode, only reopen next-window overlap if measured critical path and acceptance predict gain; require exact state rollback, actual accepted counts and canonical hidden-pair parity, including miss/terminal/context-bound paths.

Our runnable first test: replay existing per-stage target/provider timings through a CPU discrete-event schedule for PP3+one existing-MTP GPU and PP2+one existing-MTP GPU. A same-weights provider moved across devices must pass actual pair and terminal sealed-state parity. No source located here demonstrates Strata 3+1/2+1 B70 superiority.
