## Existing execution and identity

- Corrected native binary SHA256 is `5926a24746c62c6b0ecdc5c3e4895f310145e0f9d74a90a5d657035b9a8151f4` (B:1223). Compile receipts use `-fno-fast-math`, `-ffp-contract=off`, IEEE denormals and precise FP32 divide/sqrt (B:10-18). Matching this engine does not solve its independent-reference fidelity issue: service documentation explicitly preserves the mismatch and unqualified status (L:120-130).
- The service configuration is explicit split 24/24, draft on rank 0, context 4096 (L:46-49,112). Rank splitting keeps layers below boundary on rank 0 and layers at/above boundary on rank 1, embedding/streams only on rank 0, other global operations on rank 1 (R:40-60). **Do not infer default split from draft rank**: without explicit `target_split=24`, `draft_rank=0` chooses boundary 22 (R:44).
- Python writes one native-request text containing mode/count/overlap/dumps/prompt/script/EOS, starts NATIVE opcode 10 on each rank, then waits without issuing per-token commands (P:139-162). The token loop is C:65-102, not Python's fallback Controller.
- Rank 0 HALF for token 0 is primed and accepted (C:69). For each position, handover copies streams, rank 1 HALF begins, rank 0 may process the next known prompt token concurrently, rank 1 is accepted, and rank 0 is accepted after its completion (C:70-99). The original native backend has one outstanding command per rank and a single process-shared mailbox with acquire/release sequence publication (C:12-44).
- Each HALF checks token/position bounds, no unresolved candidate, no rank1 speculation, then prepares token or imports streams, runs the plan, drains, checks sticky error, swaps rank0 recurrent banks, exports 20,480 bytes, and replies; ACCEPT publishes candidate captures/clears pending state (R:121-155,171-209,338-352). Head operations `final.*`, logits and argmax are skipped for fixture 0 (R:175); fixture becomes positive only at the last prompt position (C:67,89). Intermediate prompt positions therefore **already omit target head**.

## MTP is not last-position-only

The draft consumes the preceding target's four final hidden streams plus the next confirmed input token's embedding (D:228-233). Every confirmed next prompt position invokes DRAFT, even when its head flag is false (C:94-96). Draft `target_position` must equal private `position+1`; the whole draft layer/attention-cache update runs, omitting only `final.*`/logits/argmax when `head=false`; then draft position advances (D:228-255). Draft cache outputs include QSA keys, values, raw and pooled vectors (D:307). Thus skipping early draft steps loses its history and violates both sequence checking and later proposal identity. The draft head is enabled when the confirmed token is the last prompt token (`p+2>=length`), then continues during generation (C:96).

Because this service puts the draft on rank 0, rank 1 exports its final-layer streams through `reverse_offset`, tagged `position+1` (R:184-187), and DRAFT verifies that reverse position before copying hidden state (R:319-321; D:231). A batch must retain **every row's rank1 final streams** and replay draft updates in order with exactly the preceding hidden row and confirmed token. Draft mutable allocations are explicitly private and target-alias checks are enforced (D:199-204), so deferring draft work until a target chunk finishes can be mathematically safe if all required hidden rows survive and the same sequential draft cache updates are performed. It can lose target/draft overlap; do not count that overlap twice in a speed projection.

Suggested first integration retains the last one or two prompt target positions in the unchanged scalar controller, so target head/emission/EOS and the final draft publication are not changed simultaneously. The transition must carry a precisely defined current target position, already-confirmed rank0 candidate status, draft position, draft guess/publication sequence and reverse-row identity; it cannot simply call the original `run` again because that unconditionally primes position 0 (C:65-70).

## PLE/history and HC constraints

`prepare_token` clears lookup IDs, forms host PLE IDs from token and the two previous input tokens, handles EOS by resetting the older token, uses 64-bit wrap/XOR and signed modulo with metadata offsets, then advances `(history0,history1)` (E:1275-1298). Batch preparation may run this exact host loop over known prompt IDs, retaining per-row lookup outputs and final scalar history; neither floating-point GEMM nor token reordering belongs here. Rank0 also retains device `token_history`, and candidate rollback records the previous 16 bytes (R:142-143,198). RESET restores both host and device histories to EOS (Z:29-35). Hashes must include these, even if all emitted tokens happen to match.

HC input/output streams are four BF16 streams of width h=2560, hence 20,480 bytes per position (R:154,185,208; L:112 configuration). Rank handoffs must preserve their bits; HC does not justify flattening these streams to one or moving its rounding boundary. The exact arithmetic/kernel mapping is covered in the kernel map task.

## Proposed batch protocol (design, not present implementation)

Define a new, versioned `PREFILL_HALF_BATCH` command in an additive controller/transport copy. Do not repurpose HALF or DRAFT. Keep the existing fixed command envelope only as a descriptor to a separate, versioned shared region; require version, start position, positive row count, prompt-only flag, token-array offset/length, forward/reverse stream stride, payload byte lengths, end position, request ID and sequence. Reject speculative batches, noncontiguous positions, overflow, unexpected initial position, tail beyond context, unresolved scalar candidate/draft or aliasing control regions. Perform input bounds checks before submissions. The current Request is 32 bytes, Reply 64 bytes (R:15-18), so a full batch descriptor cannot fit without an explicitly versioned ABI.

The current shared mapping totals `4*65536+4096+64=266304` bytes and includes 64KiB forward slots, a publication/control page, reverse region and probe region (R:13; P:6-8). A 64KiB forward slot holds only floor(65536/20480)=3 complete stream rows. A single forward matrix requires M16=327680 B, M32=655360 B, M64=1310720 B; preserving reverse hidden rows requires the same again. With independent producer/consumer forward slots plus reverse slot, payload alone is 983040/1966080/3932160 B. Allocate this separately and leave old control offsets intact; do not overwrite the MTP publication/mailbox/probe regions. Explicit descriptor bounds and producer-release/consumer-acquire ownership replace assumptions in `Backend::handover()` (C:44).

For each chunk: prepare token/PLE rows on rank0; run layers 0..23 layer-major; publish rank0 output matrix; rank1 consumes exact rows and runs layers24..47 layer-major; preserve/export every final row; run required draft updates sequentially using these rows; commit chunk only after sticky error/candidate/draft checks. Initial implementation serializes chunks. A later double-buffer pipeline may overlap rank0 chunk k+1 with rank1 chunk k, but rank0's draft shares the device and needs reverse rows, so the ownership schedule must explicitly account for it. Failure poisons the batch and invokes existing cooperative error behavior; no partial-success resume/retry is proposed (R:203,373; C:21-26,41).

## Full target state means more than KV

The reference `state_dump` hashes and bundles **all plan allocations including overwrite-only intermediates**, all alternate temporal banks, host history and FP32 cache metadata (R:250-257). The additional request inventory hashes all standalone target mutables excluding already represented buffers, weights, pinned slab, immutable snapshot tables and draft-labelled allocations; this includes scratch and speculative reserves, plus lookup IDs, selected IDs, loaded layers, cache source/extent, bank parity, current/alternate launch extent, logical event, history and poison state (I:6-27). RESET also records full draft state, whose mutable allocations are hashed by label (Z:15; D:301-305).

**One final unchanged scalar token is not a proof that these bytes match. Two final tokens are not a general proof either.** Scratch write ranges differ by operation, and QSA-related ranges are position-dependent; an unwritten tail can still carry an older token's last write (S:118-150). Running scalar tokens may repair recently overwritten regions and both recurrent banks, but not an arbitrary stale-tail mismatch. No whole-buffer hash may be ignored or zero-normalized after the fact.

Concrete exact-state design:

1. Enumerate the write sets of every old mutable allocation at the actual selected kernel/subpass, including data-dependent extents and scratch. An unknown writer creates a full-allocation preservation dependency: keep its original token-major execution until exact actual write masks and predecessor reads are proved. Snapshot may-write unions are conservative copy bounds, not valid last-writer masks (S:118-150). Keep per-row computation workspace separate from the legacy scalar allocations.
2. For each legacy byte/typed element, materialize the value from the **last writer in the original ordering** `(absolute position, plan-site, subpass/write ordinal)`. Preserve the prechunk byte if no writer occurred. An implementation can use proven static interval overlays instead of per-byte tags; dynamic sparse writes need explicit writer metadata. This restores the old scalar allocation's final contents even when layer-major execution produces them in another order. Values are copied exactly, never recomputed with a different reduction or zeroed to make a hash pass. Validate each scratch read has the same preceding producer; otherwise keep that operation sequential/shared in the original order.
3. Rank0 temporal banks need the exact final TWO versions. For every GDN/conv layer, sequentially alternate the same physical active/spare pair for each row, starting from the original bank selection. After M rows each layer's pair holds the original `S_(p+M)` and `S_(p+M-1)`; globally change bindings iff M is odd. The existing scalar path swaps after each rank0 HALF (R:204), and global swap changes all bank IDs, parity, command caches and FP32 source validity (E:1161-1167). Do not globally swap during just one layer's row loop. Preserve the third reserve untouched during non-speculative prefill; reserve rotation occurs on speculative snapshot begin (S:401-415; E:1150-1158).
4. Match both context extents at boundaries crossing 32-token buckets. The scalar engine admits `min(context,ceil((position+1)/32)*32)` (E:1644-1658); active/alternate extents follow their respective bank cache pairs (E:1143-1147). A batch-wide larger extent must not change an earlier row's attention iteration bound or its final metadata.
5. Keep logical event accounting as the number of original logical plan-site visits, even if physical kernel submissions are combined. It is incremented once per `issue_site`/`enqueue`, not intrinsic hardware work (E:1681-1694,1696-1723). This preserves the existing inventory value; physical launch counts remain separate new telemetry.
6. Preserve legacy allocations and hash all of them. Extra batch-only allocations must be separately registered as transient workspace, drained and released before the original full-state DUMP/inventory boundary so they are no longer live inventory entries (I:12-18). They never excuse missing/changed old allocations. Retain their bounds/lifetime audit separately; do not hide a live target allocation by relabeling it. Require exact field-by-field numerical and control state equality, including untouched tails. The original DUMP boundary already retires/zeros private speculative backups only when dirty (R:365; S:472-482); compare baseline and candidate at the SAME such boundary, not a candidate-only cleanup.

If a write-set/state-preservation proof is unavailable, keep that kernel serial and its original workspace semantics. If a full-state device gate differs, that stage fails: localize first differing allocation/byte/site and fix it or disable the candidate. No tolerance or output-only fallback.

## Device gates for later authorized implementation

These are a proposed plan; no gate was executed in this research task. Bind the oracle to B:1223 and exact selected model/flags/compiler arithmetic, not the earlier BF16-state parent hash. Operator gates compare each row's BF16/F32 output bytes and all written scratch at M=1,2,3,16,32,64, tails and routed-ID permutations against repeated scalar kernels. Then compare each layer/chunk's active+alternate recurrent state, KV/raw/pooled full extents, PLE/history, HC streams and complete legacy allocation inventory. Include starts and ends around 3/4-token pooling and 31/32/33,63/64/65-token context buckets (D:307; E:1644-1658).

End-to-end gates run unchanged binary and candidate from independent fresh states for the same prompt IDs, with prompt splits of all tested M, target-only and MTP, then exact full emitted tokens and complete target state hashes at prefill boundary and after continuation. MTP additionally requires exact sequential draft-cache/mutable-state hashes and identical proposals/accept/reject decisions; record sticky errors, bank parity, cache extents, host histories and full unused tails. Repeat after RESET and in a fresh owner. The existing 32-token target/MTP pass is bounded evidence, not broad qualification (L:116-130). Preserve that distinction in all results. A two-token scalar suffix can simplify the first integration but cannot replace the full-state gate or the write-set proof above.

## Exact scalar-controller seam (proposed)

For service MTP mode3 with draft_rank0 and overlap enabled, let prompt length be P>=3 and bulk target prefix length N=P-2. The bulk phase consumes target positions 0..N-1 on BOTH ranks. Replay the draft at confirmed positions 1..N-1 using the matching prior rank1 hidden row; all of these have head=false. Retain rank1 hidden row N-1. Before the seam, execute and ACCEPT the original scalar rank0 HALF at position N, then execute the original rank0 DRAFT with confirmed token prompt[N], target_position=N, head=false and the retained rank1 hidden row N-1. This is the old loop's state after iteration p=N-1: rank0 is one position ahead, rank1 is committed through N-1, the draft has advanced to N, and its publication for position N+1 is ready. The ordering follows C:82,87,94-97 and R:319-321. P<=2 uses the unchanged scalar path.

Introduce an explicit `Resume` record rather than invoking `run` from position0: next iteration p=N; rank0 stream row for position N; rank0 position=N+1 and rank1 position=N; no pending candidates; draft private position=N; draft_pending=true with draft_sequence=N, Publication.sequence=N and Publication.position=N+1, and publication polling already completed; history contains prompt[0:N]; no emitted tokens/guesses yet; out.start is original request start; current logical counts, bank identities and context extents preserved. Resume the original loop body at p=N, which processes the final two prompt target positions N and N+1=P-1. The head flag for the subsequent DRAFT at target_position=P-1 becomes true exactly as C:96 prescribes. No modified head, first-token emission or speculative-decoding logic is needed in that suffix. For target-only mode0, use the same two-rank target positions but omit every draft replay, leave draft state untouched and set draft_pending=false. For MTP rank0 the sequence must be N specifically: C:73 expects uint32_t(p), C:36 sets the local draft request sequence to its position, and D:265-281 completes the publication/position advance. Other draft placements or overlap modes require separate seam definitions and gates.

A canonical comparison boundary is this named resume phase: both ranks drained, all candidates accepted, rank0 consumed N+1 inputs, rank1 consumed N, draft consumed N confirmed transitions with its publication ready. For the intermediate oracle, use an isolated diagnostic host driver of the unchanged binary's existing HALF/ACCEPT/DRAFT/DUMP commands, executing the SAME scalar-loop phase and then quiescing; never compare rank0 and rank1 at a fictional equal position if the scalar sequence is already one ahead. The binary already exposes these commands independently of NATIVE (R:311-381,403), so no source instrumentation or process suspension is required. Record sequences as transport identity fields and check publication identity/payload; physical command numbers can differ only under a new explicit protocol schema, while model/control state bytes in the legacy state inventory remain exact. Label intermediate diagnostic command schedules separately from the unchanged native-controller end-to-end run. The unchanged binary's existing end-of-request DUMP provides the final oracle; no edit to the running service or frozen sources. Invoke the existing full-inventory DUMP convention (R:365) at matched quiescent boundaries in both compared arms.

Sequential first implementation must retain per-row scalar QSA invocation geometry, including its one-token semantics and prefix bound, rather than setting an existing kernel token count to M. Its existing capacity admission advances in 32-token buckets (E:1644-1658), and each row must keep its own original admitted extent. The draft replay uses private scratch/head workspace allocated by DraftRuntime (D:167) and explicitly private target-disjoint mutables (D:199-202); this does not permit casually aliasing batch target scratch. Enumerate any shared engine-level scratch/metadata writes anyway in the whole-state writer audit.
