# C2 — Precision/reference contract and qualification plan

Research/design only, 2026-10-24. No model execution, build, device access or service change was performed. New work for this task is confined to this directory. Numerical costs below are source-derived estimates, not measurements or memory admission. Future execution described here is a proposal; the current task authorizes none of it.

## Recommendation

**Do not qualify the current engine by relaxing the CPU comparison.** Preserve corrected engine `5926a247…51f4` as the behavioral oracle for lossless optimizations, and create a separate, explicitly higher-precision target identity. The strongest practical path is to remove the remaining runtime BF16 rounding from the target, validate an own-code F32 reference against independent equations and F64 diagnostics, and then require fixed same-prefix and state gates. The existing 32-token target/MTP equality is useful but the shared-prefix target/reference disagreement remains open. (`L/recurrent-f32/STATUS.md:1-8,22`; `L/recurrent-f32/operating/launch-b/RESULT.md:3-13,27-30`.)

The main obstacle is **typed implementation and reference validation**, not hundreds of gigabytes of GPU weight expansion. At context4096 the source plan gives +132,596,320B rank0 and +66,703,920B rank1 for F32 ordinary activations, attention KV and index caches, including the existing rank0 snapshot policy. Additional known scratch and full RoPE-table changes bring the indicative subtotal to +138,766,944B/+71,886,384B. These are not complete fit guarantees; see the derivation and exclusions below. The selected quantized weights stay quantized. (`PLAN:102-245,254-295`; `MAIN:1180-1204,1217-1238`; `SNAP:355-391`; `ROPE:8-12`.)

A few days is a reasonable **engineering estimate** for a bounded F32 implementation/reference checkpoint and the registered short/long tests below, with more time possible for unexpected semantic or kernel differences. It is not a promise of a pass. Until all hard gates pass, the correct status remains “experimental; fidelity not qualified,” as the service already states. (`L/serving/lan/README.md:120-130`.)

## Pre-registered contract: two distinct kinds of change

The following is a proposed contract to freeze before implementation/results. It grants no operational permission and does not redefine an observed failure as a pass.

**B0 — behavioral preservation.** For scheduling, packing without changing decoded values, transport, draft-only changes, and observation-only instrumentation, require bit-identical emitted IDs, stop/EOS outcome, and complete target state against corrected5926 on exactly the same inputs. Compare both ranks, recurrent/history/KV/index state, position/token counters, streams, and deterministic target scratch/capture ranges; explicitly exclude only newly introduced diagnostic buffers and draft-private state, with a predeclared allocation map. No token mismatch, tolerated state delta, or “equivalent prose” escape. The existing corrected state lifecycle includes typed snapshots and full copies on miss; that obligation must survive changes. (`L/recurrent-f32/STATUS.md:16-18`; `L/recurrent-f32/operating/launch-b/RESULT.md:3-13`.)

**P1 — strictly higher precision.** A target precision correction may change5926 tokens/state, so it establishes a new numerical identity rather than masquerading as a B0 pass. Preserve the exact two GGUF shards, metadata/architecture, tokenizer/template, quantization interpretation, HC/PLE/QSA/GDN semantics, routing policy, context bound and greedy tie rule. Every changed numerical site must remove a precision reduction or increase precision; no compensating lower precision elsewhere. A narrower final-HC island is useful attribution, not complete P1 qualification. (`L/model-identity.json:4-20`; `L/recurrent-f32/reference-longer-plan/UPSTREAM-PRECISION-OPTIONS.md:16-44`; `L/recurrent-f32/precision-appraisal/REMAINING-DTYPES.md:16-22`.)

**R32 — declared numerical reference.** Use the exact checkpoint's canonical dequantized F32 values, F32 activation products/accumulation and state, full F32 residual/HC/router/expert/logit outputs, and F32 KV/index caches and RoPE constants. Freeze reduction order, whether multiply/add contracts, transcendental implementation, finite/NaN behavior, top10 and argmax tie order, QSA selection order and absolute positions. Preserve architectural sparse attention; “all-F32” does not mean changing QSA to dense attention. An explicit separate `R32-BF16KV` diagnostic may retain the historical attention cache format, but it must not be called all-F32 or quietly satisfy the stronger literal no-extra-runtime-quantization contract. Existing reference BF16 KV is a documented profile, not proof that its rounding is free. (`PLAN:147-179,197-218`; `L/reference-cpu/runtime-longer-a/RESULT.md:8`; `ROPE:8-12`; `L/recurrent-f32/precision-appraisal/REMAINING-DTYPES.md:9-16`.)

**R64 — arithmetic sensitivity control.** Widen the *same canonical decoded weight values* exactly to F64; increase arithmetic/state/cache/trig precision. Do not silently dequantize using different formulas or compare another checkpoint. Canonical format-defined dequantization itself has F32 operation boundaries in the existing loader; declare them as the weight interpretation and verify them independently. For operator tests, also use identical F32 input values widened toF64 to isolate one operator. For end-to-end R64, allow its own high-precision state/routing and record route differences; a replay with R32-fixed expert/QSA choices is a separately labeled localization control. (`S1/loaders/dequant.py:1-6,29-39,59-121`; `PLAN:197-218`.)

**Qualification language.** A finite suite can support “same checkpoint, no added low-precision storage/activation quantization, deterministic and quality-qualified under contractP1 on the named tests.” It cannot prove universal semantic no-loss, and F32 itself is finite arithmetic. Precision dominance alone is not a theorem of output quality: cancellation, reductions, transcendental accuracy and discrete expert/QSA choices matter. Exactness remains mandatory forB0. ForP1, demand the structural precision proof plus the fixed reference/functional gates below; never use small KL to excuse a failing exact gate. This is a proposed claim boundary, not a tolerance waiver.

## Own all-F32 CPU reference: feasible without full expansion

There is useful original code, but no ready-made full-model F32 oracle. The closer NumPy reference implements HC/GDN/MoE/PLE/QSA structure, yet generates synthetic weights, hardcodes mini QSA/PLE details, runs only one layer in its real-geometry mode, and rounds recurrenceBF16. The older packet1b reference is the different hidden5120 model. Reuse ideas and loader components in new files; do not rename a synthetic pass into a real-model qualification. (`S2/packet3/tests/reference.py:70-92,115,142-143,160-217,219-281,283-299`; `S1/reference/math.py:211-217`.)

Implementation proposal:

1. Reuse the own GGUF header/split/range parser scaffolding, **add current GSQ format coverage**, and independently verify the two pinned shard identities before a future run. Use bounded reads/mmap for embedding/PLE rows and selected experts. The parser validates dimensions, alignment and tensor ranges without materializing all weights. The older Python type table/decoder does not admit **Q2_0 (type42)**, which this checkpoint uses; it cannot directly parse/decode the whole target unchanged. Add its64-value/18-byte block and `(2-bit code - 1) * FP16 scale` decode, cross-checking the existing own GSQ equations and independent format source. (`S1/loaders/headers.py:15-19`; `S1/loaders/dequant.py:19-20`; `L/metadata/new-census.json:1108-1123`; `E/integration/build/private/additive/device_formats.hpp:10-23`.) 2. Vectorize each quant-format decoder in NumPy, retaining the scalar decoder's exact canonical F32 results on its supported formats and the independently validated new Q2_0 decoder on synthetic and selected real blocks. 4. Provide two compute modes: an explicit-order F32 mode for exact device/oracle comparisons, and ordinary vectorized F32/F64 semantic modes for independent numerical cross-checks. ## Fixed teacher-forced test plan and decision rules

F32/F64 comparisons have value because they can localize an avoidable low-precision boundary and expose unstable choices. They cannot yield a scientifically valid guarantee of no semantic loss merely by declaring an empirically convenientKL threshold. A blind calibration split avoids tuning to candidate results, but does not turn such a threshold into exactness. The proposed contract therefore uses **no numerical tolerance to pass a preservation claim**.
