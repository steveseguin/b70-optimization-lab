# Minimal persistent two-rank coordinator plan

Reuse the P195 `pipeline.py` **Transport protocol methods and NativeController**. Add only a model-specific launch constructor and bounded request/session coordinator under this directory. No new rank protocol, native graph, benchmark-window fork, or service is needed. This is a source plan; no launch or device admission has occurred. Exact paths, argument templates and source hashes are in [source-plan.json](source-plan.json).

## Existing seam

`NativeController.run(prompt, count, eos)` writes `native-request.txt`, sends opcode 10 to rank 1 then rank 0, waits for both replies and reads `native-result.json`. It accepts target-only mode 0 and MTP mode 3 per request. The target and draft weights remain in their existing ranks. The native rank loop accepts another command after a completed request.

Launch rank 0 with the draft already allocated (`--draft-mtp --draft-rank 0`) and rank 1 without it. First run `Draft('none')`; after retaining its confirmed tokens and state, RESET both idle ranks (opcode 11) and run `Draft('mtp')` with the same prompt/count/EOS. This compares the same target weight allocations in one rank pair. The first request is target-only execution with a resident but unused draft; it is not a target-only loading-memory measurement. MTP initialization currently occurs only at process startup, so lazily adding a draft later would require a native change and is unnecessary here.

RESET uses each rank's fixed original output path and current sequence to locate `reset-N.txt`, containing the next absolute output directory and optional oracle line. It preserves immutable allocations/prepared commands, dumps the completed state, resets mutable target/draft state, and refuses a poisoned target or unresolved candidate. Reuse these native semantics and the small Python reset metadata sequence from `suite.py`; do not call the historical suite's automatic warm-up, state-pruning or benchmark campaign entry point. Resetting is not prefix reuse: each new request begins from a clean state and renders its full conversation prompt.

The existing `chain_pipeline.py` is almost identical to `pipeline.py`; its only material differences are output-local HOME cache placement and a ready hook. It offers no separate persistent protocol advantage. Keep the simpler pinned pipeline methods and preserve the actual user's HOME.

## Launch adaptation

Each rank receives the new build receipt's exact native binary and SHA, `--gsq-packed`, `--cards 1 --card 0`, `--target-split 24 --draft-rank 0`, `--context 4096 --memory resident --host-path prepared`. Both use the immutable loader's exact `placement.tsv`, `shard-auth.tsv`, and SC117 model directory. No old dispatch/selection is passed: GSQ mode explicitly refuses those. Rank 0 receives the retained official `mtp/draft-manifest.tsv` and `/mnt/fast-ai/llm-models/Qwen3.8-Flash-Next-FP8`; full-vocabulary head policy is already part of the new integration. The compiled source-location default manifest path must not be relied upon.

The inherited constructor cannot run unchanged: it applies the old model's memory ledger, derives plan/auth paths from old `input.json`, chooses `card+rank`, mutates HOME, and does not forward the GSQ/draft authority arguments. A small source-bound constructor adaptation can retain the unchanged socket pair, shared mapping, sequence/reply checks, stop pipe, wait and explicit close methods. The existing new-model HOST_ONLY lifecycle helper demonstrates this form of constructor extraction; actual native launch admission remains separate.

Candidate placement is rank 0 at `0000:23:00.0`, rank 1 at `0000:47:00.0`. Use independent closed per-child environments with the existing literal library path, unchanged HOME, private supported cache paths, and the historical BDF filter tuple (`NEOReadDebugKeys=1`, `FilterBdfPath=<exact BDF>`, PCI order enabled, affinity/selector ordinal 0). Both child arguments remain `--card 0`. This filtering is a proposed reuse, not a verified mapping: fresh physical topology/holder evidence and an exact selected-device PCI identity gate must precede target loading. Ordinal order alone is insufficient. The requested vision BDFs 27/43 must retain their existing owners and are never a stop/restore target.

## Required bounded admission and shutdown

Before launching either rank, bind the native build/source closure, immutable target and draft authority, current boot/fault baseline, exact two-card ownership, protected vision PID/start identities, disk space and host memory. Use the new static [memory ledger](../memory/engine-accounting.md) only as a forecast; replace the old-model `memory_gate` input, retain its 30 GiB logical cap, and independently require physical availability. Rank 0 draft capacity is needed from startup. The inherited 8 GiB aggregate anonymous-RSS guard also needs an explicit new-model assessment; do not silently delete or raise it.

Retain the original error before cleanup. The first rank may already exist if second-rank startup fails; construct the transport object before calling its constructor so partially initialized ownership remains reachable. No automatic retry or replacement. A fault stops intake and writes the cooperative stop pipe once; bounded cleanup cannot release coordinator resources while either rank is uncertain. Normal close sends FINISH (5) only when both ranks are idle, waits for exit 0 and safe native teardown, then an independent passive device drain. Never infer physical drain solely from a successful JSON result.

Bound request count, context/token caps, total lifetime and idle waiting. Record each request/result before allowing the next; archive the fixed `native-result.json` because it is overwritten by the next request. RESET dumps state, including draft state, so budget and retain those files explicitly; `--retain-steps none` does not disable boundary state dumps. Do not import the historical suite's deletion helper as an implicit storage policy.

## Small validation sequence

1. CPU launch interception tests: exact per-rank argv/environment, immutable plan/auth/draft pins, both `--card 0`, no dispatch/selection, no HOME rewrite, refusal before Popen on wrong identity/missing resources, partial-start/error retention.
2. One explicitly authorized HOST_ONLY miniature pair, same processes throughout: target-only request, RESET, MTP request, equal confirmed tokens and target state, another RESET/request, FINISH and both safe receipts. Existing separate-pair tiny tests alone do not qualify this new same-pair coordinator.
3. After separate native admission, one small real-model target-only request then same-pair MTP comparison. Keep complete token and state evidence; no throughput claim or automatic repeat. A result comparison is against the new quantization's own target-only path.
4. Once that is qualified, attach a serial local chat facade using the admitted tokenizer/template and full prompt rendering. The current NativeController returns after completion; it does not provide a token callback. Ordinary completion is the minimal initial interface; streaming requires a separate reviewed seam. Request-front v2 checkpoint parking is not this two-rank protocol.

Nothing in this plan authorizes a device enumeration, model read, process start, service change or restart. `native_admitted` remains false until root supplies the separate operational admission and the required evidence passes.

## Implemented CPU checkpoint

[adapter.py](adapter.py) now supplies `build_plan`, `validate_plan`, an explicit `Transport` constructor subclass, `compare_attached`, and `qualification`. The CLI exposes only `--plan`; it cannot start ranks. The library entry requires trusted coordinator `admit`, continuous `check`, and `launch_hook` callbacks. These are operational ownership seams, not self-issued device approval. Parent protocol, I/O, stop and close methods remain unchanged.

`build_plan(output, evidence_output=...)` supports separate private control/cache/log storage and rank evidence storage. The target plan buffers plus alternate banks occupy 221,743,168 dump bytes per request; draft KV/position adds 9,699,332. Two requests require 462,885,000 raw retained bytes, plus a 64 MiB metadata allowance; control/cache forecast is 128 MiB. Root floor is 27 GB, external evidence floor 2 GiB. Storage checks run before startup and each request; trusted continuous monitoring remains required because cache/log growth has no hard quota. The evidence parent identity is pinned even where its filesystem cannot enforce a private mode. It must contain no credentials. No copying, deletion or automatic pruning occurs.

`RetainedOwner.original` preserves the primary exception and `transport` preserves the uncertain process/mapping/FD handles. The outer coordinator **must catch this condition, stay alive, and retain its lease/drain resources** until passive cleanup proves safety. Keeping a Python global reference does not prevent process exit or preserve external locks by itself. An uncertain Popen outcome skips inherited close entirely, preserving shared mappings/FDs. Normal failed known-owner cleanup uses the inherited stop pipe and never hard-kills or retries.

The comparison covers confirmed tokens and exact target plan buffers/alternate banks/state JSON, not every standalone runtime scratch allocation. Native request-state inventories and other raw evidence remain retained separately. A target/MTP mismatch halts the sequence without a third request. Historical NativeController performance/quality labels are replaced with experimental scope and no speed claim.

[15 CPU checks](evidence/cpu-tests.json) exercise actual inherited NativeController code with a mock rank protocol, real temporary socket/mapping creation with Popen intercepted, uncertainty/error handling, command/environment/source binding and storage refusal. The historical successful Host build's three relocated sources are individually hash-bound through its retained-source map; native validation permits no historical-source waiver. This checkpoint has **not** launched even a synthetic owner. A separately authorized same-pair HOST_ONLY run remains the next execution gate.
