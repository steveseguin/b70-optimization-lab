## Candidate decision after attribution

A plausible larger exact expert improvement is joint gate/up processing of the
same routed expert/input, retaining separate accumulators and unchanged output
rounding/status. It could reuse the BF16 input and route/address work, but gate
and up are different weights: no claim of halving weight reads. Another is a
format-specific decoder/reduction improvement for whichever *measured* format
is costly. The current unfused generic path retains original gather/per-slot
inputs; do not replace it with a historical selected fused kernel solely by
name. Any candidate must match actual quant format, raw storage, route/tail/error
semantics and reduction order, then exact native outputs/full states. No
candidate implementation, memory expansion or additional micro is selected yet.
