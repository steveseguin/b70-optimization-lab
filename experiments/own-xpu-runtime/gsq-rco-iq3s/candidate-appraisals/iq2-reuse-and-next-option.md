# IQ2_S block reuse and remaining options (source appraisal only)

Close the simple IQ2_S block-hoist idea. The current p6 `decode8<IQ2_S>` already amortizes metadata over eight contiguous values. With SG32/K2560, each lane visits `k=lane*8+256*b`, b=0..9: ten half conversions, ten grid lookups and ten sign bytes per row/lane. The IQ3_XXS win's repeated scalar half conversion is absent. Explicit block pointers and invariant offsets (`q=lane`, scale byte `lane/4`, nibble `(lane/2)%2`) could remove integer bookkeeping, but the compiler may already do this. There is no supported prediction of a useful improvement.

Exact arithmetic remains `((half*(0.5+scaleNibble))*0.25)*gridMagnitude`, then sign, BF16 input multiplication, ordered addition; adjacent SG32 tree and BF16 output. Preserve staged local rows, four subgroups, per-slot gathered input, route/status/tail behavior and captured bindings. The direct-global IQ4 experiment is a measured loss and supplies no reason to remove staging here.

The fixed IQ2_S subset is40 gate/up sites on layers1,2,3,4,5,6,8,9,10,11,13,15,19,23,24,26,32,34,36,39. Each is count10/N640/K2560/512experts,820B packed row and268,697,600B bank. Retained early-generated positions94..101 attribute13.972286ms gate plus14.020936ms up (320events); these are sampled event durations, not current whole-request cost. If later selected, a pointer-only experiment needs exact old/new address and decode-vector/chain/tree tests,1024 grid indices,256 sign patterns,16 scale nibbles and representative exceptional half values, then one fixed actual both-order output/status case. No implementation now.

## Next-option comparison

- **Route integer ranking is the strongest remaining source-level alternative.** Current adapter `simple_body<route,3>` makes all512 probability comparisons for every expert. Existing `p33::route_rank<512,10>` stops after rank reaches10 (four comparisons per iteration). Since rank only increases, rejected experts can stop; every selected expert still finishes the complete comparison set, preserving ties by lower index. This can preserve all FP softmax/normalization operations, probability scratch, five launches, output writes and capture topology. It is not the broader `route42` fused scheduling path, which changes the probability staging/launch structure. Retained sample route cost26.258949ms/1920events and old whole-request702.142ms make it plausible, not a measured prospective win. Proof would target stable ties, finite extremes, invalid-input/error/active semantics and exact all intermediate/output state; arithmetic and new code are not implemented.
- **Other expert formats:** IQ3_S already uses decode8; IQ4_XS gate/up has only2.997605ms in the same retained sample. Head's old whole-request174.971ms is smaller than route702.142ms; neither is a justified priority from present data.
- **Recommended decision sequence:** finish the19-site Q6 correctness/result first. A single same-binary class diagnostic on that qualified binary is the highest-value information step before another candidate, because both IQ3 and dense-Q6 dispatch changed after the existing class/format profiles. Reuse the fixed prompt00, excluded disjoint warmup, exact baseline states/tokens and qualified bundle capture. No broad attribution campaign is needed unless class results make a mixed-format choice ambiguous. If root instead wants one already-source-supported candidate, integer-only route early exit is more defensible than IQ2 block hoisting. No speed forecast or allocation/quality promotion follows from these observations.
