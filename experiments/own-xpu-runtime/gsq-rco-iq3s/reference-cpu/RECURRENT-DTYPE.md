# Confirmed recurrent precision gap

The current5aef custom target **stores GDN recurrent state in BF16**; the pinned llama.cpp qwen4exp reference **stores it in F32**. This is a substantive precision difference requiring independent same-weight validation, not a harmless shorthand for BF16 attention KV. No quality impact has yet been measured, and target/MTP equality cannot settle it.

The source-bound path for5aef is `dense-packed-block/engine/build/source/main.cpp` (75c6742b…), which builds the unfused graph using private `packet3/step/plan.hpp`. That file's `buffer` default at35 is `Scalar::bf16`; `gdn()` at136 creates `state[48,128,128]` without overriding it. Main allocates `count(shape)*scalar_bytes(type)` at1235. The actual closed expanded prompt00 rank0 `state-index.tsv` records `blk.0.gdn.state.bin` length1,572,864B =48×128×128×2, including its same-sized alternate bank. This is metadata-only confirmation, no state payload read. GDN convolution history is also BF16:10,240×3×2=61,440B.

GSQ mode rejects external dispatch/selection at main291. The default dispatch maps `gdn.recurrence` to packet18/implementation0. `prepare_site` uses `packet18::submit_parallel`, whose adapter maps state to ng slots5/7. `kernels.hpp` Args::b at28 widens a uint16 BF16 value; Args::bits/put at29–31 rounds FP32 back to BF16 (nearest-even plus NaN quieting). In the recurrence at124–139, state is read through `a.b`, decay/prediction/delta/outer-product/y computations use float scratch, and `a.put(7,...)` commits BF16 each token. The F32 `ssm_a` weight flag2 and gain flag8 do not change state storage. There is no selected hidden F32 state path for this current configuration. Native submit and adapter objects11/13 are the receipt-bound reused objects; their source and kernel dependency hashes match the5aef build receipt.

In the reference, `src/llama-model.cpp:2814–2830` constructs qwen4exp `llama_memory_hybrid_idx` with recurrent types F32/F32 while forwarding separately requested attention K/V types. The recurrent constructor creates its state and convolution-history tensors from those F32 types (`llama-memory-recurrent.cpp:101–112`). CPU GDN `ops.cpp:11166–11269` reads/copies/updates float state and writes float snapshots with no BF16 commit. `--cache-type-k bf16 --cache-type-v bf16` therefore matches attention KV storage only; it does not lower reference recurrent precision.

The CPU reference should retain this F32 state. Do not make it imitate our BF16 recurrence merely to force agreement, and do not describe a mismatch as expected-and-acceptable without measuring its significance. The first32-token same-weight probe is a bounded functional comparison; even a full match would not certify recurrent long-context fidelity. A divergence needs localization among recurrent rounding, activation quantization, normalization/transcendentals, QSA and reduction differences. No fix or new kernel is implemented here; any F32-state product correction would require separate graph/kernel/copy/snapshot/storage-memory work and new independent qualification.

Exact paths, source hashes, reused-object provenance and the retained byte-length row are recorded in `recurrent-dtype-audit.json`. No model or state payload, compiler, GPU, executable or service was used in this audit. Earlier reference prose describing merely an expected numeric difference must be read with this explicit precision-gap finding.
