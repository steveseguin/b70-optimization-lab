`compare.py` defaults to metadata-only validation. Root may execute `python3 -B compare.py --read-ranges --output evidence/comparison.json` after independent source review. The output must not exist. The fixed target-only rank1 bundle is held with O_NOFOLLOW and its recorded dev/inode/size/mtime/ctime checked before and after reading. Only logits (496,640 bytes) and position/token/next_token (12 bytes) are read and hashed: **496,652 payload bytes**. No full-bundle rehash, model read, device, server, compiler, or replay occurs. Prior full-stream authority plus unchanged identity is explicit.

The conditional prefix is the exact 87 raw prompt IDs plus the first 31 matching output IDs. Both ranks' accepted/consumed traces must match it. Its last evaluated zero-based input position is 117; committed position is 118. Saved token is output31 (220), and next_token is output32 (16). Their indexed hashes already match these expected scalar encodings; actual bytes remain for root readback. Final logits have 248,320 BF16 values, emitted by the full target head before argmax. No draft logits are used.

Analysis computes stable float64 log-softmax over every native BF16 logit (max shift and math.fsum). It reports each reference top32 token's native global rank and tie interval, logprob delta, selected-token delta, and top1/5/10/32 overlap. BF16 ties use lower token ID for the deterministic reported rank. A completed comparison can report disagreement; no numerical tolerance or quality pass is invented. The reference exposes only top32 probabilities, so full-reference KL/distribution equality is unavailable. The llama reference computes probabilities with FP32 exp/accumulation after partial sorting and a float logarithm; this analysis is not a bitwise reproduction of that normalization. Source locations and hashes are in `source-inputs.json`.
