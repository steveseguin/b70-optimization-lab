# Remaining activation and logit precision gap

The corrected native binary5926 retains F32 recurrence but **still deliberately rounds ordinary activations and final logits to BF16**, unlike the selected CPU reference graph's F32 tensor outputs. This is a substantive remaining precision difference under the owner's no-extra-quality-loss condition. The retained final-position comparison is evidence of a numerical difference, not a measurement of which boundary caused it, and supplies no severity or quality threshold.

The actual compiled source closure is bound by recurrent-f32/evidence/native-build.json (6cf68…) and materialization.json (36d066…). Exact inspected generated paths and hashes are in source-inputs.json; these are the relocated sources used by5926, not stale top-level entry sources.

Source examples of extra intra-operator boundaries: native kernels.hpp norm helper rounds normalized values through Args::bf; conv with dilation3 rounds its pre-silu accumulator; moe_combine rounds routed sum and gated shared branch independently before addition; attention_value rounds its reduced value before gating. The selected adapter also includes explicit BF16 pooling/PLE-add boundaries. Promoting only allocation types would leave these casts, and the current raw-pointer kernels would misinterpret F32 buffers. This requires a typed dispatch correction, not an enum-only edit.

A narrow **head-only diagnostic/correction** can first preserve the existing FP32 lane/reduction result in a typed F32 logits buffer, with an F32 argmax consumer and typed dump allocation. Full248320 logits become993,280B instead of496,640B (net496,640B if replacing the BF16 buffer; an additional993,280B if retaining both). The current p33 submit binding has no diagnostic-F32 destination in its9-allocation binding; an actual additive kernel/output interface is needed. This isolates the last rounding boundary on the same hidden input; it does **not** correct upstream BF16 activations, prove F32-reference parity, or justify a quality claim. No implementation/build is authorized by this note.

A full reference-storage correction is wider: typed F32 embedding upload, residual/norm/linear/nonlinear/router/expert activations, GEMV input/output bindings, and explicit removal only of BF16 boundaries absent from the reference graph. Recheck routing IDs (BF16 router scores can alter expert selection), transfer sizes, private MTP hidden-state exchange and projections, scratch/alternate/snapshot/rollback byte lengths, dumps, and all specialization guards that currently require BF16. Preserve selected quantized weight bytes and the admitted BF16 attention KV contract. Recalculate the complete live/snapshot ledger before any claim of memory fit. Existing BF16 token/state exactness remains historical evidence, not the new baseline.

Even matching F32 tensor storage does not establish bitwise equality with this CPU reference. Its quantized CPU matmul can pack F32 activations into a vec-dot format (Q6_K usesQ8_K; ggml-cpu.c:327–331,1278–1365), and optimized tiled/ISA paths may run. Its reductions/activation math differ from our fixed SYCL trees/detmath. This source finding identifies concrete implementation differences; it neither dismisses the discrepancy nor assigns the observed logprob deltas to one mechanism. Longer same-prefix comparisons and, if needed, aligned intermediate checkpoints should localize divergence before a broad precision rewrite. No speed work or numerical tolerance waiver follows from token agreement.
