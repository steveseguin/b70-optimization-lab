# F32 recurrent correction: new numerical baseline

The5aef target stores matrix state and GDN/PLE convolution histories in BF16; pinned llama.cpp qwen4exp uses F32 for both recurrent state categories. See `../reference-cpu/RECURRENT-DTYPE.md` and its compiled-source/actual-index receipt. Old optimization/MTP receipts remain valid internal parity records, not proof of no precision loss versus that reference. This source correction must establish a new numerical baseline; it must not be forced to reproduce old BF16 tokens or state hashes.

The initial additive patch touches three private source files. Graph Builder creates36 matrix-state,36 GDN history and1 PLE history buffers as F32. Native ng::Args gains explicit recurrent F32 loads/stores selected by flag16; state extents double. GDN FP32 arithmetic/reduction remains unchanged but its commit no longer rounds state to BF16. GDN and PLE convolution histories retain FP32 old values, with current BF16 activations widened exactly. Adapter admission rejects mixed state input/output types and rejects old specialized implementations for F32 recurrence. Default current GDN/conv implementations are0. Existing BF16-state branch remains explicit for historical/synthetic use; the corrected production graph always selects F32.

BF16 attention K/V, indexer raw/pooled stores and ordinary activation/output buffers remain unchanged. In particular this does not silently claim all reference numerics are matched: reference QKV/intermediates are F32 whereas current projection activations are BF16; existing PLE accumulator rounding before SiLU is also unchanged. The independent CPU reference should preserve its own F32 recurrence. Any remaining divergence requires localization, not a quality waiver.

`prepare.py` verifies actual parent source hashes against the5aef build receipt and generates `source/{plan.hpp,kernels.hpp,adapter.cpp}` plus an exact patch. This is a reviewable source checkpoint, not a complete relinkable private tree. Full private include relocation and affected-TU build recipe are pending. The shared kernel-header change affects21 reused object dependency closures plus the current entry; the old39-object reuse recipe is invalid. The old object0 also includes old graph/inline kernels and cannot be reused unchanged merely because it may be discarded by the linker. No compiler or model/device invocation has occurred.

`test_storage.cpp` is a focused GNU CPU proof source using the actual modified ng::group/HostTeam and actual graph Builder. It checks73 F32 recurrent buffers, unchanged48 BF16 KV stores, extent/admission refusals, non-BF16-representable state retention,32 ordered feedback updates, inactive/error/position guards, and dilation1/3 history shifts. A byte-copy roundtrip is explicitly only a storage demonstration; it does not stand in for production speculative rollback/RESET. Root owns compilation and execution; planned strict flags are `-std=c++20 -O2 -g0 -DOWN_RT_HOST_ONLY -fno-fast-math -ffp-contract=off`, a depfile,4GiB AS and normal helper placement. Expected tests are not reported as passing until actually run.

Source audit of `state-bundle/build/source-v4/rank.hpp` shows bank allocation uses slot.n*scalar_bytes(slot.type), backup/readback uses actual allocation extents, and bundle append hashes the full typed extent. State-bank swaps exchange IDs; no BF16 conversion belongs in rollback.
