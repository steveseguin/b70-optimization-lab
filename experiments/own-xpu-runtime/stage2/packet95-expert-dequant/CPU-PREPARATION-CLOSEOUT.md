## Question and identity

Prepare the next exact expert dequantization designs before consulting packet86's
remaining diagnostic verdict. Frozen packet90 source lineage, packet84 explicit
hc-wide/wide64/ordered/rec-parallel control, `iq3-p49-split32-v1`, 24/24 target,
rank1 draft, full BF16 KV, shared pinned v4 lane screens. CPU only on the
four-card host; no model payload reads or GPU execution.

## Outcome

E3 is implemented and sealed. E2 is closed by exact no-fit arithmetic; no
hottest-layer ranking supports a bounded choice. E5 is deferred within the
bounded task. There is no device quality result or measured speed improvement.

Production and E3 each pass two fresh GNU and two fresh Intel fixture runs.
Each has 28 cases, 118,784 raw FP32 chain checks and 3,456 tree checks, plus all
finite-half/scale-nibble and all grid/sign combinations. Both view/rank startup
paths pass the actual allocation, dispatch, prepared-capture, snapshot and draft
construction paths. Eight malformed allocations and five malformed selections
are refused. Real arena admission passes on all four paths, with no E3 growth.

## What worked

The final two-word next-tile pipeline keeps arithmetic order and uses existing
wide code/high metadata. Linked code shows next-table reads outstanding during
current FP32 work, at 128 GRF and without scratch or flag-register spills.
The seal directly binds the real startup archives, linked assembly, tested
screen modules and cleaned-up fixture evidence. Closed choices refuse.

## What failed or remains uncertain

All-next banks spilled 15,488 bytes; per-chain next-block residency spilled
1,152 bytes. A spill-free scalar-metadata form incurred 69 static loads and an
early wait. The final wide-metadata form has 56 static loads versus 51 for
production, and 2,055 instructions versus 1,993: regression remains possible.
Static code is not a timing or occupancy measurement. GNU13's fixture template
condition caused an internal compiler error; spelling the type condition directly
fixed it without changing kernel arithmetic. A stale parent Python-test hash
was caught after a coordinator restoration; the tests were rerun, not repinned.
