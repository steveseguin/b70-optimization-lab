# P209 admission contract

Current disposition is **not admitted** because the protected vision application holds target BDF27. This file is a future reviewed recipe, not authorization to alter that application or launch the fixture. No manifest should be produced from the preparation snapshot.

## Fixed artifact and manifest

`runner.py --plan` is read-only and reports paths, environment and resource constants. The root coordinator must supply `READY-FOR-DEVICE.json` with exactly the keys accepted by `validate_manifest()` in [runner.py](runner.py). It is never generated by `--run`.

The manifest schema is `packet209.native-admission.v1`. Fixed fields are authorized=true, unit=`packet209-native-pair-a`, bdf=`0000:27:00.0`, lane=A, window=screen, timing_claim=false, output=`evidence/device-a`, and the absolute compiled `build/native/paired-qualification` path. Binary SHA and `source_sha256` must exactly equal the current compiled/source closure. `parent_device_image_sha256` is the P208 digest in the README. `boot_id` and an integer expiry timestamp are fresh reviewed values, not automatically adopted by the runner.

`environment` must exactly equal `environment()` in runner.py, including the frozen LD_LIBRARY_PATH, HOME unchanged and private cache paths. `fault_review`/SHA bind a complete captured kernel journal and the exact reviewed historical fault records. `pause_sha256` and `queue_sha256` bind both A/B files; both queues must be empty. `topology` maps all eight actual Intel DRM node paths to `{bdf,dev,sys_device,driver}`; `dev` is `major:minor`, driver is xe, and the four BDFs are 23,27,43,47. `target_nodes` is the sorted primary/render pair whose BDF is27, regardless of current card/render numbers.

`protected_units` is a dictionary of exactly three application units to their complete selected systemd property snapshots. `allowed_holders` contains exact `{pid,start_ticks,nodes}` entries from the complete privileged passive inventory; target aliases are forbidden even for a protected PID. `competitor_units` lists the reviewed experiment units that must remain inactive; this list is not a permission to ignore unknown device holders. Fixed floors are root_floor_bytes=27000000000, write_bytes=268435456, host_available_bytes=3221225472. No credentials or inherited environment dictionary belongs in the manifest.

## Future one-shot unit

After a fresh independent root admission and only with a reviewed manifest, use one user unit with these properties:

```
Restart=no
SendSIGKILL=no
KillMode=process
ExitType=cgroup
TimeoutStopSec=infinity
Nice=0
CPUAffinity=0-3 16-19
UMask=0077
LimitAS=infinity
```

The process command is `/usr/bin/python3 -B ABSOLUTE_PACKET/runner.py --run`. The wrapper must retain its ordinary user runtime environment for `systemctl --user`; only the native child receives the closed manifest environment. No extra worker, retry chain, stop/restore sequence or queue edit is part of this unit. The wrapper/native child inherit unlimited AS; do not wrap this command in the CPU compiler's AS cap or helper nice/affinity settings.

Before mutation, verify all source/object/build pins, fresh output/control absence, safe unit identity, both PAUSE bytes and empty queues, no outstanding lane/inflight marker, protected application PID/startticks and target-free raw metadata inventory. Fresh reviewed full-boot kernel evidence is required. The privileged helper only reads metadata; its rc1/passed=false is normal when other cards have allowed daily holders. Any helper error or unknown holder refuses admission.

The first native enumeration happens in the same explicitly admitted child, before owner creation. Its admission render descriptor plus BDF/dev_t receipt must be seen by the parent before ACK. Parent checks continue throughout. A new fault or changed admission halts new native requests and requests one cooperative incident stop. No failure changes PAUSE, queues, applications, power, memory settings or cache settings.

## Retention and result

A successful result is recorded durably before the lane/drain markers complete, then a final coordinator receipt is written. Failed paths never mark completion. Uncertain spawn, incomplete owner teardown, live process or target descriptors keep both actual flock contexts held; passive checks continue but no new native request is issued. A failed fully drained child may release the flocks while markers remain for explicit coordinator review. A positive, manifest/PID/starttick-bound entry-refusal receipt can prove no fixture entry. Missing output or missing ACK alone is insufficient; absent trustworthy proof retains ownership.

No current launch is possible without changing the observed target occupancy. This preparation does not authorize that change.

The current `--run` CLI deliberately refuses before constructing LiveOps, even if a file named READY-FOR-DEVICE.json exists. Enabling it requires a later reviewed source change and fresh admission; this prepared recipe is not currently operational.
