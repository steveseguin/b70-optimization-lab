# P210: actual host storage under a frozen cache interval

This additive CPU fixture connects the unchanged Device/Arena/CopyEngine and P198 Host backend retained by [P205](../packet205-host-row-capture/README.md) to the inherited `p58::Cache` and actual HOST `p58v::Publish`. It is not a model run, a native-device event proof or production expert arithmetic. Real CPU bytes are copied; queue/event completion uses the existing Host/LifetimeMock/MockDevice markers.

The fixture has 48 layers, four synthetic experts per layer, three 32-byte projection payloads, all 144 table destinations and a 2 KiB cache with eight aligned slots. It retains both rows' actual 12-byte `iq3::Route` values through CopyEngine copies. A captured synthetic consumer copies selected bytes from published pointers. Independently generated expected payloads and route logs constrain the result. The proposed cache policy freezes both tables and victim bytes for the entire two-row interval, then performs one chronological row-major prepare/fill/publication/commit. The row-serial control uses exactly this same policy. This is a policy change from P201's overlapping observe/prepare cadence, not a claim of unchanged recency or throughput.

Both initial host misses and later populated-cache hits are exercised. Real CopyEngine fills and both the serial publication-copy path and captured `p58v::Publish` update fixed handles. Tests distinguish caller metadata rebinding from live staging/table contents. Indirect pinned payloads and staging remain owner-held through completion: raw pointers are not ownership leases. Any Arena release invalidates generation, and pending work prevents release. All allocations precede capture, and no state is freed while captured consumers may run.

Negative fixtures cover wrong replay order, late old-table consumers, publication while readers own victims, indirect-payload release, incomplete consumer/publication markers, and failures after actual populated-victim overwrite or a changed table publication. Partial failure poisons intake and forbids next interval/publication; this fixture has no checkpoint operation. No rollback to the old table is claimed. Runtime owner cleanup and cache-policy success are distinct. Every fixture owner retains a shutdown receipt.

[Production binding](production-binding.json) pins reused source/object identities. [Build helper](build_engine.py) retains per-attempt source, command, logs and result bytes. Build/run is bounded CPU-only on nice19 helper cores with OMP/BLAS/MKL2 and a 4 GiB AS cap. No GPU enumeration, model load, service or queue action is part of this packet.

The selected [P201 dispatch source review](evidence/selected-dispatch-source-review.json) finds no active p25/p27 prepared-input conversion consumer in that exact configuration. Generic other dispatches are outside scope; selected FP32-conversion caching is not an unresolved active path for this proof.

## Result

The designated corrected CPU run passed all **25 checks**. [Host proof](evidence/host-cache.json) and [build receipt](evidence/build.json) bind 37 source inputs and 23 inherited GNU-host objects. Three intervals each compare 18,432 consumer bytes and 2,304 retained route bytes; their hit/miss counts are 0/192, 12/180 and 12/180, totaling 24 hits and 552 misses. All ten Host fixture owners report safe shutdown, zero in-flight work and zero live bytes. Serial and layer-major schedules agree exactly on outputs and normalized table identities, generations and payloads under the matched policy.

The [first attempt](evidence/build-1792799516282681432/receipt.json) compiled but stopped before comparisons because a pinned-copy-slab requested transaction lifetime. Its [raw error](evidence/build-1792799516282681432/proof.stderr), source and build command remain intact. The correction assigns transfer lifetime to pinned allocations and transaction lifetime to device scratch. The [fresh successful attempt](evidence/build-1792799565715335965/receipt.json) retains the exact corrected source and [raw result](evidence/build-1792799565715335965/proof.stdout).

This establishes real CPU storage/capture/publication behavior and consequential failure refusals. It does not qualify production expert arithmetic, device events, native-device execution, a model, performance, or the selected production cache policy. The next integration boundary is the actual tiny Engine's existing expert consumer, retained row/layer routes and captured table bindings under the explicit frozen policy.
