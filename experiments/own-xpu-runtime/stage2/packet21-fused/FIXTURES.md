# Packet 21 fixture contracts

No device fixture has run during the fault halt. Device executable compilation is not a device correctness pass.

`gemv_fixture.cpp` builds as `fused-fixtures`. Its 553 checks cover 540 matrix cases (ten matrix classes, six dispatch variants, M=1/3/87, K=512/1280/2560), nine paired-output checks, one four-stream residual case, and three routed/status/probability cases. Matrix classes are F32, F16, BF16, Q8_0, Q6_K, Q3_K, IQ3_XXS, IQ2_S, IQ3_S and IQ4_NL. Every dense bundle places three rows of one class immediately before five rows of another class. Paired tests mix Q6_K split4 and IQ3_S constant dispatch in the same work-group. The K=1280/2560 cases give all four split partitions nonempty work. Weight fixtures include signed zero, subnormal and maximum finite half scales, and very small/large finite F32/BF16 weights. Real model layer fixtures and token gates cover the production K values separately.

The three paired cases use no input transform, SiLU(input/4), and four-stream HC mixing. Each checks both original GEMV outputs after their BF16 stores and the BF16 SiLU/product output. Materialized prologue bytes are checked separately. The HC residual test updates four streams in place, with each output row owning the same coordinate in every stream. The routed case uses one valid and one out-of-range expert, a shared input row, two distinct status allocations, and probability normalization in the same submission. The invalid expert produces canonical NaN output and status 1 without reading the invalid row. Writable aliases with sibling inputs are rejected.

On device, unfused dense/routed GEMVs use the inherited original kernels. Separate standalone elementwise submissions reproduce the unchanged v2 equations and BF16 boundaries for prologues, activation, HC residual and probability normalization. Each output is checked against host bytes, then against the fused output via the same expected bytes. Two fresh owners and matching host-compiler byte files remain necessary; the fixture executable itself is one owner.

`nongemv_fixture.cpp` builds as `nongemv-fixtures`. It retains packet 20's 72 fixtures, six producer/consumer chains, eight inactive/sticky/invalid-control checks and norm-to-activation boundaries. The snapshot and original-source hashes are in `prototype/prototype-provenance.json`. The only copied host-gate source adjustment is explicit success return when its main function is renamed for embedding. The device reference submits one unchanged Core row at a time. The candidate uses parallel original group geometry for standalone operators, sharded route ranking, per-head fused attention, and one-work-group chains for the registered M=1/3 producer/consumer cases. In particular the standalone M=87 GDN case does not serialize all groups into one work-group.

The non-GEMV executable also links the actual packet 21 `adapter.cpp`, `runtime_kernels.cpp` and native helpers. `adapter_fixture.cpp` adds 16 comparisons: HC combine/norm/mix, convolution/GDN/gated-norm, QSA prepare/pool/select/attention, and sharded route ranking, each at M=1 and M=3. Here M=3 means three consecutive one-token submissions through the runtime API, preserving the recurrence and cache state. Specs use the production `packed_heads=true` layout, and fixture uploads complete before compute submissions. Every candidate output is compared with the unchanged v2 host interpreter and separate same-card unfused interpreter submissions. Rank IDs and both descriptor tables are compared with the original route plus expert-gather operations; raw selected probabilities are checked against the v2 max/exp/adjacent tree, then a standalone normalization step permits direct comparison with the original route's final probabilities. The independent GEMV fixture checks the runtime's fused normalization placement. Both raw and final probabilities contribute to the output hash.

Copied prototype namespaces are isolated at their include boundary because their 16-slot buffer ABI differs from the actual adapter's 19-slot ABI. The snapshot files remain unchanged. Device non-GEMV runs have two sequential owners on the same card: the first completes and shuts down before the actual-adapter owner starts. The receipt states `sequential_owners:2` and retains both complete shutdown receipts. Host non-GEMV runs have one CPU mock owner and state `sequential_owners:1`. Whole-runtime packet 21 CPU gates and prepared W1/W2/W3 additionally cover integrated scheduling. No CPU pass upgrades these device paths to qualified status. New M=1/3 fused chain device durations are unmeasured. The historical single-work-item reference Core row is about 1.05 seconds; this is neither a timing guarantee nor a speed result for the new chains.

Both binaries accept `--output DIR`; device builds additionally require `--authorized-device-window --card N`. The non-GEMV executable accepts `--fixtures DIR`, defaulting to `build/fusion-fixtures` under this packet. Each writes `output.bin` and `receipt.json`; the receipt uses `own-runtime.iq3.packet21.fixtures.v1`, includes the output SHA256 and largest profiled submission, and requires safe owner teardown. Only the sealed window wrapper authorizes a future device run. The source files and direct executable options are not permission to run anything during the fault halt.

The row-bundle descriptor table is uploaded by the runtime owner and remains device-resident. Each output row scans at most eight descriptor ranges and branches uniformly on its matrix class and variant. Every row receives a 128-thread work-group. A nonsplit row uses one SG32 subgroup and leaves the other three subgroups idle; split4 uses all four and combines `(p0+p1)+(p2+p3)`. Paired dots run sequentially in that group and preserve the two original BF16 stores before activation. Input prologues are recomputed into local BF16 storage per device output row, up to 34,816 bytes at K=17,408; this duplicated work may offset issue savings and needs measurement. The CPU emulator computes those same pure expressions once per distinct input within each submission, sharing an immutable temporary vector among output rows. It retains nothing across submissions and changes no output bit.
