# Packet58 memory plan

Metadata only: no model payload, large pin, or GPU allocation ran. The
[machine-readable plan](memory-plan.json) is regenerated by
[memory_plan.py](memory_plan.py). Every packed target expert is represented
exactly as in the admitted mixed-quantization census. There are 48 layers,
512 experts each. Each ordinary expert is 1,971,200 bytes; layer 2 uses
2,329,600 bytes. Total pinned expert storage is **48,627,712,000 bytes**.

The first milestone is plain target decode, 4K capacity and BF16 KV on one
card. The complete target nonexpert allocation is 5,815,529,984 bytes, derived
from the retained two-rank allocation census after removing expert weights
and one duplicate RoPE table. PLE/embedding remain file-backed lookups.
The 18,000,000,000-byte global LRU arena is additional to its metadata.
The cache starts empty, independently of prompt content; no benchmark prompt
trains initial placement. Niko1221 / Strata supplied the hot-expert-cache
idea. All implementation is independently authored lab code.

GPUActive is kernel driver memory and is absent from process RSS. The
[host diagnosis](../../../../docs/host-stability-and-fault-diagnosis.md#host-ram-that-vanishes)
measured this shadow in a multicard context. A single-card context ordinarily
avoids it. We still reserve the entire possible shadow and monitor its growth.
The wrapper masks a single physical card; the native program uses visible
index 0 and constructs a one-device context. No runtime debug knob or host
memory setting is changed.

MemAvailable already reflects existing processes and GPUActive; no existing
allocation is subtracted again. Swap never adds to admission. The wrapper
refuses before model load or pinning if available memory is below the exact
bound. It requests graceful stop if MemAvailable falls below 8 GiB, anonymous
memory exceeds the pinned-plus-process allowance, or GPUActive growth exceeds
the reserved device bound. It never kills a busy child or changes memory
settings. Failure to drain leaves the child for the coordinator.

The loader must stream the target experts straight into their single pinned
bank using bounded reads. A second long-lived expert file/page copy is not
admitted. Full file-backed nonexpert/lookup residency is charged, though the
lookup working set should be smaller. The full pin occurs only in coordinator
model windows. CPU tests allocate tiny fixtures only. Blocks 54 and 56 must
remain offline; states of best-effort margin blocks 53, 55 and 57 are recorded.

The draft is omitted. Adding its 3,354,364,214-byte device allocation also
requires host backing/shadow and verified rollback accounting; this target-only
admission must not be reused for MTP.

## Packet58c accounting correction

The table and all byte budgets above are unchanged. The earlier sentence that
all GPUActive growth is shadow is superseded: host expert USM can also be
accounted there. Let P be completed census-checked pinned expert bytes, G be
nonnegative GPUActive growth since admission, and A be process-tree anonymous
RSS. The sensor checks `max(0, G-P) <= 26,409,219,600`. It also checks
`P + max(0, G-P) + A + 33,323,087,360 <= 109,718,973,456`, the original host
budget excluding the 8 GiB reserve. A is charged in full, without another P
subtraction. This conservative charge can overcount during teardown or on a
driver that includes host USM in RSS; it cannot grant the same pin credit twice.
The old pinned-plus-4-GiB anonymous stop remains independently enforced.

Credits come from the initial load progress log, which remains in place when
per-request logs move to subdirectories. Every complete `pinned-expert` row
must name a unique tensor with its exact census size. Partial writes get no
credit; duplicate/unknown/wrong-size rows, truncation and disappearance fail
closed. Each new window starts at zero. One in-flight bank is conservatively
charged as shadow until its completed row is flushed. No full-model pin or
future layer is credited in advance. K1 keeps its original 4 GiB GPUActive cap.

58b's closed environment excludes both `NEOReadDebugKeys` and
`EnableDeferBacking`; see the retained window receipt. The older
[multi-card probe](../../../ltx25-b70/notes/2026-10-04-host-ram-shadow-of-vram.md)
is background evidence about device-buffer shadow, not proof that pinned host
USM vanishes with that setting. No environment change is proposed.
