# Independent source audit — packet 16

Reviewed independently of the incident README's causal claim. CPU file reads only; no device discovery, device binary, parked-process inspection, or device run. Original source line references below refer to packet16-decode unless another packet is named.

## Result and evidence limits

No missing inter-submission RAW/WAR/WAW edge, foreign compute allocation, or pending allocation release was found in the shipped resident first-token path. This is a source-review conclusion, not a device qualification. The original CPU mock cannot validate driver mappings, native event interoperability, or workgroup races.

`owner.cpp:Device::compute` appends `events_.back()` to the supplied dependencies (lines 109–110), and `CopyEngine::copy` does the same (218–219). `Engine::dev` always returns `devices[0]` (main.cpp:448–455): both native queues share ONE owner/event ledger. Therefore the predecessor is global, not per-card. Every native submission checked passes these dependencies to `h.depends_on`. The two native queues additionally have `in_order`, although correctness does not need that extra edge. The ordered DAG is a total order within every non-retired segment. Randomizing a correct representation of this DAG will leave that segment in the same order; a useful sanitizer must also have negative missing-edge tests.

The incident does not establish “before any site completed.” `main.cpp:enqueue` emits site timings only with `a.mini || a.checked`, and per-site progress only with `a.checked`. W2 had neither. No completed token is recorded, but empty sites.jsonl is the expected behavior of this command even after successful sites. The kernel log records two distinct addresses: 43:00.0 faults on `0x0000d556a9ed0000`, 47:00.0 on `0x0000caac549d0000`. Both coredumps were read; both VM-state captures end with `[0].error: -19`, so no allocation/address correlation can be made. Their snapshot timestamps differ by 0.000318839 seconds. Both report GuC 70.44.1 with wanted 70.54.0; that is context, not proof of causation. The capture filenames alone do not justify attributing a batch address to a physical card; the batch address families and kernel fault-address families cross the filename labels.

## Ranked explanations

1. **Native cross-device event/backing residency or shared-context submission behavior, unproven.** Unlike packet14's drained peer bridge, packet16 submits cross-queue event dependencies from its first pair of kernels: begin.0(Q0) -> begin.1(Q1) -> broadcast(Q0). Thus a synchronization allocation internal to SYCL/Level Zero, rather than an application tensor, could be read remotely before the layer-23 handoff. This can fit near-simultaneous faults on both queues. The application registry does not see these internal allocations. The evidence lacks a native event/allocation trace or VM dump needed to establish it. `EnableDeferBacking=0` is not consumed by application code and cannot be judged from this code. It may affect the underlying allocator/backing behavior, but the code does not demonstrate either safety or a bug caused by it. Packet14 without this key proves neither result for packet16's different event topology.
2. **Device-computed index corruption plus incomplete local guards, demonstrated guard gaps but no causal trigger found.** Tiny QSA has unguarded positions and selected IDs; real ng attention_value trusts earlier score validation. The former is not the real W2 geometry; the latter runs after a guarded score kernel in the audited complete chain. All plan buffers including routes/IDs are zero-initialized. Expert weight pointers in packet6/7/8/9 are formed only inside valid_route guards. These weaknesses should be fixed, but are not a demonstrated W2 first-token fault source, and do not by themselves explain two simultaneous faults.
3. **Application cross-device binding, omitted edge, or early release, not found.** Context::compute checks every bound pointer against allocation_card; all call paths select the site card; copy is the only allowed foreign endpoint. Both compute and copy append the common predecessor. Allocation release requires no in-flight events; event retirement synchronizes before clearing. Any contrary candidate needs a precise path or native trace, not inference from the symptom.
4. **Hardware/driver pre-existing fault state, unresolved.** A previous fault on the same boot and the common software stack remain confounders. Near-simultaneous symptoms are compatible with a common software trigger but do not logically rule out driver/global recovery effects or a hardware-triggered cascade. No such behavior can be proven from the captured source and logs.

## Exact submission expansion and ownership

Let `Eprev` mean the most recent event in the one owner ledger. Every row below receives caller dependencies followed by `Eprev` when it exists. After a successful host wait and `retire_completed_events`, earlier events are absent because retirement performs backend synchronization, not because the edge was silently dropped. All device allocations are in shared context C and owned by the queue's logical card; physical Q0 is the first selected native device and Q1 the second. The two `bounded-copy` slabs are pinned host allocations in C with owner -1, never kernel bindings. Scratch/control/score/probability/workspace/snapshot/mixture allocations are distinct per card. Weights belong to the card of the site that first loads that weight, and lookup weights are read on CPU instead of resident device allocations.

## Hazard checks at the requested boundaries

- **H2D embedding:** `put -> upload` drains, copies into a pinned slab, submits H2D, waits, synchronizes/retires. Row source vectors stay live through the copy. `prepare_token` preloads embedding and PLE rows before any model site; the later lookup site is deliberately a no-op.
- **Layer23 boundary:** every copy gets the previous global event. First Q1 copy depends on the last Q0 kernel/capture. Last error copy precedes the first Q1 kernel, and buffers resolve in buffers[1]. No Q0 pointer is directly bound to Q1 compute.
- **Sticky error:** per-card plan error buffers are initialized to zero. ng entry copies sticky error into its local controls, exit merges it back; entry/main/exit are chained. Handoff uses a copy, so a Q1 begin error would be overwritten by Q0 error, but first-token positions and active values are equal and host admission checks context. This is a latent diagnostic preservation issue, not a first-token uninitialized read. Tiny/simple global error reads/writes need consistent atomic handling when new multiple-workgroup guards are added.
- **Routes:** route kernel -> gather -> fused projection -> check_status -> activation/up check -> down -> check_status are all chained. All route slots and expert input are zeroed initially. Packet9 `Projection::run` validates route before weight pointer arithmetic, as do packet6/7/8. `simple(expert_gather)` nevertheless converts floating View data to int before testing range; guard before conversion, and fill safe route/input data on failure.
- **Fixture captures:** snapshot D2D copies depend on ffn.combine and precede later writes to streams (WAR protected). However snapshots are allocated without initialization, and capture reads all 48 slices on each card, including slices never written by that card (and all unused layers for tiny). This is an actual uninitialized-byte readback, not an index read or demonstrated page-fault cause; only captured slices are hashed. Fix by zero-initializing snapshots or reading only populated slices.
- **Lifetime:** resident weights/state/scratch persist through all tokens and teardown. Slab reuse is separated by completed waits and retirement. Local Operation objects copy their Spec/pointers into submitted closures; no escaped references to stack Operation state were found. Queues/context/events are released only after drain and synchronization. Failure retains the owner. No application use-after-release found.

## Device-index guard inventory

- Host token IDs and bounded embedding/PLE row IDs: host validated before CPU row reads. PLE device IDs are written but packet16's lookup uses host-derived IDs; they are not device address inputs in this path.
- `simple(expert_gather)`: integer conversion precedes range test; must finite/range/integrality-check floating View value first and write safe route IDs.
- `tiny(qsa_prepare/qsa_append_pool/qsa_select)`: reads unchecked uint32 position and converts to int; begin normally rejects invalid position, but each address-forming kernel should be self-contained.
- `tiny(qsa_attention)`: selected IDs cast to int without finite/range check and used for key/value addresses; -1 sentinel terminates, all other invalid values must set error and substitute0.
- `ng::group`: validates position globally before pool/select/attention addresses. attention_score validates selected upper bound and future positions, treats negative as sentinel; attention_value does not repeat the bound test and can form a wild address when invoked directly or after corrupted IDs. attention_softmax can consume unwritten scores if a corrupted nonnegative list extends beyond min(capacity,budget+3). Local bounds required.
- QSA score ranking with NaNs can make duplicate ranks (write race) though it does not produce out-of-bounds indices; reject nonfinite ranked values before writes. Router already rejects nonfinite logits before ranking.
- Serial control `packet4/core.hpp:Core::run` also lacks standalone QSA position/ID guards; qsa_attention converts unchecked positive floating IDs, and expert_gather accepts NaN because both range comparisons are false. The ordinary begin/route chain protects valid runs, but standalone defense needs finite/integral bounds before conversion. `packet4/kernels.hpp:evaluate` narrows uint32 position without its own check. These gaps are included in the patched copies and standalone core tests.
- Expert bank pointers: packet6/7/8/9 use valid_route before pointer formation. valid_route checks expert_id, row_begin, row_count, and span using bounded subtraction. Dense row IDs, head IDs and group indices derive from validated launch geometry rather than device-computed values.
- Argmax local lane IDs derive from bounded loop counters; NaN logits set sticky error and generated host token is range-checked by vocabulary access. No raw NaN-to-int path in argmax was found.

## Why W1 could not qualify this path

W1 uses stage_layer/release_layer, loads only selected experts after router D2H, uploads compact routes 0..top-1, and repeatedly drains/synchronizes around weight loads. W2 keeps complete expert banks resident, consumes original route IDs directly, chains both queues through one ledger, crosses cards at begin/handoff/result/commit, and holds ~53 GB of weights. W1 exercises most valid-input arithmetic, but none of these residency/event-topology or full-bank-addressing differences. It also cannot validate a compiler's handling of cross-device events, internal allocations, or native backing policies.

The smallest post-reboot device check should use two cards and the same shared-context backend with a few KiB of local buffers: Q0 initialized-input trivial kernel -> cross-device event-only dependency to Q1 local-input kernel -> Q0 kernel, before peer data copies; then tiny bidirectional peer copies with canaries and local consumers. Drain and verify each short stage, preserve exact environment and allocation/event trace, and stop on the first fault. No model weights or 53 GB allocation should precede that check. This document does not authorize or perform it.

## Review of proposed containment and guards

The patched `Context::dependencies(deps,target)` preserves application happens-before by host-waiting each foreign-card event and retaining local-card native dependencies. It records the queue card for compute/copy/marker and clears the event-card map alongside events. This prevents a foreign native event from appearing in a SYCL wait list, but is speculative containment of an unproven event-residency cause, not a proven root-cause fix. Same-context peer copies still require device qualification. A CPU mock cannot validate the native mapping mechanism.

Snapshot initialization must cover every allocated card even if it lacks an `active` plan buffer (e.g. a first-layer two-card diagnostic); place it before the active-buffer early continue. This fixes the confirmed never-written snapshot readback bytes without modifying captured layer bytes.

Parallel guards use atomic sticky errors plus a workgroup-uniform startup snapshot, avoiding divergent barrier participation if another group fails. Native attention_value validates indices independently of attention_score, and softmax/value reject lists longer than the number of score slots launched. Tiny QSA validates positions and selected IDs before any conversion/address arithmetic. Both expert gather paths validate floating IDs before integer output conversion. The serial Core receives equivalent standalone guards. All arithmetic on valid inputs is preserved.
