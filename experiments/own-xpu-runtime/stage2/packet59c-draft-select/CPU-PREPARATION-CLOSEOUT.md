## Question and identity

Can the coordinator isolate packet59's measured draft regression without
rebuilding for every switch? October 17, 2026, steve-b70s, CPU-only preparation
from packet59. The quantized compressed Flash-Next IQ3 lane retains packet56's
target, packet49 arithmetic/oracle, BF16 KV, 23/25 split, draft rank1 and the
91,392-row draft prefix. No model payload read or GPU execution was authorized.

## Outcome

Prepared and sealed: 30 draft swaps and ten fusions, production defaults,
one device binary, four screen selections. GNU host and Intel device builds
pass. Forty-six registered choice sets each pass two fresh CPU runs; every
run matches 96 packet56 target layer fixtures and 24 target tokens. The
production default's proposals match packet56; all-on proposals match packet59.
The 132 copied target files and 33 shared compiler inputs are unchanged; the
only inherited target-facing change is the strict init-time selection parser.

Route (135 checks/run), split32 (88 checks/run) and production-width dense
fused/unfused fixtures agree across two fresh runs. Fourteen selection tests,
including 46 profile and ten fusion-dependency subtests, pass. The default and
four selected lineages pass the unchanged screen tool's CPU-only `--plan`.

Fast reseal takes 0.86–0.87 seconds for the four prepared profiles. A new
qgate+route combination, including two fresh CPU runs, takes 3.40 seconds.
All selected lineages share the same binary inode/hash; overwriting an
existing seal is refused. The root build occupies 125.48 MB. No GPU, sudo,
service, host-setting change or external publication occurred.

## What worked

Native init validates every switch and the exact selection hash. The target
choices are frozen. Capture retains every original launch slot; replay uses
prepared commands. Each fusion can be disabled while retaining its candidate
producer. Immutable selection lineages carry their own JSON, CPU fixture and
screen seal, and reuse the binary through hardlinks.

## What failed or remains uncertain

The first configuration caught an omitted inherited `.inc` file during the
source copy; the exact parent file was restored. The first seal attempt found
a bookkeeping error: the host receipt had been added to the source map before
the device comparison. The corrected sealer compares each build against the
same compiled source set. Neither issue executed a device. Compile history
remains under ignored `build/build-log-history/`.

Source diagnosis ranks short-context split32 overhead, HC synchronization,
fixed256 norm barriers and serial fusion tails as suspects. No source-visible
odd vector stride establishes misalignment. Device performance, acceptance,
full-model exactness and device determinism remain unmeasured for 59c. The
four screens isolate groups, not individual effects or all interactions.

## When to revisit

The coordinator runs attention, HC, experts/route, then norms/merge under the
same screen conditions. Keep production for losing or unresolved groups.
If a group wins, a selected combination needs its own measured validation;
never sum isolated deltas into a speed claim. Further per-switch bisection
uses the same binary and fast reseal. This closes the requested CPU task,
not the optimization lane.
