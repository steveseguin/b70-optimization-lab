# Packet 53 CPU identity argument

The unchanged production expert row has 32 logical lanes. Logical lane `l`
reads positions `256*t + 8*l + j`, with `j=0..7`, in ascending `t` and `j`.
It starts at positive FP32 zero and performs a separate rounded multiply and
add for each value. The final reduction adds adjacent pairs at widths
1, 2, 4, 8 and 16, then rounds to BF16.

Virtualization assigns logical lanes `V*p + v` to physical lane `p`, for
`v=0..V-1` and `V` equal to 1, 2 or 4. Each logical lane keeps its own FP32
accumulator. Interleaving independent chains changes no operation in a chain.
The first `log2(V)` levels of the original adjacent tree occur inside each
physical lane; subsequent levels select adjacent physical lanes. These are
the same additions with the same operands and order as the production tree.
For down projection, K=640 gives three eight-value steps to logical lanes
0–15 and two to lanes 16–31. An absent step performs no addition.

Persistence changes the owner and order in which separate rows are evaluated.
It introduces no accumulation between rows. The SLM IQ2 table contains the
same 2,048 32-bit words as the production 1,024-entry, eight-byte codebook.
Moving its two indexed word reads to SLM changes no decoded number. No weights,
scales, routes, BF16 rounding, or arithmetic oracle are replaced.

`cpu_identity_test.cpp` is an independent gate. Its scalar decoder reads the
normative byte tables and compact format planes without calling the candidate
or production decoder. Its scalar traversal walks K in ascending order and
assigns each product to `(k/8)%32`, rather than using the production lane loop.
It compares every FP32 logical lane, the full FP32 reduction, and BF16 bytes
with the unchanged production arithmetic and the shared candidate functions.
BF16 rounding cannot conceal an FP32 reorder in this gate.

Coverage includes all 1,024 IQ2 indices and all 256 sign masks; finite half
scale boundaries, signs, zeros, subnormals, and scale nibbles; both real K
shapes; both expert streams; actual 640-row gate and 2,560-row down expert
strides; ten distinct routes changing across serial M=1/M=2 rows; and random,
cancellation, signed-zero and tiny activation patterns. Selected first,
interior and final rows limit CPU work while retaining the true expert and
format strides. A scalar-position census covers every K position and verifies
the asymmetric down-projection chain lengths. Tree adversaries include a
negative control that would reject a reordered sum.

The gate also checks the paired gate/up helper with distinct weight rows,
compares all registered host kernel arms against production on route/status
controls (including invalid, shortened and nonzero-start routes, inactive
control and sticky errors), and counts every scheduled output exactly once.
The scheduling census covers real output counts and padded tails on both sides
of a persistent launch stride. The production comparison should run with
`OMP_THREAD_LIMIT=1` to keep this gate to one CPU worker.

CPU evidence proves the arithmetic/mapping implementation under the recorded
compiler flags. It does not prove SLM synchronization or device shuffle
execution. Coordinator E1/E2 compare device bytes directly with the unchanged
production expert kernels before timing may qualify. No oracle regeneration
is required or authorized by this packet.

Build and run receipts are generated by the packet CPU gate; do not infer a
pass from this design argument alone.
