## Implemented kernels and gates

`fused.hpp` changes no GEMV arithmetic. `chain` invokes unchanged group bodies
with ONE work-group for the whole multi-site chain; its barriers therefore
cover every producer. All intermediate BF16 stores and adjacent/dot128 trees
remain. Increasing group count without a new synchronization design is invalid.
The gate checks 72 fixtures against copied v2 Core, plus six actual chains at
T=1 and T=3: HC combine+norm→mix, conv→GDN→gated norm, and QSA
prepare→pool→select→score→softmax→value. It compares every retained intermediate
output/state. Eleven norm→activation chains exercise dependent BF16 stores
and odd widths. Eight controls cover inactive, sticky-error, invalid-position,
and late-row invalid attention slots. This is not full-model decode integration.

`attention` uses one work-group/head and unchanged score, softmax and value
groups. It retains admitted order, maximum, exponential, adjacent sum including
original odd-node addition of positive zero, probability division, PV tree,
and BF16-before-gate rounding. Every group prevalidates every token’s selected
IDs before writes. Invalid requests fail closed; nondeterministic partial
scratch from the unfused fault path is not an exactness oracle.

`route_rank` distributes expert candidates over four groups/token. Each group
recomputes the original max/exp/adjacent softmax denominator, then ranks its
disjoint candidates with lower-ID ties. Every selected slot has one writer.
Duplicate denominator work avoids a third synchronization launch without
changing bits. The second launch normalizes selected probabilities using the
same top-k adjacent tree; it skips work on sticky error. No 2,560-wide input
row is copied. The gate compares single-row indexing to every original gathered
row and asserts the removed gather destination stays untouched. Descriptors,
IDs and FP32 probabilities match Core.

For rule (iii) minimum, run rank then emit finish from one designated group/token
inside existing expert gate/up. Expert arithmetic consumes no probabilities;
MoE combine waits for the whole launch. Alternatively finish inside MoE combine.
Those consumer integrations are designs: the tested independently callable
prototype has two launches. It must not be described as the minimum.

## Rule (ii) interfaces: design only, no GEMV edits

1. Replace one matrix descriptor with RowBundle of row ranges carrying weight
   pointer, quant type, input/output views, row offset, reduction variant and
   partial-buffer offset. Concatenate only equal-input siblings; dispatch each
   row through its original arithmetic. Physical phase count is maximum sibling
   count. Frozen variants1/4 keep two phases; expanded variant7 already uses one
   launch with its split tree internally.
2. Bundle HC down/inject; GDN qkv/z/alpha/beta or QSA qgate/k/v/index-q/index-k;
   router/shared-gate/shared-up/shared-scalar; PLE key/value. Expert gate/up is
   already bundled. Retain all branch outputs until every consumer completes.
3. InputView prologues implement HC SiLU/4 and four-stream mix, explicitly
   rounding BF16 at original boundaries and retaining stream-order multiply/add.
   Re-evaluation per reading GEMV row costs work but is exact. Norm remains a
   separate global row reduction, never silently an elementwise prologue.
4. Paired gate/up epilogues assign both corresponding row reductions to one
   group, keep original BF16 outputs, then apply SiLU/product and BF16 rounding.
   Attention-output residual epilogue retains output BF16 then residual BF16;
   four stream destinations are disjoint. Head final.act folds into final.gate
   input and final.mix into logits input: these are the two outer savings.
5. Status checks move to consumer prologues after the previous launch completes.
   Check the same ten statuses before dependent arithmetic; use atomic sticky
   error and uniform per-group decisions. Device fault-path gates remain needed.
6. RoutedInput{base,row_stride,expert_stride} uses expert_stride=0 for gate/up:
   every selected expert reads one 2,560-wide row. Down keeps expert_stride=640.
   Weight bytes, descriptors and every reduction’s logical input order stay.

Alias constraints: HC streams remain live through old-stream readers; conv
history is read before replacement; recurrence forms its output before BF16
state commit; attention score/probability storage stays separate while heads
read. The prototype retains distinct intermediates and original state updates.
Integrated arena liveness must extend to the fused event. Reject cross-group
producer/consumer aliases or add scratch/serialization. None requires changing
a floating-point operation. The expensive serialized prototype is not admitted
to the tiny launch-cost window.
