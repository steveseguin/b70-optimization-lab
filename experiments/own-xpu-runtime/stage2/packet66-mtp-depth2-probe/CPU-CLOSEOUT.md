## Question and identity

Prepare a discarded recursive second-token MTP probe in a separate copy of
packet61x, dated October 17, 2026. The target is the quantized compressed
Unsloth IQ3 Flash-Next lane, unchanged packet49 oracle, two B70s, rank1 draft,
23/25 split, 4096-position BF16 cache. Device work belongs to the coordinator.

## Outcome

CPU preparation is complete and the lean screen seal admits lane B. No GPU,
model payload, CPU model generation, service or host-setting operation ran.
Device output identity, a2 and second-pass timing remain pending. The screen
will check incident64 and all 12 fixed prompts exactly against packet49.

The small fixture passes against packet61x's original draft implementation:
two fresh candidate runs, each 68 tiny draft steps over two reset-separated
requests. Every d1, full-state fingerprint and retained raw final-state byte
matches. Both runs' 68 discarded d2 guesses match each other. The production
HC target byte fixture equals packet61x's retained output. All 136 copied
target source files remain byte-identical. Four acceptance-analyzer tests pass.

## What worked

A bounded private snapshot lets the same MTP layer run again with its first
hidden output and the d1 embedding, without duplicating weights. Deferring the
probe from the publication callback to a quiescent command boundary preserves
the existing event owner. Restoring the exact attention extent preserves the
normal draft across the 32-position boundary. The 32 MiB memory reserve fits
inside the unchanged arena and free-space limits.

## What failed or remains uncertain

Two setup refusals were fixed before qualification: the tiny plan initially
used inconsistent context options, then the new backup used an unsupported
scratch/process lifetime pair. The final lifetime is transaction. An original
reference build also needed its includes rebound to the same unchanged kernel
headers to avoid duplicate type definitions. No device fault occurred.

There is no measured M=1→M=2 GDN increment in the reviewed receipts and the
engine does not batch target verification. The cost model therefore labels
its serial-row proxy and normalization explicitly. At assumed a2=0.60 the
optimistic partial projection is 55.03 tok/s (+7.84%); acceptance is not
measured. Do not build the full depth2 engine until the ≥10% case is supported.
