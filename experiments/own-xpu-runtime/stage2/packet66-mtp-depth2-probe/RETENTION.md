# Packet66 retention and rebuild

This is a local diagnostic packet, not a public deployment package. Preserve
the sealed packet61x compiler outputs: unchanged kernel/wait objects are linked
by hash. Only host entry objects and small CPU fixture drivers are compiled.
No GPU compilation target is executed. The final build receipt records exact
commands, source hashes, compiler version, binaries and logical build size.
Compilation is serial, nice19, on cores 8–15,24–31, with an 8 GiB address-space
limit. Preparation requires 10 GiB disk free; build output must remain below
1,000,000,000 bytes.

Retain `build/` locally. It is ignored in Git and can be rebuilt from this
source plus the retained hash-bound parent compiler objects. Do not edit or
write through inherited hardlinks. The copied 4 MiB `rope.bf16` is necessary
for source-relative engine initialization; it is the parent's exact immutable
RoPE constant, not a model weight. Its SHA256 is in the build receipt. This
explicitly retains the file despite the repository's 1 MiB review threshold.

Fixture `.bin.gz` files retain every expected/actual/state byte with an
uncompressed SHA256 and archive SHA256 in `fixture/retention.json`. Raw `.bin`
files stay local and are ignored; restoration refuses to replace different
bytes. Before verifying a seal in a restored checkout:

```bash
P=experiments/own-xpu-runtime/stage2/packet66-mtp-depth2-probe
nice -n 19 taskset -c 8-15,24-31 python3 -B "$P/retain_fixture.py" --restore < /dev/null
```

Never remove the existing seal to rebuild this admitted candidate. A changed
candidate gets a separate directory. The tiny original-reference fixture is
generated by adding only observation accessors to packet61x's `mtp.hpp` and
rebinding its two includes to the identical local kernel headers. Its compute
bodies are unchanged. The source closure records both original and generated
files.

Earlier preparation-only fixture failures are retained locally under
`evidence/fixture-context-failure/` and `evidence/fixture-lifetime-failure/`.
The first used inconsistent tiny-plan context options. The second exposed the
backup's invalid scratch/process lifetime pair; the final code uses the
required transaction lifetime. A passing earlier fixture before the final
allocation-accounting correction is retained under
`evidence/fixture-before-memory-accounting/`. None executed a GPU or model.
The final fresh gates are the ones bound by `screen-seal.json`.
