# Evidence and scratch retention

This packet owns only this directory. Device programs are compiled but never
executed during CPU preparation. `build-receipt.json` and its named gate receipts
are the qualification authority; older attempts are historical evidence.

`parent-copy.json` records the amended packet38 tracked source copy. Unchanged
large parent evidence was not duplicated: `inherited-evidence-links.json` maps
its exact hashes and immutable parent locations. Copied parent receipts remain
historical until re-executed and bound by the packet40 execution ledger. New
failed and successful attempts are retained separately under `evidence/`.

Large artifacts are intentional and reviewed for retention:

- `official-tensors.json` retains the authenticated official draft tensor ranges
  and hashes required to reproduce the load manifest. Regenerate with
  `prepare_mtp.py` against the pinned publisher shards; it contains no weights.
- `p33-candidate-gates.json` retains every operator identity case. Regenerate
  with `p33_candidate_gates.py`; do not reduce it to an unbound pass boolean.
- `native-mini-cpu.json` retains all 1,109 controller comparison cases and raw
  per-request inventory hashes/counters, including the declared terminal-state
  scope. Regenerate with `native_mini_gate.py` against the sealed GNU host binary;
  its size preserves auditable coverage instead of a bare pass count.
- Historical `resume-*` archives belong to packet38 and are reachable through
  `inherited-evidence-links.json`; they are not new packet40 gate executions.
- `evidence/qualification-*.json` binds a command, return code, exact source and
  binary identities, freshly written receipts and its compressed log. Failed
  attempts remain evidence but do not qualify the build.
- `evidence/scratch-*.json.gz` keeps test text and original byte hashes before
  deleting raw CPU scratch. Decode with Python `gzip` and `json`; each text
  entry has its exact original string. Raw states are regenerated by the named
  source-bound CPU gate, not restored from a claimed backup.
- `evidence/scratch-*.jsonl.gz` uses the bounded-memory
  `packet38.scratch-stream.v1` format: file records with sizes/hashes and
  base64 chunk records for retained text or nested compressed evidence.
  `storage.archive_files` reads back and hashes every retained member before
  deletion. `seal.archived_run` verifies and reconstructs it for final checks.
  Real-controller archives can exceed 10 MB because every target allocation,
  token/guess event, and retained fixture is needed to compare both controllers.
  They are deliberate qualification evidence, not disposable build output.
- Compressed argument/event traces and complete fixture receipts preserve the
  detailed identity/ownership evidence behind concise gate summaries.

All writes are subject to the 8 GB root reserve and 3 GB build budget.
CPU campaigns share the process, memory and disk budgets. Each CPU fixture output is hashed,
its receipt retained, then its scratch directory removed. Suite requests retain
state hashes and compressed metadata before deleting raw state snapshots; the selected layer-fixture steps remain
available through the exactness check (1–8, plus 97–104 for the 128-token
companion). Speed windows retain none and check every emitted token. Raw event logs are
compressed. Nothing outside this packet is cleaned.

Coordinator inputs are retained under ignored `build/`: sealed executables,
compile/link metadata, fixture inputs, target input bundle, official-draft capture
inputs, and the small authenticated target streams used to regenerate KD references. These are required
inputs rather than abandoned test scratch. `LIFETIME.md` lists the KD dependency
chain. Rebuild with `build.py`; regenerate draft captures with `capture40.py`.
The exact commands and environment are in `WINDOW.md`.

Packet40 draft captures retain verified compressed text, fixture byte hashes
and exact source/compiler/dispatch identities, then delete every owner scratch
directory. KD authenticates this archived identity and regenerates the complete
CPU reference for the actual selected K2 dispatch before either device owner.
No archived raw cache/logit fixture is required as a live build input.

Coordinator K windows may produce large transient fixture output in their
packet-local receipt directory. Outputs above 20 MB are read and SHA-256
checked against the native receipt, then removed after a durable hash-only
disposition records the native receipt hash, exact `children.json` launcher,
sealed binary identity and input dispatch hash. No gzip duplicate is created
for these bytes. Reproduction reruns that exact fixture with a fresh output
and stop descriptor; device reproduction remains coordinator-only. Small
linked fixture bytes remain available. Raw event logs still retain verified
compressed bytes. This policy applies to `output.bin` only, never to arbitrary
missing prerequisite files.
