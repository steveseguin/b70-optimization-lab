# Strict terminal rollback: proposed patch

`strict-terminal-snapshot.patch` is a prepared implementation, not applied or qualified at the time of this note. It creates `strict_snapshot.hpp` and changes `rank.hpp`. `strict_terminal_gate.py` is a new CPU-only qualification producer. No arithmetic kernels change. Admission remains failed until the applied runtime and gates pass.

The rank0 owner allocates one private device backup before its census, after-load memory record and READY reply. Its conservative real-model capacity is 319,074,840 bytes (304.29348 MiB), plus a 65,536-byte host copy of rank0's shared stream slot and small copied host metadata. Device storage uses the existing runtime-overhead/process lifetime category. It is reused across guesses and requests; there are no checkpoints or allocations at individual launch boundaries. Snapshot copies are device-to-device and tracked through CopyEngine and the Engine tail. This is substantial extra work whose speed cost is unmeasured.

Before the guessed token write or embedding/PLE preparation, the owner saves every declared target output, explicit token/position/token-history controls, inactive recurrent banks, invalid QSA tails, and the complete potentially mutable standalone workspaces. Valid QSA prefixes and active recurrent banks remain outside the write set, so illegal changes there remain visible to final-state comparison. The current QSA pool kernels may recompute existing complete pools; those writes must reproduce their prior bytes, not be covered up by restore. Full workspaces are conservative; no unproved selected-kernel prefix optimization is assumed.

The same boundary saves histories, lookup IDs, selected routing IDs, loaded-layer state, FP32 source IDs/extents and bank parity. The host layer-streaming path must have released its last layer at a half boundary, so saved metadata cannot refer to a weight allocation that a speculative half later frees. Restored FP32 source IDs are checked live. The backup also saves exactly the first 65,536 bytes of shared transport memory, which belong to rank0. Rank1's stream slot, target-verification publication, draft publication and native mailbox are never copied back.

Every rollback drains, rejects poison/sticky errors, restores the original bank selection, then restores the saved physical bytes and host metadata. This includes token input and derived cache state that the old rollback left changed. Completed and partially cancelled halves use the same image. Accepted guesses discard rollback authority without touching committed model state. There is no arithmetic retry, new token authority or error clearing.

At a resolved request dump/reset/finish boundary, only the private backup is zeroed. Saved host containers and the private shared-slot copy are retired; all live Engine model state remains unchanged. The full final inventory includes the zeroed device backup. Its receipt asserts both private device and host cleanup and labels snapshot counts/payload as telemetry. Event counters and these telemetry counters remain recorded separately from model parity. Pinned transfer staging is explicitly outside model state: the hash readback itself uses and overwrites that slab. No model buffer, history, control, inactive bank or QSA tail is omitted from final-state comparison.

`strict_terminal_gate.py` compares all plan/spare allocation hashes, complete standalone inventory and host metadata, and rank0 shared-slot bytes. It omits only the recorded scheduling event counter from equality. Both controllers run every mini-model launch boundary, including before any compute and a fully completed/swap-returned half, with retention off/on. Real-mode cases use the unchanged first seven original prompt tokens and then append one confirmed token, sampling deterministic random indices and endpoints at positions seven/eight across a QSA pool boundary. These are explicitly diagnostic short-prefix cases with complete production weights and launch plan; the full original-prompt quality gates remain separate. Original/prefix/per-owner token hashes, lengths, logs, receipts and archives are recorded. Actual CPU-only corruption of a protected active bank and a valid QSA prefix must survive rollback and be detected by the final-state comparison. The corruption command is absent from device builds.

The existing nonterminal cancellation, retention, reset, draft, sanitizer, wrapper and identity qualification must be rerun against rebuilt binaries. No performance or device result is asserted here.
