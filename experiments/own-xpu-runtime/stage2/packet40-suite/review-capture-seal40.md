# Capture and seal receipt review

This is the capture/seal implementer's follow-up source review. The independent
runtime review remains `review-p40-nonblocking-draft.json`, written by the
cancellation reviewer; its six runtime source hashes remain current.

The capture producer authenticates the immutable target input streams before
each fresh owner. GNU and Intel host owners use the same dispatch. It compares
every sample, complete vocabulary logit, cache and control file by SHA256, plus
the exact proposal sequence. Neither old acceptance distances nor old-kernel
outputs can satisfy the current gate. Historical target-token labels are used
only for the reported draft acceptance diagnostic.

Each owner archive retains exact receipt and row-log bytes and hashes every raw
fixture. The archive is verified before the scratch directory is deleted. The
second owner compares against that manifest. Pipeline agreement reads the
archived rows and final cache hashes. KD authenticates this archived input chain,
then generates its host reference using the actual selected K2 dispatch before
the two coordinator device owners. Its synthetic CPU wrapper fixtures keep a
separate raw-fixture fallback; the production seal requires the archive path.

The seal requires all 91 inherited obligations, using explicit current review
counterparts for changed reviews. An inherited executable receipt requires a
successful execution ledger binding producer dependencies, runtime sources,
binary identities, receipt bytes and compressed execution log. A copied passed
boolean does not qualify. Current additional runtime gates must bind sources or
the current executable; independent reviews bind their reviewed sources.

The full wrapper gate additionally requires its producer and eight consumer
source identities, a verified archive, all success/failure summaries, and an
unqualified CPU K2 timing result. The seal checks compile and link precision
flags, all four runtime build modes, standalone sanitizer artifacts, capture
reference identities, and the inherited deep real-suite archive/oracle checker.
Bootstrap omits only the final admission gate; final sealing binds the admission
test's consumed source and seal contract without a receipt-hash cycle.

This review does not replace pending producer execution or device gates. The
final seal remains refused until every required receipt is current. Actual
device event timing, overlap, driver behavior and host/device arithmetic parity
are coordinator work. `build_identity40.py` verifies all four current CMake
dependency graphs with one compile job, binds the source closure and generated
rope header before and after, and records every artifact and compressed build
log. A rebuild changes the artifact identity and invalidates earlier binary
gates. Standalone builds also have compile-invocation/source receipts.

The user requested equality of any state. The final terminal-EOS review found
that abandoned speculative scratch, inactive banks and uncommitted tail bytes
can differ even when tokens, committed state and reset state agree. Both
bootstrap and final sealing now refuse this unresolved scope. The pending
`state-scope-decision.json` contains no owner acceptance. Only a recorded explicit
owner message accepting that exact exception, or a fresh execution-bound proof
of terminal equality for every inventoried allocation, can release this gate.

The final producer audit checked `capture40.py` and `suite128_cpu_gate.py` without
launching a model. Capture owner failures now remain failed even when inventory
validation fails after execution; source, binary and dispatch identities are
checked across the run, and the CPU MTP lock closes deterministically. The suite
producer records every launched PID with its process start time. After any
failure it retains scratch while an owned rank still exists, instead of deleting
files beneath a child that outlived the suite's bounded cooperative drain. Setup
files are covered by the owned-directory cleanup path. Both source files passed
syntax parsing; these findings still require the separately scheduled runtime
gates, and do not authorize the pending EOS exception.

The first real capture startup then exposed an additional producer defect: it
created the output directory before calling a binary that requires the output
path not to exist. That failed owner's receipt and archive remain evidence.
`execute_owner` now writes the log beside the absent output path, lets the
binary create its own output, and moves the log into that directory only after
the CPU child has exited and been reaped. A missing receipt is an explicit
failed-owner result whose startup log is archived. The new focused CPU gate
passed three cases: actual mini capture startup (three rows and 26 fixture
files), parser rejection without a receipt and with its log preserved, and
refusal to touch an existing output directory. Every owned case scratch path
was removed after its archive was verified.
