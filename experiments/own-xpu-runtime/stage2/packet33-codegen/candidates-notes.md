# Candidate source and CPU identity scope

The candidates keep the original weight format, BF16 inputs and output rounding, multiplication argument order, lane-eight tile order and adjacent reduction tree. No floating-point compiler relaxation is used. They have not run on a device. An assembly change is a mechanism result, not a speed result.

| Candidate | Intended integer/control change | Arithmetic/shape contract |
|---|---|---|
| `p33.down.bank` | Replace 16-entry IQ4 table loads with selection among four immediate 32-bit words and byte extraction. | IQ4_NL K640; same scale-to-weight multiply, input multiply, serial lane sum and adjacent32 tree. |
| `p33.down.select` | Balanced select expression over the four code bits, no source table address. | Same as bank. Source spelling does not guarantee the compiler will avoid a table; final assembly decides. |
| `p33.gate.restrict` | Disjoint read-only pointer annotations around the unchanged packet28 private paired lane. | IQ2_S/IQ3_S K2560 paired gate/up; same decode body and order. Unchanged assembly is an allowed negative finding. |
| `p33.dense.segment` | Remove generic scale-segment loop for aligned eight-weight tiles. | Expanded Q6_K/Q8_0 K2560; starts aligned to256, end at aligned split boundary or K. All eight weights share one16/32-weight scale group. Supports split1 and split4 with original final `(p0+p1)+(p2+p3)`. |
| route rank4 | Do four rank comparisons before testing losing-rank early exit. |512 candidates/top10. Winners have the same exact rank; losers can exceed10 and must never write. Original softmax, normalization and descriptor stages remain. |
| QSA fixed shape | Make capacity128, budget2048, tokens1 compiler constants after exact shape guard. | Calls unchanged round2 score/softmax/value bodies. Other shapes retain original body. No added or removed barrier. |

`build_driver.py` derives the timing harness from packet29 using exact single-match substitutions. It retains the runtime R5 incumbent calls, full dimensions, 200 measurements, eight preflight and eight postflight iterations, eight rotated payload banks above8 MB, byte comparisons and failure recording. The generated round2 clone preserves all control/output bindings and fallback geometry. Every parallel-for capture is checked at compile time against1024 bytes.

`candidate-gates.py` compiles a CPU-only binary separately under g++ and icpx, runs each in two fresh processes, and checks exact float bits or final output bytes without NaN tolerance. `candidate-gates.json` retains per-relation counts and binary hashes. The gate uses the same frozen Core v2 snapshot adapter as packet29 for QSA on the existing1-token and3-token fixtures. Historical expected bytes stored in the3-token fixture differ from the current reference core in two probability bytes; those differences are retained explicitly under `qsa.stored-expected-diagnostic`, while current-core and unchanged-round2 comparisons are required gates.

The finite contract matches packet29. Exceptional scale/input combinations are retained as diagnostics with exact bits, and are not silently qualified. In particular, unchanged packet28 IQ expert arithmetic differs from frozen R5 on some exceptional inputs; the new restrict wrapper must still equal packet28 exactly. Down tests cover the20 half-scale patterns and16 BF16 input patterns from packet29 plus mixed inputs and odd K=1,3,17,255,639 beside640. Dense covers odd ends, actual K2560, nonzero split starts, lane bits, trees and BF16 output. Expert covers actual K2560, both projections, lane bits, trees and BF16 output. Full three-stage route tests include ties, varied logits, disabled control and NaN rejection, and compare selected IDs, probabilities, gate/down descriptors and status against the unchanged generated source.

CPU exactness does not establish GPU determinism or on-card byte identity. The prepared coordinator timing window still requires its own incumbent/candidate byte checks. All prediction and assembly acceptance decisions belong to the codegen/model tables.

The first GEN inspection showed that source table removal alone was insufficient: the bank variant removed table gathers but later tiles loaded eight BF16 words separately, and the select variant became divergent branches. `iteration1.patch` retains the exact source change from that initial candidate to explicit device vector reads of eight code bytes and eight BF16 words, with signed-byte conversion expressed as an integer extension. These loads cover precisely the original eight elements; K must be divisible by eight, otherwise the scalar guarded path remains. The arithmetic still consumes elements in the same serial order. The host scalar path remains separately gated; CPU execution cannot establish how a SYCL vector load lowers or whether its on-card result is exact. Parent assembly receipts and coordinator device checks decide those claims. `iteration1-receipt.json` preserves the initial CPU gates and source identity.
