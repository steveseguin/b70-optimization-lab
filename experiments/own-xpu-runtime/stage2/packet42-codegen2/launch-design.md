# Launch floor: prepared, not measured

T1 uses packet29 `ownrt::Device::compute`, packet29's event ownership ledger and the original SYCL backend. All allocations remain owned until their events complete. No produced native executable was invoked during CPU preparation.

The body reads BF16, adds exactly FP32 `1.f`, then rounds once to BF16 using the runtime rounding/NaN rule. It covers N = 1, 32, 640, 2560, 6400, 10240, 25600. Geometries are plain range, WG32 with one active lane per group and one element per group, WG32 with all lanes and ceil(N/32) groups, and WG256 with all lanes. A bounds check handles tails. Each is compiled both with and without SG32, unused 4 KiB local accessor, and value arguments versus a pointer to a pre-uploaded immutable parameter block. ND-range variants additionally include both barrier settings; plain range cannot legally have a work-group barrier. Thus there are 56 legal shape combinations × 7 lengths × 3 split counts = 1,176 rows.

One, two and four launches cover disjoint partitions of exactly the same N elements. For N smaller than the split count, empty partitions still launch one guarded work-item so this explicitly measures the full requested launch count. A control readback checks every output byte before timing. Each row has 200 repetitions. GPU time is the sum of event durations; wall time runs from before the first `Device::compute` until the final event wait returns, including submission and waits. Uploads, readback and event retirement lie outside the wall interval. Medians and nearest-rank p90 are reported for both metrics. No cache or response reuse is relevant to this microbenchmark; this is a diagnostic launch cost study, never a model throughput claim.

Four further rows launch 1,000 identical N=1 operations back to back, with dependency events, for each canonical geometry (SG32, no local accessor, no barrier, value arguments). Each burst is repeated 200 times. Input/output allocations are separate, so repeated writes have the same value and do not create a floating recurrence. Compare GPU-event sum / 1,000 and wall / 1,000 with the matching one-launch row to test constant per-launch cost. Total: 1,180 independently receipted rows. Estimated millions of submissions may take minutes; coordinator watchdogs must be generous. An unused accessor may vanish during compilation; the assembly metadata, not its presence in C++, decides whether the axis actually differs.

The postprocessor requires exactly the full matrix and 200 finite positive samples for every passing row. It emits the measured table and one paragraph selecting the lowest GPU median at each N, breaking exact ties by host wall. Failed cases remain rows. No cheapest-shape rule exists yet: the coordinator has not run T1. Tiny-class candidates still need their own device equality and timing gate even after the floor is measured.

Offline evidence is complete in `launch-assembly.json` and compressed `launch-assembly/`: 56 requested kernel specializations, eight additional SYCL range wrappers, and the runtime marker (65 GEN entries). Every unused local-accessor variant emits zero SLM messages and no SLM pointer argument; the compiler removes that unused allocation from the kernel interface. The source still constructs the accessor, so T1 also tests any host-side submission cost. ND barrier variants emit three barrier/fence-related assembly lines and three additional messages. Without SG32 the offline compiler still selected SIMD32 on this target, so a null measured SG effect would be consistent with identical emitted SIMD widths. Plain range has a compiler wrapper as well as its direct body; both are retained because device runtime selection determines which executes.

Representative static counts (instructions / memory messages, direct entry): plain range value 52/5 versus parameter pointer 56/6; WG32 lane-zero value 43/4 versus pointer 48/6; full-lane WG32 and WG256 value 52/5 versus pointer 56/6. Adding the barrier changes lane-zero to51/7 and full-lane to60/8. These are static whole-kernel counts, not measured latency. Cross-thread extent is8–68bytes across T1 entries, below1,024. Unused-local and SG32 source toggles do not change these counts in this offline build.
