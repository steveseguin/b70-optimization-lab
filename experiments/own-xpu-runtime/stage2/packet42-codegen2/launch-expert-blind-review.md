# Independent expert assembly review

This review started from the eight raw GEN dumps named by the coordinator, before opening the expert report or its conclusions. The instruction-count script's input hashes, explicit basic-block paths and counts are in `launch-expert-blind-counts.json`. Mapping from numeric template identities to human names was subsequently checked against the enum and dispatch source; two initial informal name assignments were reversed and are explicitly corrected in the JSON. Counts remained attached to the original hashed assembly throughout.

On the normal, finite-scale, full-input loop, the shipped paired IQ2_S kernel (Type22, entry0076) issues 392 GEN instructions and 22 memory messages per 256-column gate/up block. IQ3_S (Type21, entry0082) issues 418 and 22. One loop represents 8 weights per lane in each row, or 16 per lane / 512 scalar weights over the subgroup. The loop increments 256 and has ten trips at K2560. Reporting instructions divided by 16 and divided by 512 answers different questions: both denominators are retained; neither is a hardware throughput estimate. Exceptional half-scale conversions and invalid routes have separate paths and are not folded into this finite hot-path count.

The old down.bank (Kernel0 entry0001) second full tile has 188 instructions and seven memory messages. The old down.select (Kernel1 entry0002) has 290–306 instructions for homogeneous immediate-selection arms, 482 in the union where all four arms are represented across SIMD lanes, and 17 messages in either case. The new Kernel0's same region has 288/11; new Kernel1 has 249–265 homogeneous, 441 mixed-union, and seven messages. These are conditional region counts, not measured instruction issue traces. A single-lane CFG path must not be described as the SIMD issue count when lanes diverge. The mixed union is an explicit envelope; the real index distribution decides which arms execute.

The measured old select winner therefore cannot be explained by fewer instructions or messages: it has more under these definitions. The bank path's register-table/shuffle dependencies versus immediate select scheduling are plausible mechanisms to investigate, as are load latency overlap and register placement. Offline counts alone do not establish which is the actual limiting resource. A cycle prediction or causal bottleneck statement would overstate this evidence. The newer immediate-selection variant removes ten of the old second-tile messages while retaining the arithmetic, making it a sensible card candidate; no speed is claimed.

The new paired IQ2_S body (entry0003) visibly unrolls two adjacent 256-column blocks. The IQ3_S body (entry0004) retains one block per loop. Both preserve distinct half-scale exceptional CFG branches. The loop induction, expected block coverage and select-versus-bank distinctions can be checked directly in the retained raw dumps. Exact bytes and real event timing remain coordinator gates.
