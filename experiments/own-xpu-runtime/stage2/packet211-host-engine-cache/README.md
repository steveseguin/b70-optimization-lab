# P211: tiny Engine with indirect expert cache bindings

This is an additive, synthetic `OWN_RT_HOST_ONLY` integration over [P207](../packet207-host-paired-projections/README.md). The designated CPU proof passed: 48 completed requests across direct, serial-cache and paired-cache controls, plus one intentional partial-chunk failure. This is correctness evidence, not a performance result. The unchanged serial default remains available. The new cache modes refuse non-mini, non-pipeline, non-resident, multi-owner, legacy, draft and alternate execution paths before weights or Engine construction. No device target is built.

The actual four-layer mini Engine uses twelve expert pointer tables and a 4 KiB logical cache arena. [host_indirect.hpp](host_indirect.hpp) is a new binding adapter: it preserves the inherited HOST `Multiply` route/status loop, `arithmetic::row(..., 2)` and BF16 writes, while resolving admitted F32 rows through `p58::Pointer`. This is not the production quantized indirect operator. The independent direct operator remains the numerical control. Table extents, cross-writable aliases, F32 alignment and retained payload spans are checked. The Engine also checks retained allocation generations and committed table identities before each prepared issue.

[cache_runtime.hpp](cache_runtime.hpp) owns original banks, pinned bank mirrors, aligned cache storage, tables, staging and row/layer route logs. Cache and table allocations use process-lifetime weight categories so ordinary request reset preserves them. Every real fill includes the aligned arena offset. Tables are published with twelve completed `CopyEngine` transfers; the fixed 144-table production overlap publisher is not used.

Both `serial` and `paired` modes freeze the table and victim bytes over each two-row nonfinal prompt interval, splitting at 32-position boundaries. Serial tails, final prompt positions, decode and resumed decode use single-row intervals. Real route copies retain all twelve bytes of each gate/up route before workspace reuse. The Engine owns each copy as a tail dependency, validates and consumes helper event IDs before retiring them, then replays retained routes in row-major order. Updates use `Cache.begin_position → finish_position → prepare → fills → publication → commit`. This single-touch policy differs from the selected production overlap policy; only matched-policy serial versus paired comparisons are meaningful here.

The paired mode retains P207's actual row maps and qkv/z pair captures. Cache preparation, table installation and allocations happen before captures; changing a pointer map alone is not treated as a prepared-command rebind. All payload allocations remain alive through completion. Partial chunk or maintenance failure poisons intake, does not retry or roll back, and preserves failure evidence before runtime cleanup. Cache state is not stored in model checkpoints; output and saved model state must still match the independent direct run.

The completed [host proof](evidence/host-proof.json) used one standalone adapter process with nine small runtime owners, three comparison Engine processes (direct, serial cache, paired cache), and one intentional paired partial-chunk refusal. Four top-10 adapter cases matched the unchanged direct operator; all 27 binding, live-payload and failure controls passed. All sixteen generated sequences and thirteen checkpoints (twenty state blobs plus tokens each) matched across the three Engine controls, all thirteen retained P207 references and six historical tiny references. Each cached mode matched 108 prompt endpoint states against direct execution. Append across position 31→32, same-generation resume, final prompt and decode paths remained exact. Old-binary checkpoints were never restored. [host_probe.py](host_probe.py) owns the exact fixture and execution gate; [AUTHORITY.md](AUTHORITY.md) records inherited authority and limitations.

Each cached owner completed 181 intervals covering 281 processed positions: 500 hits, 10,740 misses, 11,007 fills (16,906,752 payload bytes) and 11,005 evictions. The complete normalized transaction records matched serial versus paired execution. The paired owner issued 400 paired projections and skipped exactly 800 original sites. These tiny-cache counts validate actual populated-cache consumption and churn; they do not estimate production reuse or speed.

Ten parser refusals ran before owner construction. The intentional partial chunk retained an active, poisoned cache receipt, emitted no successful request/chunk/checkpoint, refused further intake and exited 1 after safe cleanup. All three comparison processes exited 0; no incident signal, retained owner or retry was needed. The standalone malformed-pointer cases separately recorded failed-but-drained runtime owners. [Eleven read-only authority tests](evidence/authority-tests.json) passed against the retained results.

The complete 1,709-file, 28,367,578-byte raw proof is retained in the [2,008,263-byte archive](evidence/raw-host-proof.tar.gz) with a [full member index](evidence/raw-host-proof-index.json) and verified readback; original scratch files remain local. Both compile attempts are preserved: [first compile](evidence/build-1792800987758056692/receipt.json), then [final compile](evidence/build-1792801059411629341/receipt.json) adding the serial frozen-interval state-observation boundary. Both compiled successfully; only the final binary was executed. The [source delta](evidence/integration-delta.patch), [plan](evidence/host-plan.json), [console log](evidence/host-proof-run.log) and [build closure](evidence/build-compile-only.json) bind the tested implementation.

Build with the repository's compile-turn lock, nice 19, helper cores 8–15/24–31, two CPU threads and 4 GiB address-space bound. [build_engine.py](build_engine.py) compiles only the new HOST entry, links pinned inherited GNU objects, preserves per-attempt generated sources/logs and verifies compiler dependency hashes. `build/` stays ignored. The existing `Host` backend executes real CPU arithmetic and copies with simulated queue/context/event markers; this is not native-device synchronization, cache speed, production arithmetic or throughput qualification.
