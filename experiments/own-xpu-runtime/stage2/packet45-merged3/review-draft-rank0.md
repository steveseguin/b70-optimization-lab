# Independent draft placement review

This source review checks pipeline ownership and timing. It ran no device binary or device discovery. CPU mock wrapper tests are separate from model-state gates; device races, physical residency, exactness and speed remain unqualified until coordinator windows.

The reverse stream region is appended after the existing forward slots and controller metadata. Rank1 copies streams immediately after its final layer combine, before head/argmax enqueue, then release-publishes position+1. Rank0 acquire-checks that marker against the draft input position, checks the target-only confirmation when generation has begun, uploads into private merge.hidden, and drains that upload before the next rank1 half can overwrite the source. The forward stream buffers never become draft input or scratch.

Rank1's target head alone chooses emitted tokens. The controller invokes draft with the known prompt token during prefill or the confirmed target output during generation. A draft token can only propose rank0's next half. Its token, position and publication sequence must match before use. Exactly one guess is outstanding. Rank1 never executes a guessed half.

The local native HALF reply is consumed before a DRAFT reply can replace it. Only HALF changes stream_bytes; DRAFT cannot destroy the pending forward payload. The accepted candidate is distinct from the pending command reply. Draft-private allocations are created after SpeculativeImage inventories target allocations, so restoring a wrong target half cannot rewind a confirmed draft cache. Target and draft allocations are checked for mutable aliasing. Quiescent request reset resets both allocations and the whole enlarged shared mapping.

A wrong guess preserves packet40 cancellation at every actual compute launch and tracks every submitted event. The owner drains its submitted prefix, restores target state and shared rank0 output, then recomputes from the confirmed token. Draft state follows confirmed inputs, so it survives target rollback. Terminal EOS rolls back an abandoned speculative half and starts no new draft. ProviderError disables drafting and yields no guess; owner/device failure remains fatal.

Findings corrected during review:

- Starting rank0 draft before speculative accept made image.accept drain the new draft, serializing every hit before rank1's next half. The controller now accepts a confirmed hit before issuing draft and avoids a second accept. Miss restoration remains serialized with already queued rank0 work.
- Reading backend.sent[0] at the next cycle misreported draft start after ACCEPT/redo overwrote that slot. Native code now saves issued_draft_at at issuance and records placement-neutral draft fields.
- The draft memory receipt previously equated resident mode with shared-head ownership. It now checks actual target output.weight ownership; rank0's second head is separate.
- Suite fixture collection assumed boundary24. It now requires exactly one actual owning rank for each retained layer, covering boundary22 without weakening missing/duplicate detection.

This is an estimate from aggregate measurements, not measured per-layer balance; transfer, host and miss costs are excluded. New device windows must decide actual balance.
