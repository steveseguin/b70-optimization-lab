# Retention and restoration

Retain copied packet75 engine sources, exact parent hashes, selection/coverage,
raw-attribution census, changed-source patch, serial build commands, CPU receipts,
full-shape memory summaries, wrapper pins, seals and proposed queue plans in Git.
No model payload or derived Q4 weight copy is committed. The Q4 copy is generated
at model startup and owned by the draft allocation lifetime.

Ignored build products and miniature snapshots stay local. Rebuild with the
entry points in README, under the same pinned packet75 source/object identities.
The incremental linker reuses hash-verified packet75 objects; see
`evidence/object-identity.json`. All source copies are independent of the frozen
parent. Hardlinked inherited object bytes must never be edited in place.
This research screen depends on those local build objects and is not a public
reproduction package. A new build identity requires new seals and fresh outputs.

The task caps build storage at1GB and each CPU process at8GiB. At preparation,
the generic50GiB free reserve refused with about19GiB free; the explicitly bounded
task build budget was used and recorded, without deleting anyone else's files.
The first build receipt is retained as superseded: the rebuild corrected only
prefix provenance and head-sharing report metadata before any device use.

`rope.bf16` is a4MiB existing model-independent rotary-position constant table,
not model weights or a cache. The engine requires it beside its source-relative
root and verifies its fixed hash. This independent packet copy is byte-identical
to packet75's table and can be restored from that pinned file. Git deduplicates
its unchanged content; retaining it closes the runtime's local constant dependency.
