# Host submission path

The packet18 kernel arithmetic is unchanged for default dispatch. The resident plan resolves non-GEMV Specs and allocation IDs, GEMV Matrix descriptors and immutable weight bindings before token generation. The owner resolves allocation IDs to raw pointers on their first use and retains those immutable binding sets; releasing any allocation invalidates that owner's binding cache. Layer-streamed weights continue to take the checked changing-binding path. Arena row lookup uses the sorted allocation handles instead of a linear scan.

The owner reserves its event ledger and uses stack dependency storage. It validates owned dependencies using sorted handles; queue identity uses a generation-tagged bounded ring. Each returned event enters the owner's ledger before any subsequent registry operation can throw. Events are retired in bulk only after queue completion. The shared two-card backend uses the proven ordered allocation containment lookup and one reserved vector of native event records. It validates each dependency's target card, then omits explicit same-card native dependencies because both queues are in-order. Every inherited card-transition and peer-copy host fence remains present.

`--timing token` creates queues without profiling enabled and makes no event profiling queries. `launch` and `class` profile individual event execution durations; class totals sum those durations instead of including gaps between events. Each token reports prepare time, enqueue-loop time excluding nested waits, enqueue time including waits, and total wait time. `--seconds` is the overall cooperative deadline; `--wait-seconds` (default 60) bounds a drain wait; the four-second per-event GPU budget is checked only when profiling is enabled. Token timing declares that per-event budget unmeasured.

The CPU-only benchmark compiles one identical no-op submission workload against packet18 and packet26 owners: 3,000 allocations, 2,181 submissions, 19 bindings per submission, three setup iterations and nine recorded iterations. [The receipt](host-issue-benchmark.json) records medians, p90, every sample, source hashes and binary hashes. It isolates owner bookkeeping, excluding SYCL, device execution and Engine plan work; it cannot establish device speed or predict W2. The same 12 ms enqueue-loop target must still be proved by the coordinator's W2 card run.

Every token also reports host-to-device, device-to-host, peer and local-device copy counts per card. Kernel-parameter uploads remain zero per launch. The unchanged packet18 schedule contains diagnostic snapshot copies, lookup uploads and peer control copies; these are counted explicitly and are not concealed as parameter uploads. The inherited all-copy <=2/card/token target is not met by this schedule.

Synchronous errors write failure text and a failure receipt before teardown. A refused teardown parks only when its owner reports outstanding work. A failed but drained backend can be retained until process exit and is reported as failure; it cannot turn into a successful run.

Reproduce the bookkeeping comparison with `nice -n 19 ionice -c 3 env OMP_NUM_THREADS=2 python -B experiments/own-xpu-runtime/stage2/packet26-specialised/host_benchmark.py`. It writes a new ignored build receipt and does not overwrite the retained result.
