## Three release blockers

1. Both actual native CPU-preparation probes refuse `--lookups resident`.
   The existing build contains packet58ah's mapped lookups, while the new
   brief requires packet58aj's resident line in both controls and candidate.
   A native source port, build and requalification are necessary; this task
   forbids compilation. The failed probes read no model or device files.
2. Both temporary-copy lanequeue plans refuse immutable-pin admission.
   Copied historical metadata under `vendor/` and the inherited host-admission
   bundle still contain mutable parent paths. The source snapshots are retained;
   those manifests need a proper private dependency closure and refreshed seals.
   No allowlist or shared pin guard was changed.
3. Both shared `rehearse_entry.py --report` invocations run a synthetic
   single-view smoke adapter that requires 12 requests. This preregistered
   smoke has two views and 24 requests. Its real report returns 24 and is
   rejected at the checker's line 1219. The 60-request bracket report passes.
   Extending the shared adapter is outside the frozen `ops/*` scope.

Do not flip readiness or enqueue either job until all three are repaired and
all checks are rerun. The old build/seal/readiness are preserved under
`lineage/p58amc-before/`; they do not certify the new proposals. Full device
exactness, overlap, overhead, actual smoke storage and speed remain pending.
