# CPU preparation corrections

The private preparation path initially needed an explicit no-device entry
and complete captured demand bindings; those are covered by the final real
argv probe. Production arithmetic proofs use the actual generated partition
kernels and the original unpartitioned arithmetic in the same fixture.

A final byte-proof receipt edit used the namespace name `p58am_down.hpp`
instead of the actual file `p100_down.hpp`. All four byte executions passed,
but writing that receipt failed. The path was corrected and the full gate
was rerun. This was a CPU receipt failure, not a device or arithmetic result.

The retained parent's four-second submission field was also removed as a
data-proof limit. New receipts explicitly record a null limit and no enforced
submission data deadline. Profiling labels include smoke's demand diagnostics;
the boundary reports the configured context capacity rather than labeling it
as the dynamically prepared attention extent. No device was run to test these
changes, and no performance claim follows from them.

The staged whitespace check reports four pre-existing trailing-space lines in
the retained `p109_route.hpp` copies and `p49d_route.hpp`. Their private and
original hashes are intentionally preserved. Newly authored files pass the
whitespace check; those four copied lines are not a build or runtime failure.
