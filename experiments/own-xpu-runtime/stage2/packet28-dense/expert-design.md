# Routed expert source review and design

Source inputs: packet8 `decode.hpp` (`decode8`/`dot`), packet9 `kernels.cpp` (`Projection::run`), packet2 `kernels/math.hpp` (`decode`/`element`), and the normative format tables in packet2 `kernels/grids.hpp`. Normative tables retain their existing ggml/llama.cpp contributor credit and FORMAT-DATA-LICENSE.txt; the kernel implementation is original lab code.

Counts below are source operations normalized per output weight, not GPU instruction counts. The existing compiler may eliminate redundant source work. An eight-weight lane tile reads one scale group; block groups are 16 for IQ2 and 32 for IQ3/IQ4. IQ2/3 blocks have 256 weights. In a 640-column IQ4 row, tile 512 has lanes 0–15 active, all with eight weights; inactive lanes use block 512 to participate in broadcasts safely.

For IQ2/3, the old scale-NaN condition is evaluated once per weight plus a block-inf condition per lane tile. New classification is once per tile (two integer predicates), with separate finite and exceptional loops. Exceptional values use `(scale*float(magnitude))*float(sign)` in the original order. This is an algebraic spelling match, not a promise of NaN payload selection across compilers. Shared variants preserve the original broadcast group owners; private variants remove 2/8 broadcasts per IQ2/IQ3_S weight and 3/8 per IQ3_XXS weight, at the expense of private metadata loads.

IQ4 current already reads/decodes the half scale once per lane tile through a subgroup owner. Thus this proposal does **not** claim to remove eight half conversions there. It tests eliminating broadcast/decode scaffolding and constant integer-table traffic. Both private and shared variants need card timing. The bounding result 71.2 us is a hypothesis anchor versus the in-model 130 us, not a measurement of this implementation. The coordinator subsequently added a grid-layout stand-in receipt while this packet was prepared: byte-grid128.0us (one row) and130.7us (four rows). Use128–131us only as a hypothesis anchor; it is not actual GGUF layout or a packet28 measurement and may lose. Theuint64/byte choice alone is not the saving: the uint64 stand-in also took126–127us.

The paired path computes both lane sums independently and converts each x once (1/2 input reads/conversions per output weight versus 1). It never combines the sums, changes accumulation order, or shares their final BF16 rounding. The enclosing kernel must independently apply the adjacent SG32 reduction tree, any split4 tree, then BF16 conversion to each output.

The constexpr byte-table transformation shifts original normative words during compilation only. Runtime accessors return individual bytes; none loads or shifts a 64-bit grid word. Pointer addressing remains native-width, as required by the platform ABI.

CPU fixtures compare the candidate to packet8 current and packet2 original scalar element values using the v2 eight-weight lane order. Cases cover odd rows 1/3/5, K=32/64/256/512/640/672/768/2560 as valid per format, split1/split4 including empty split ranges, upgraded format fixtures, both activation encodings, half-scale signed zero/subnormal/normal/max finite/inf/NaN, and signed-zero/subnormal/inf/NaN inputs. Exact non-NaN bits and BF16 bits are required. NaN payload differences are counted separately: host compilers may choose different source NaNs in a sum with multiple NaN operands. This must not silently pass the device admission test: G2 requires candidate/current device bytes equal and only relaxes current/reference comparisons for NaNs.
