# Packet 28 harness implementation

`g2.cpp` is one host/native entry. The host build has no SYCL entry or library.
The native build is prepared only: it has not been run by packet 28 preparation.

The registry contains 34 production workload identities and 78 candidate
entries. It includes F32 `hc.a.inject`, `hc.f.inject`, `router`, `gdn.a`,
`gdn.b`, and `shared_gate`, plus BF16 `qsa.iq`/`qsa.ik`. These are raw
weight paths, not expanded Q6/Q8. `final.low`/`final.gate` and both attention
projection families are registered separately under the runtime labels.
`ple.key` and `ple.value` are GEMVs; `ple.conv` is a convolution operation.
The input plan places QSA q_proj at 512 rows and k_proj at 128 rows.

The control submission calls the linked packet26 `integrated::dense` or
`integrated::experts` function unchanged. R5 arithmetic selection occurs using
the original model geometry before CPU fixtures reduce the row count.
`current_kernel` names the dispatched path on every baseline/timing row.
A timing discrepancy with the in-model result must block measured dispatch
admission; invoking the right source function alone does not prove comparable
timing. `summary.py` owns that decision.

`--validate` uses fake aligned CPU allocations carrying the true extents. It
executes the extracted native baseline validation and shared candidate
validation for all workload/candidate entries, plus seven malformed candidate
arguments per entry. It performs no accelerator discovery and no math timing.
`--cpu-fixtures` executes nine-row fixtures with the original R5 variant;
family CPU gates separately cover boundary dimensions and per-lane arithmetic.
Output hashes record actual BF16 bytes, allowing same-compiler fresh-process
comparisons. CPU comparison permits both-NaN equivalence and records whether
bytes were also equal; native G2 requires exact new/current bytes, including
NaN encodings.

Native K0 builds all linked kernel IDs into an executable bundle on the selected
card. It creates no queue and submits no kernel. Its receipt explicitly says
`kernel_execution: false`. It is still a device program and must only be run
through the authorized window by the device owner.

Native G2 first tests five data modes for each workload: varied finite values,
signed zero input, tiny/denormal scales and input, exceptional scales and input,
and finite extremes. Routed experts additionally test invalid expert IDs,
out-of-range row starts/counts, empty routes, and shifted short routes. Every
baseline/candidate correctness launch has output/status buffers poisoned first,
and every routed status output is checked. The seventeen-row weight seed period
is coprime to the production expert row counts so a wrong expert bank produces
different output. Ten distinct dispersed expert IDs are used in timing.

Weights use actual packed formats, with expanded Q6/Q8 bytes generated by the
existing expansion helper. GPU storage is tiled from a pinned staging slab of
roughly 4 MiB. No full host weight replica is created. The largest device weight
fixture is the roughly 795 MB logits matrix. Host references evaluate the seed
rows and reproduce their known tiling. Allocations and events remain owned until
completion and explicit retirement.

After all fixture modes pass, the control runs first for 200 repetitions,
followed by each surviving candidate for 200 repetitions. Copies occur during
fixture setup and correctness checks only, never in the timed repetition loop.
`timing.jsonl` records each GPU event separately with `event_index` and
`event_count`; the summary sums the full launch group per repetition before
computing median/p90. Four-row split4 candidates use 16 SG32 groups (WG512) and
local reduction in one event. Single-SG split4 candidates preserve the four
contiguous partitions through a scratch event plus a second final-tree event;
both execution durations count. Non-split WG32 is one event.

A candidate mismatch or argument rejection is written immediately and excludes
that candidate while the rest continue. Failed timing admission is recorded as
`phase: timing`; partial timings cannot qualify. Infrastructure/device failures
write the failure snapshot before owner teardown. Success is an explicit return
and requires zero live bytes, zero in-flight events, and a safe shutdown receipt.
The 300-second per-submission timeout includes compilation allowance; the outer
window handles its longer watchdog and two fresh owners.
