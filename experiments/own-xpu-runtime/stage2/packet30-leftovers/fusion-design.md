# Combine, norm and mix kernels

The runtime combine is elementwise: each of 10240 values evaluates its stream's inject sigmoid, combines branch and stream, then rounds to BF16. About 11 us includes launch overhead, repeated sigmoid work, reads and writes. Mix is 2560 independent outputs, each evaluating four sigmoids and the ordered four-term sum (about 8.5 us). Norm squares 2560 values for each of four streams and performs the adjacent reduction, reciprocal square root, gain and BF16 store (about 7.6 us in the supplied class account). These are whole-kernel measurements, not separately measured fixed overheads. Packet26/27 specialised norm uses two launches: 320 subtree work items followed by 2560 four-output items; each final item recomputes the upper 80-partial tree. The actual G3 incumbent must preserve whichever runtime path was selected and reject an unrepresentative baseline.

`combine_norm` combines the adjacent combine and next HC norm in one specialised launch. Both intermediate combined BF16 output and final normed BF16 output are retained. The formula first applies `Args::bf(stream + branch * (2 * sigmoid(inject / 4)))`; only then is it squared for norm. The output gain expression and final BF16 conversion are unchanged. This preserves the downstream consumers of the intermediate stream.

The sg32 candidate launches four workgroups, one SG per stream. The tiled candidate launches 40 WG32 at width2560, one per (stream,256-output block), independently recomputing the complete reduction to trade work for occupancy. Both have no local memory and no WG barriers. Each aligned 32-leaf block computes original reduction levels 1–5; lane0 computes upper nodes over the 80 block roots with the original odd-right-child `+0` rule. Widths below32 stop at their original tree height. Tiled stores are disjoint; its extra work never reads newly written intermediate buffers.

Standalone norm uses the same two placements and exact tree. Standalone mix provides WG32/WG128 placement and has one item per output, the same four sigmoid products accumulated in head order, followed by division by four and BF16 rounding. There are no padded items at width2560; odd CPU fixtures cover partial groups.

Hypotheses only: combine+norm 10–25 us per fused group versus the actual incumbent sum; norm 5–15 us; mix 5–12 us. SG32 norm may lose badly with only four resident groups, and tiled reduction repeats are intentionally screened rather than presumed faster.

There is no combine+norm+mix claim. Between norm and mix, the real schedule produces low, rounds it, applies activation, and computes gate. Mix cannot consume that future gate in the same independent launch. The admitted adjacent fusion is combine+norm; both standalone norm and mix candidates address the remaining steps. No gate, activation or rounding point is skipped.

`fusion.hpp` exposes `Fixture(shape)`, `validate(shape,args,sizes,variant)`, `cpu`, and the event-returning `submit`. Shapes are one token, four heads, width1..2560; flags0/1/8/9; position/active/error follow runtime slots15/17/18. Device error writes are atomic. Host validation rejects overlapping outputs before submission. CPU gates compare candidate bytes to both `ng::cpu` and the runtime's `specialised::cpu`, with 768 combinations of op, flags, widths1/3/17/31/32/33/255/2560, positions1/3/87/255 and placements, in both compilers and fresh repeats.

Dispatch vocabulary: classes hc.a.norm/hc.f.norm -> a measured norm candidate; existing HC mix class labels -> measured mix candidate; fusions attn.combine+norm and ffn.combine+norm -> measured combine_norm candidate. Never count both the fused group saving and its removed standalone norm saving. Only a G3 row with representative incumbent and byte equality can supply such a dispatch recommendation.
