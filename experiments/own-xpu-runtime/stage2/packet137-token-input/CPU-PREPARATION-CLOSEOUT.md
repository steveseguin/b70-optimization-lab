# Packet137 CPU preparation closeout

## Question and identity

Can packet135 lever2 remove repeated draft projection and target token setup
without changing arithmetic, proposals or rollback? The prepared runtime copies
packet136 bundle8 (`3dfcff0ca`) and fixes banked rollback in every view.
`token_input` alone selects original, draft_table, target_buffers or both.
The model remains the `iq3-p49-split32-v1` line. See [preregistration](PREREGISTRATION.md)
and [parent identity](parent136-binding.json).

## Outcome

The CPU numerical, launch, queue and final qualification gates pass.
Device quality and speed are pending. CPU
preparation does not promote a result or change the existing record.
The planned next checks are the lane-B 12 × 64 both smoke, the lane-B
one-load original/both/original/both/original bracket, and the unqueued
lane-A bracket. Coordinator admission and the exact smoke remain required.

## What worked

All 248,320 draft rows match byte for byte under GNU and Intel. The read-only
1,271,398,400-byte table is streamed to disk and selected by SHA-256.
One pinned 5,120-byte row replaces the raw upload into the existing private
projection buffer. Rank0 keeps warm lookups and uses fixed buffers and
pre-resolved quant-block descriptors. All half-scale bit patterns, signed
PLE history, EOS and host/device rollback pass their CPU checks.

Four fresh 491-case state runs have identical transcripts. The miniature
native IPC replay preserves draft proposals, tokens and state across both
compilers and fresh bracket repeats. Boundary reset preserves the old bank
roles until the completed request is retained, then canonicalizes all six
captures without new allocations. The bank reserve replaces equal backup
bytes, so device arena size does not increase.

## What failed or remains uncertain

The initial Intel pilot needed the OpenMP runtime rpath. The unchanged legacy
K2 numerical fixture exceeded the mandatory 4 GiB cap; its failure remains
retained, and its exact frozen startup archive and binary hashes are reused.
Its real argument and measurement-validator replay checks still execute.
An oracle subprocess intercepted by the launch test is now explicitly allowed
only under its exact original command; native launches remain intercepted.
The frozen queue test mixed scratch output accounting with an older 1.811 GB
build. A local copy checks packet137's actual build and uses scratch for both
queue storage roots. No historical tree or budget was changed.

Device sample equality, target output, proposal/acceptance identity and speed
are not measured here. The 128-token bracket is screening evidence; it cannot
stand in for the realistic 512-token final gate or fresh-device determinism.
