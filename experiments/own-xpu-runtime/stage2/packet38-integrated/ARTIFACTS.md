# Evidence and scratch retention

This packet owns only this directory. Device programs are compiled but never
executed during CPU preparation. `build-receipt.json` and its named gate receipts
are the qualification authority; older attempts are historical evidence.

The resumed session found empty receipts in an interrupted mini-model run.
`resume-integrity-initial.json` records that scan (two `.json` directories were
also reported by the initial recursive scan; those are intentional rejection
fixtures, not corrupt JSON files). `resume-input-integrity.json` records renewed
verification of 5,544 input hashes, including official shard and tensor bytes,
captured target streams, and existing draft fixtures. Final binaries and gates
are rebuilt or rerun before sealing.

Large artifacts are intentional and reviewed for retention:

- `official-tensors.json` retains the authenticated official draft tensor ranges
  and hashes required to reproduce the load manifest. Regenerate with
  `prepare_mtp.py` against the pinned publisher shards; it contains no weights.
- `p33-candidate-gates.json` retains every operator identity case. Regenerate
  with `p33_candidate_gates.py`; do not reduce it to an unbound pass boolean.
- `evidence/resume-stale-scratch.tar.gz` preserves the exact text files from the
  interrupted session, including failures. Its companion
  `resume-stale-scratch-index.json.gz` retains every original file hash. Each
  archived member was read back and its hash checked before scratch deletion.
  Extract with Python `tarfile` to a packet-local scratch directory. Nontext
  fixture/state files are regenerable scratch, deliberately not in the archive.
- `evidence/resume-stale-fixtures.json.gz` retains old fixture receipts and every
  file hash before the three stale fixture trees were removed.
- `evidence/scratch-*.json.gz` keeps test text and original byte hashes before
  deleting raw CPU scratch. Decode with Python `gzip` and `json`; each text
  entry has its exact original string. Raw states are regenerated by the named
  source-bound CPU gate, not restored from a claimed backup.
- `evidence/scratch-*.jsonl.gz` uses the bounded-memory
  `packet38.scratch-stream.v1` format: file records with sizes/hashes and
  base64 chunk records for retained text or nested compressed evidence.
  `storage.archive_files` reads back and hashes every retained member before
  deletion. `seal.archived_run` verifies and reconstructs it for final checks.
  Real-controller archives can exceed 10 MB because every target allocation,
  token/guess event, and retained fixture is needed to compare both controllers.
  They are deliberate qualification evidence, not disposable build output.
- Compressed argument/event traces and complete fixture receipts preserve the
  detailed identity/ownership evidence behind concise gate summaries.

All writes are subject to the resumed 8 GB root reserve and 3 GB build budget.
Only one timestamped fixture tree may exist. Each CPU fixture output is hashed,
its receipt retained, then its scratch directory removed. Suite requests retain
state hashes and compressed metadata before deleting raw state snapshots; eight
layer-fixture steps remain available to the oracle checker. Raw event logs are
compressed. Nothing outside this packet is cleaned.

Coordinator inputs are retained under ignored `build/`: sealed executables,
compile/link metadata, fixture inputs, target input bundle, official-draft capture
inputs, and the current draft capture outputs consumed by KD. These are required
inputs rather than abandoned test scratch. `LIFETIME.md` lists the KD dependency
chain. Rebuild with `build.py`; regenerate draft captures with `capture_cpu.py`.
The exact commands and environment are in `WINDOW.md`.

Cleanup archives finished capture timing/progress/site logs before removing
their raw files. Draft-row reference tables become `draft-rows.jsonl.gz`, with
an exact decompression check and both hashes in `scratch-cleanup.json`.
`pipeline_draft_agreement.py` accepts either raw or compressed rows. The small
deterministic `draft-capture.jsonl` token table remains a comparison input;
the BF16/cache fixtures required by KD remain byte-for-byte intact.
