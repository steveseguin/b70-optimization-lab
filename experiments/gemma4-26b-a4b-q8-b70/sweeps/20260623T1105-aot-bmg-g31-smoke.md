Date: 2026-06-23

## Hypothesis

Ahead-of-time SYCL compilation for the actual B70 device target may reduce JIT
or kernel-dispatch overhead versus the generic SYCL build and improve the
current sustained-decode record.

## Build Notes

The first attempted CMake value was `GGML_SYCL_DEVICE_ARCH=intel_gpu_bmg_g31`.
That failed at the SYCL link because this oneAPI `ocloc` accepts target names
such as `bmg-g31`, not the underscore `intel_gpu_bmg_g31` spelling:

```text
Could not determine device target: intel_gpu_bmg_g31.
Error: Cannot get HW Info for device intel_gpu_bmg_g31.
```

`ocloc ids bmg-g31` maps to local hardware IP `20.2.0`, which matches the B70s
reported by `sycl-ls`. A second build succeeded with:

```bash
GGML_SYCL_DEVICE_ARCH=bmg-g31 \
BUILD_DIR=/home/steve/src/llama.cpp/build-sycl-b70-aot-bmg-g31 \
JOBS=24 scripts/build-llama-cpp-sycl-b70.sh
```

Build artifact tested:

```text
/home/steve/src/llama.cpp/build-sycl-b70-aot-bmg-g31/bin/llama-server
```

Note: the AOT binary requires oneAPI runtime library setup when invoked
directly. The standard launcher sources `/opt/intel/oneapi/setvars.sh`, so the
benchmark path is valid.
