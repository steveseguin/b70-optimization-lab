## Fresh-Response Validity Rule

Only row 0 of a no-cache benchmark can be used as a headline unless every row is
a distinct fresh prompt with no usable prior generated continuation. Repeated
prompt warmed/history throughput, n-gram continuation learning, prefix/cache
reuse, response reuse, and averaged repeated-output speedups are not valid
fresh-response headline numbers.

For this lane, every candidate must record:

- canary pass count;
- first measured row `tok_s_after_ttft`;
- first measured row wall throughput and TTFT;
- `cached_tokens` from the benchmark response usage;
- output SHA and whether it matches or intentionally differs from the Q8
  reference style;
- exact target and draft GGUF file paths and checksums;
- clear quality label: Q8 target, Q8 target with lower-precision draft, or QAT
  target.

## Operational Note: One GPU Per Replica

For this QAT lane, each run is pinned with `ONEAPI_DEVICE_SELECTOR=level_zero:N`.
After that selector is applied, llama.cpp sees the selected physical GPU as
`SYCL0`. Therefore replica runs on physical GPU 1/2/3 must still use:

```text
LLAMA_DEVICES=SYCL0
--spec-draft-device SYCL0
```

Using `SYCL1`, `SYCL2`, or `SYCL3` inside the filtered process produced
`invalid device` failures.
