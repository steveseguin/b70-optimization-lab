1. **P2 — Switching replica → control can permanently skip a clip.** Collection uses the **current** request’s `index - depth`. After replica request `k` emits `k−2`, switching to control at `k+1` emits `k`, leaving `k−1` stranded. There is no transition drain. The runner’s separate index ranges avoid this particular case, but per-request placement switching does not. See [ltx_pipeline.py:292](/home/steve/llm-optimizations/experiments/ltx25-b70/scripts/ltx_pipeline.py:292) and [prepare-graph-capture-runtime.py:865](/home/steve/llm-optimizations/experiments/ltx25-b70/scripts/prepare-graph-capture-runtime.py:865).

2. **P2 — Failed probes can retain both unqualified replicas.** `_REPLICAS` is populated before decoding the fixtures. A mismatch, post-probe insufficient-memory verdict, or decode exception leaves those allocations resident. The runner then runs control, including after an insufficient-memory result. Thus “replica rejected” does not restore control’s memory headroom; control can subsequently fail instead of reaching the intended clean stop. See [pipeline_decode_node.py:547](/home/steve/llm-optimizations/experiments/ltx25-b70/scripts/pipeline_decode_node.py:547), [pipeline_decode_node.py:568](/home/steve/llm-optimizations/experiments/ltx25-b70/scripts/pipeline_decode_node.py:568), and [run-campaign-91.sh:194](/home/steve/llm-optimizations/experiments/ltx25-b70/scripts/run-campaign-91.sh:194).
