# Compiler screen 03: remaining activation boundaries

Source-only audit, 2026-09-14. The failed native-RMS screen still differs from eager: parent campaign reports 54 video bytes (same expected and actual hashes as screen 02), while audio differences fell from 5,923 to 10 bytes. These output measurements do not locate the first divergence.

The emitted server-04 wrapper contains **15 actual `torch.ops.ltx_exact_rms.native.default` calls**. Its SHA256 is `6e1474734e379c65aae34a54d7b2cddff5e4b32c0fe6c868cf62bc762a9344db`. The [source census](../data/compiler-screen-03-activation-source-audit.json) pins both wrappers and the actual pre-rewrite FX graph, records all RMS call sites and eight activation sites, and preserves short generated function excerpts. No Torch import, native execution, server action, or source modification was performed.

The remaining three sigmoid and two GELU generated kernel bodies are exactly AST-identical to server-03 counterparts after normalizing only the function name and removing decorators. The comparison retains arithmetic, constants, casts, arguments, indexing and stores. This demonstrates that these activation implementations remain unchanged across the failed compiler candidates; it does not prove they are responsible.

The six sigmoid sites belong to video self/text attention, audio self/text attention, audio-to-video and video-to-audio attention respectively. Strides are `[2048,32,1]` and `[832,32,1]`. GELU strides are `[1048576,16384,1]` and `[212992,8192,1]`. The process-visible device is `xpu:1`; these are emitted first-stage shapes, not a claim about completed second-stage compilation.

In original `comfy/ldm/lightricks/model.py`, line 499 invokes native `torch.sigmoid`, then multiplies by 2 before gating attention. Line 311 invokes `torch.nn.functional.gelu(..., approximate="tanh")`. The emitted sigmoid kernels use `tl.sigmoid` and BF16 round trips (wrapper lines 698–721, 832–855, 1457–1480). GELU uses a float32 polynomial, `libdevice.tanh`, and final BF16 cast (1750–1774 and 1888–1912). Native eager and generated transcendental implementations need not produce identical rounded outputs. This is a source-backed hypothesis, not a measured operator discrepancy.

The concrete next candidate is a private FX rewrite preserving **these eight native activation calls**, alongside the existing 15 native RMS calls and unchanged compiler OPTIONS. Use separate opaque custom ops calling saved `torch.sigmoid` and saved `torch.nn.functional.gelu` with the original `approximate='tanh'`; validate target identity, one tensor argument, supported keyword, BF16 dtype and contiguous layout before replacement. The fake result should be a fresh contiguous tensor of identical shape/dtype/device, with no aliases or mutation. No weight or parameter copies are needed. Preserve the external `2 * sigmoid`, gate multiplication and all surrounding operations, rather than changing their expression order. Reject unexpected targets, counts or GELU approximation rather than silently substituting behavior.

Before a native campaign, require the focused CPU operator and tiny-block exact gates plus emitted-graph census of 15 RMS, six sigmoid and two GELU native calls. Native qualification must still pass bitwise eager/candidate/repeat equality for both block outputs, both stage shapes and the existing clip/lifecycle gates. If it fails, the minimal useful intermediate boundaries are preactivation input and native activation result at the first affected attention gate or FF module; capture input/output before buffer reuse and require any instrumented replay to reproduce the existing failed output hash. Adding opaque boundaries changes compiler scheduling, so even a future pass would establish candidate parity, not by itself prove the original first-divergence location. There is no speed or full-clip parity claim here.
