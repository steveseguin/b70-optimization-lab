2026-09-14. The first ten clips passed all four original raw comparisons, including five host-table clips. Request11 began the return to control but did not finish component node420. The kernel globally OOM-killed server116013 at18:12:58UTC; the saved kernel records a BCS page fault/reset at18:13:01, after the kill. The structured [audit receipt](../data/host-embedding-transition-memory-audit-01.json) binds the source/evidence hashes and compact memory snapshots. ## Concrete peak mechanism

In packet11 `scripts/host_embedding_resident_node.py`, the transition first runs `clip._host_embedding.detach_restore(clip)` and saves its receipt. It next calls `comfy.model_management.unload_all_models()`. Only after that returns does it clear `_components`, delete local `clip`, collect garbage and start constructing replacements. Thus the retired full encoder and every old nonencoder component remain strongly owned throughout bulk offload.

The exact native path is `unload_all_models` (model_management2098) → ascending indexed devices (215) → `free_memory(1e30, device)` (879) → `LoadedModel.model_unload` (821) → `ModelPatcher.detach(True)` (1375) → `unpatch_model(offload_device)` (1194) → `self.model.to(cpu)` (1219). This is a preserving device-to-host copy, not disposal of obsolete weights. Its free-memory test protects device capacity, not the host destination of all these copies.

The host encoder contributes24,218,316,900B (22.555GiB) of newly CPU-resident eligible state before this call. The original diffusion primary partition is21,127,647,680B (19.677GiB), the secondary20,880,443,520B; both were fully loaded in the host arm. Merely retaining restored encoder plus copying the full primary adds42.232GiB, exceeding the36.508GiB available at request start before secondary or other staging. This is a source-backed mechanism consistent with the observed RSS rise and OOM. Memory reclamation, existing backing and copy progress prevent treating this arithmetic as a measured exact peak.

Layer sharding does not duplicate registered weights: primary owns `_ltx_primary_blocks`, secondary owns its `ModuleList`, while `diffusion.transformer_blocks` is an unregistered tuple referencing both. Primary patcher `additional_models` retains the secondary owner. Its routing objects preserve device placement and contain no alternate retained output cache; the per-forward transfer cache clears in `finally`. These strong references make partial tuple deletion insufficient to dispose of the complete diffusion owner set. Native bulk unload copies the separately registered partitions; it does not need an explicit shard detach callback to cause the peak.

The OOM stack is the invoking systemd task's swap-in/allocation stack, not the killed server's allocation stack. No Python or native server stack identifies the exact allocation at the kill. The completed encoder receipt, absence of subsequent loader messages, device0-first offload path and later BCS fault make the bulk-unload phase the strongest source-backed location, but do not prove the final instruction. The later GPU event is not evidence that a GPU fault started the preceding host OOM. Shared DRM/GTT counters must not be summed as independent physical RAM allocations.

## Safer inactive successor boundary

Retain the unchanged diffusion model and shard, both VAEs and upscaler across encoder variants. Construct them once, and only retire/replace CLIP. This eliminates the unnecessary39.124GiB diffusion copy and reload from the transition. Keep the existing encoder restore/ownership proof, then drop all old CLIP strong references before constructing another encoder. Require actual weakref death, native registry cleanup and a new host-memory observation before replacement; fail if any owner survives.

`LoadedModel` stores patcher and real model as weakrefs (model_management758–818), and registers `weakref.finalize(real_model, cleanup_models)`. Native `cleanup_models` (1069) removes entries whose real models died. Therefore the registry should not require direct list mutation: dropping the real owner and collecting its cycles can trigger normal cleanup. This must be proven with the actual CPU loader in a future scheduled fixture; the source audit alone cannot establish finalizer ordering or identify every external reference.

The actual server uses `--cache-none`; `CacheSet.init_null_cache` installs NullCache for both outputs and objects, and NullCache retains no values. `ExecutionList` and its dependency-link cache are local to one `execute_async`, with consumed-node entries removed. `PromptModelTracker` only holds dynamic patchers; this lane is static, and its state clears at start/end. There is no designed cross-request graph cache owner of the retired CLIP. Hidden references or callbacks remain grounds for fail-closed weakref checks, not a reason to force-delete registry entries.

A generic discard-all optimization has no audited native no-copy disposal API here. `detach(False)` preserves loaded weights and is not destruction; moving to meta or rewriting registrations would alter shared owners and bypass normal lifecycle. If all immutable disk-loaded components were ever discarded, a separate terminal no-reuse ownership proof and reference release would be required. Keeping the unchanged components is a smaller, safer next experiment.

The existing8GiB client free-RAM guard is insufficient for this transition's explicit copy allocations. A successor needs source-derived restore/constructor destination bounds, pre/post memory receipts and a fail-closed admission floor. No swap, page-cache or power changes, retries or automatic restarts follow from this incident. Inactive source preparation and stdlib lifecycle tests may proceed; actual CPU/native qualification remains separate and halted under the fault.
