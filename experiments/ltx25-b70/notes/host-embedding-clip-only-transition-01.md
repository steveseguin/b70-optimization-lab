# Inactive CLIP-only transition successor

2026-09-14. After the [packet11 OOM audit](host-embedding-transition-memory-audit-01.md), new source retains diffusion/shard, video/audio VAEs and upscaler across encoder modes. Only CLIP is restored, released and replaced. Packet11 and its original component node remain unchanged. No application, endpoint, native CPU, GPU or settings action was performed for this preparation; the fault halt remains active.

Source: [resident v2](../scripts/host_embedding_resident_node_v2.py), SHA `bdaa14a06bd9937946eee470e562f6109df239273e905197d6e94fad28dd02f7`, plus the new stdlib [memory helper](../scripts/host_embedding_transition_memory.py), SHA `707de7176a47a26063b7282fc7368818d3362b1bd917c76141d58ed00dfcdb86`. The complete source and fake test are preserved in [transition patch01](../patches/host-embedding-clip-only-transition-01.patch). A future packet must include the new helper and new component schema; packet11 admission/client are not automatically compatible.

For a mode transition, the node inventories current registered state, records `/proc/meminfo`, and admits the explicit non-CPU parameter/buffer bytes needed for encoder restoration plus the existing8GiB operational headroom. It then runs the unchanged ownership restore and writes its unload receipt. All old CLIP strong references in the component slot and local variable are dropped before collection. The unchanged nonencoder components remain strongly held in a separate `_shared` tuple.

Saved weakrefs cover old CLIP, group, patcher, encoder model and, when applicable, host owner, host patcher/model and table. After `gc.collect()` and native `cleanup_models()`, every weakref must be dead and the retired patcher IDs absent from the native loader view. No direct loaded-registry mutation occurs. The loader's weakref finalizers perform normal dead-model cleanup; this is not a promise that GC can remove an externally retained owner. A retained clone/model/tuple causes a hard failure before replacement allocation. A receipt binds nonencoder owner IDs and completed retirement.

Construction has a separate post-release admission. The pinned CPU static loader uses non-assigning state load: source checkpoint tensors may overlap separately allocated CPU parameters. The independently audited conservative overlap is26,263,774,294B checkpoint payload plus26,231,584,372B registered state =52,495,358,666B (48.890113GiB). See [constructor review](host-embedding-constructor-memory-review-01.md). The node adds the already-used8GiB operational margin; it does not claim this margin was measured as allocator/tokenizer/driver overhead. Mapped source pages are reclaimable, so this is a conservative tracked-storage admission, not a proven hard peak. Header offsets and file extent must match the audited checkpoint before allocation. Swap capacity is never counted as available headroom.

Pre-restore, post-release, pre-construction and post-construction receipts preserve memory observations. Missing, malformed, negative or inconsistent meminfo fails closed. Insufficient conservative headroom stops before the dependent allocation; the node must not lower the floor just to pass. Failure latches the component factory and retains its shared or partial owners. It performs no bulk unload, device-wide free-memory call, cache clearing or retry.

Initial construction preserves the original UNET→CLIP→VAEs→upscaler→shard assembly order. The UNET cold load still precedes the new CLIP-specific construction gate. This is therefore a CLIP-transition memory fix, not a qualification of complete cold-start memory safety. Future cold-assembly admission, if desired, is separate work.

Ten stdlib fake/header-only groups passed: three generations retain exact shared owner IDs and construct nonencoder components once; old CPU-table owner weakrefs die; retained external model or output tuple fails; restore allocation and constructor floors stop before their respective operation; construction failure retains shared owners and refuses retry; exact threshold and no-swap-credit cases; malformed meminfo; actual checkpoint header-only extent; and source exclusion of bulk offload/device movement/direct registry mutation. Evidence: [receipt](../data/host-embedding-resident-v2-stdlib-01.json), [log](../data/host-embedding-resident-v2-stdlib-01.log). These fakes prove Python orchestration only, not native full-model release, driver allocation lifetime or a successful next campaign.

Independent source review found no concrete CLIP-transition blocker and called out the cold-UNET limitation above. Actual guarded CPU lifecycle qualification, packet reconstruction, updated client receipt admission and any later native run remain pending; none may run through the active fault latch.
