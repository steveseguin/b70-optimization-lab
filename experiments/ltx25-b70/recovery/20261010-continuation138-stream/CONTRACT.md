# Packet 138 contract

Parent: sealed 137, manifest
`18c80d25c2ba4992d8c6dff24779737a056a325389a84486d24da674ef7e463e`.
All inherited arithmetic, byte comparisons, memory floors, graph ownership,
source closure, fault, storage, reset and nine-chunk qualification rules remain.
Preparation is CPU-only; a seal is not native qualification.

`LTX_TEXT_PREFETCH=off` is the default and retains the 137 computation.
`scheduled` requires the admitted 145-frame split36/native-display-on-card-3
configuration and its unchanged parent conditioning oracle. Option identity is
bound through status, qualification verdict, receipts, decode and preview
records and client expectations. Each arm has a distinct run name.

A stream request may carry the optional pair `schedule_position` (integer
0 through 39) and `schedule_sha256` (the exact pinned kitten table hash).
Absent means no scheduled candidate. A partial or malformed pair refuses.
The request prompt remains authoritative. A predicted value can be consumed
only by its bound successor, chain and prompt, without reset or reuse flags.
A mismatch discards it and takes the ordinary fresh worker path. It must never
reach the pipeline's mismatched-tag inline fallback.

The decode thread schedules and collects onto an already-qualified encode
worker. It does not execute a third set of text graphs. The worker runs the
same native wrapper and suffix window with the same weights, placement,
precision, synchronization and embedding-observation handling. No graph
capture is permitted. Producer and consumer conditioning must match every
parent oracle tensor row. Worker window/stream state must be restored. Real
pipeline jobs must be collected before inherited request-boundary checks.

Only one extra conditioning may be retained, on CPU. Text arithmetic stays on
xpu:2 and xpu:3. No reserve or memory floor is reduced. Qualified eager,
optimized and repeated outputs still require exact image, waveform, latent
and anchor hashes. CPU fakes test protocol and refusals, not native arithmetic.
Both the graph and repeat qualification chains must consume a verified
prefetch at their chunk-two cut. Missing or late qualification hits refuse
admission. Streaming misses use the unchanged fresh encode path.

The client preserves inner-plan pins and every historical packet pin. Its
`--pacing-log precise` mode records hold start/end/duration using a monotonic
nanosecond clock. The default CLI log mode is legacy; the 138 wrapper defaults
to precise. Ledger primary periods use every consecutive destination>=10
interval ending before the first hold of each invocation, retaining cuts and
outliers. Raw periods and later hold-free diagnostics remain separate. No
rounded historical hold duration is subtracted from a server interval.

See the repository design note for mechanism, predicted savings, limitations,
measurement procedures and final evidence. Launch instructions are text only.
