# Qwen3.8 Flash-Next FP8 A57 same-server depth-determinism probe preregistration

Date: 2026-09-02
Status: diagnostic; frozen before launch; no promotion claim possible

## Question

At which prompt depth does the full-graph TP4/EP4 MTP0 line stop producing
identical greedy outputs for identical requests to one healthy server?

A56 showed two identical 2048-token requests to one server returning
different 128-token outputs (`243b555d...`, `ec96db80...`), while 146-token
prompts were exact across 16 repeats and three rows. A55's single 2K row
(`6bebd491...`) and A44's 4K rows show the same class of variability. The
certifiable lossless context therefore ends somewhere between 146 and 2048
prompt tokens, and the boundary is unknown.

## Design

- Server: byte-identical to A56 (tuned M1 W13-N32 map, `twoshots`, full
  decode graph `[1]`, external checkpoint, PLE-only UVA placement, 2304 max
  model length, host guards) generated by
  `tools/rewrite-q38-a56-to-a57-depth-probe.py` at attempt 57 / port 19729.
  Packet hashes: launcher `c14b12c2...`, client `aa99a519...` (frozen but
  not executed), supervisor `7abd67ac...`, host wrapper `956aa787...`.
- Client: `tools/probe-q38-a57-depth-determinism.py`. It verifies the live
  server environment carries exactly the A56 tuned folder, then for each
  depth in `256, 512, 1024, 1536, 2048` sends three identical greedy
  `/v1/completions` requests (prompt = the first N token ids of the frozen
  2048-token exact-depth fixture case `a173e60e...`, `max_tokens=128`,
  `temperature=0`, `seed=1`, `ignore_eos`, `return_token_ids`), records each
  output's token-id hash (same canonical encoding as the battery), the
  first divergence position against repeat 1, and cached-token usage.
- Output: `<run_dir>/a57-depth-determinism.json` with per-depth
  `deterministic`, `distinct_output_hashes`, `first_divergence_vs_repeat1`,
  `all_cached_zero`, and a `boundary` block (largest deterministic depth,
  smallest nondeterministic depth). The probe then writes the supervisor
  stop file; because the frozen lossless client did not run, the supervisor
  records an invalid stop (rc 70) and the host wrapper tears down and
  restores swap/ASPM. That is the expected end state.

## What the outcomes mean

- All depths deterministic: the A56 2K divergence was not reproducible in
  this server; repeat A56's 2K rows with more repeats before concluding.
- Deterministic up to some depth D and not above: D bounds the certifiable
  lossless context for this line; the next diagnosis compares the
  chunked-prefill boundary (`max_num_batched_tokens=64`, so 2048 tokens is
  32 chunks) and the collective path (public oneCCL, `twoshots` below the
  4096-byte LL threshold, larger messages above it) by toggling one at a
  time on fresh servers.
- Nondeterministic already at 256: the problem is not prefill length; the
  short battery's 146-token exactness would then be the outlier to explain.

No speed is measured or claimed. Protected results remain unchanged.
