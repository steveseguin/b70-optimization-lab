## Quality Caveat

I added `--compilation-cache-dir` to the quality harness so it can target an
explicit compiled-cache directory. The sync `LLM(...)` quality path fails on the
preserved AOT pair during startup:

`AttributeError: 'MiniMaxText01RMSNormTP' object has no attribute '_minimax_clean_weight_xpu'`

That means the recovered `88.8-88.9 tok/s` path is not promoted. It is useful as
a recovery/debug clue, not as a quality-gated replacement for the archived
LocalMaxxing result.

## Decision

- Do not claim the exact `89.5 tok/s` runtime still works from the current cache
  state.
- Keep the LocalMaxxing result as an archived, previously quality-gated result.
- Treat cache roots and AOT payloads as part of the performance artifact.
- Before any future source instrumentation, copy the whole candidate
  `VLLM_CACHE_ROOT` aside and record:
  - torch.compile key
  - AOT key
  - AOT file sizes and mtimes for all ranks
  - selected source hashes plus traced-code cache metadata
