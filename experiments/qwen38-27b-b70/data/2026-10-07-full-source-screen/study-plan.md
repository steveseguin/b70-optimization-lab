## Outcomes and evidence

Require one complete submit JSON with exactly the original 24 typed answers.
Apply the same answer scoring as the history task: eight current, eight earlier
balance and eight ownership-join answers. Preserve malformed, missing, null,
wrong-type, extra-ID and capped responses as observed failures. A non-stop finish
cannot pass even if a partial response contains correct numbers. Unknown usage
is not zero cache. Strict final-task success requires complete valid coverage,
24/24 answers, successful finish and no infrastructure error.

Preserve exact request, raw response, usage, elapsed time, generation and source
identity, result hashes, both planned rows and an independent replay audit. Report
intermediate checkpoint/event quality as null/not applicable; never set the
streaming full-quality flag. CPU stubs validate wiring only and cannot pass model
quality or cold-cost interpretation. The independent audit must reconstruct the
public request and answer reference, not trust result booleans.

Measure request time and total task time including request/result persistence;
report offline packet preparation and server lifecycle costs separately. The
streaming comparator includes initialization, ingestion, rejected attempts,
answering and persistence. Only exact, cold, completed final-answer outcomes are
eligible for descriptive cost comparisons. This standalone two-request screen
does not satisfy the fresh-server paired speed rule or admit a performance claim.

## Interpretation and stop rule

This tests static final answering with source and questions available together.
The streaming methods see questions after ingestion, can spend more total
reasoning, and offer observable intermediate states. These differences are
intentional and must remain visible in the report.

If direct answers are exact and materially cheaper on both documents, use direct
source as the default for this short static use case and stop retrieval-interface
tuning there. Otherwise preserve and classify the failures before proposing any
next model work; no automatic rescue matrix. Neither outcome establishes broad
memory quality or a capacity limit: each document is only about 1,500 source
tokens. After these two requests, the supervised owner must stop its server,
verify card release and run health checks. No resident service or automatic
restart, host setting change, reboot or device reset is authorized by this plan.

Implementation, tests, independent review and a frozen dependency packet are
required before admission. This plan alone does not launch anything.
