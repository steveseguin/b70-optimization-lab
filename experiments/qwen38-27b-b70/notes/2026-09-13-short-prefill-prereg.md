# Short-context prefill measurement and exact optimization screen

User requested prefill measurements and optimization for Qwen3.5 4B/9B W4A16 and Qwen3.8 27B FP8/INT4, concurrency one, small context, preserving lossless quality and decode speeds.

Host: steve-TURIND8-2L2T, two B70s. Raw root: `/mnt/fast-ai/bench-results/qwen-short-prefill-20260913`. Existing R308 strict TTFT and R304 2K depth evidence will be retained as historical references; they are not matched isolated prefill rates.

Measure exact 128/256/512-token inputs, prose/code/documentation, 128 output tokens, three serial repeats in alternating order, separate compilation warmups, prefix caching disabled. Record HTTP TTFT and prompt-tokens/TTFT explicitly as a proxy, plus isolated per-request server prefill histogram deltas where exposed. Record numeric input/output IDs, repeat parity, cache-zero, full decode and conventional 99-interval timing (burst arrivals labeled). This is a diagnostic prefill screen, not a replacement decode headline.

Use the pinned R308 image for 4B/9B TP1 MTP3; R304 for 27B INT4 TP2 MTP4 and FP8 TP2 MTP1, existing arithmetic/quantization/KV/graph settings, capacity1024, batch budget1024, max sequences1. One model at a time. Keep one endpoint per profile for all requests; no automatic restart/retry chain, no power, swap, cache-drop or driver changes. Monitor kernel faults; stop requests and halt the campaign on a device fault. Capture launch identity, model manifests, logs and health before/after.

Optimization hypothesis: the existing FP16 linear custom op makes 32-row GEMMs then concatenates outputs. Preallocating the destination may remove allocation/copy work without changing any GEMM dimensions or reduction order. First screen exactness and position-balanced timings at the operator level with representative weight shapes, zero/mixed/random inputs and tail rows. Decode branch (rows <=32) must remain unchanged. Reject any numerical mismatch. A faster operator alone is not an endpoint win; adopt no runtime change without matched full-output parity and prefill improvement beyond noise, with decode regression below3%. Global classpad, fixed-K removal, precision changes and wider chunk arithmetic are excluded.

If no candidate clears these gates, retain the existing runtime and publish measurements plus negative evidence. New speed promotion still requires the full realistic suite and independent process repeat; this bounded screen cannot waive those gates.

Operator screen completed before model launch: 72/72 rows bitwise exact, including repeated baseline/candidate, about 1–5% median operator gains by shape. Endpoint experiment uses a default-off single-file overlay of each pinned parent. Within each loaded endpoint, control/candidate/control is selected by an empty flag in its unique cache mount; only m>32 bias-free FP16 calls read the flag, and the unchanged decode branch runs first. Run three measured repeats per mode and the full strict suite control/candidate, compare full numeric outputs, then remove the flag and repeat control. No model restart is needed to switch modes. Validate all parent runtime hashes and require every overlay hash other thanutils.py unchanged. No same-process speed result is independently qualified for promotion.
