## Thinking Mode Smoke Issue

The first smoke request used the default Qwen thinking template. The server
returned `content=null` and placed text in the OpenAI `reasoning` field, then
stopped by `length` at 64 tokens. That is valid model behavior but wrong for a
deterministic content smoke.

Fix applied in the experiment scripts:

- `smoke-openai.sh` now sends
  `chat_template_kwargs={"enable_thinking": false}` by default and handles both
  `content` and `reasoning` fields without crashing;
- `serve-vllm.sh` and the model-slot profile now default the service to
  `--default-chat-template-kwargs '{"enable_thinking": false}'` unless the
  caller intentionally overrides thinking.

  cache changes can produce degenerate output or regress latency. Treat
  graph/KV experiments as correctness-sensitive, not pure speed knobs.
