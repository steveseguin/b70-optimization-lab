# Sigmoid CPU oracle — closeout

## Question and identity

Resolve Flash-Next output-gate arithmetic from the official architecture code,
then measure the independent CPU oracle within three hours on steve-b70s.
Model: Unsloth UD-IQ3_XXS quantized compressed version, revision
`766911a6b7369840a91dbcd95f9f997acaab6cd6`; this is a separate model from FP8.
Identity: `iq3-cpu-fp32-m1-bf16-state-sigmoid-v1`, source snapshot
`3ebd0d2b1504648be50c122fb7899005d999be4a`. Fixed twelve-prompt suite order,
64-token cap, nice 19, eight numeric threads, CPU only, bounded read-only maps.
The run started 2026-10-11 UTC and stopped at its three-hour deadline.

## Outcome

Gate decision accepted: QSA and GDN output gates both use sigmoid. Official
Qwen4Exp GDN reads the gate-type field, unlike the cited 27B full-attention
case. The previous GDN SiLU choice is superseded; other SiLU activations stay.
The corrected synthetic reference passes 38 tests and fresh-process equality.

The first two prompts completed 64 generated tokens each: incident decode
43.331 seconds/token and code-review 46.184 seconds/token. Prompt passes took
1,985.579 and 1,972.712 seconds. The incident eight-token pilot was 43.582
seconds/decode token, below the 600-second extension gate. Total run time:
10,800.047 seconds; peak RSS: 1.057 GB. Customer-email stopped after 32/48
layers, with zero output tokens. Nine prompts were not started.

## What worked

Streaming packed-weight reads held memory below the 40 GB limit. Every saved
token has IDs, top-five logits, timing and a full-logit hash. There are 48
step-1 BF16 layer fixtures for each completed prompt, plus 32 explicitly
partial customer-email fixtures; all 128 hashes were verified. All 23 original
source hashes resolve to the snapshot commit above. Model file metadata stayed
unchanged; packet 1's full-file SHA256 receipts are retained, not remeasured.

The incident shares 68 characters with both llama.cpp baselines, then uses
Executive Summary instead of Summary. Code-review shares zero visible
characters: its two-card baseline immediately ended, while the CPU emits
`# Code Review...`. The baseline topologies themselves diverge at incident
character 180 (error rates versus request failure). These are informational
comparisons; llama.cpp is not the arithmetic authority.

## What failed or remains uncertain

The full twelve-prompt suite did not fit. No full-model same-process or
fresh-process repeat was performed; synthetic repeats are not substitutes.
Device parity and certification remain unverified, including the inherited
cast/reduction uncertainties. This gate correction does not assert exact
Transformers execution parity. No GPU, server or device launch occurred.

Read-only review found and tests now cover two comparison-reporting defects:
empty partial prefills could appear compared, and immediate baseline EOS could
look like a vacuous prefix match. The comparator was corrected after the run
and has its own hash in the final comparison; numeric source and outputs did
not change. One-card comparison still reports visible text only, sufficient
for this row's within-text divergence.

Runner limitations remain explicit: the live receipt adds a started prompt
only after its first token, while progress/partial fixtures persist separately;
finalization saves incomplete rows but replaces their phase with the stop
status. A failed final model-metadata check can prevent saving the final
receipt. That failure did not occur here. The coverage artifact records actual
requested counts and distinguishes completed, partial and unstarted prompts.

## When to revisit

Finish the uncovered prompts and full-model deterministic repeats under this
same arithmetic identity before qualifying a device implementation. A device
must match generated token IDs and step-1 BF16 layer bytes, then pass same- and
fresh-process repeats; baseline similarity or speed cannot replace these
gates. Fix the documented receipt-failure handling before unattended reuse.
Any arithmetic change needs a newly named oracle. This bounded run is closed;
the model runtime lane remains open and native work requires its own admission.
