# Packet 2 — streaming IQ3 CPU oracle preparation

**Arithmetic decision pending; no full-model run or token oracle certified.**
The CPU forward, prompt/tokenizer preparation and bounded packed-weight reader
are implemented. The full-model pilot has not run because the requested frozen
reference conflicts with the pinned model configuration: packet 1b's
[`gdn`](../../own-xpu-runtime/stage2/packet1b/reference.py) applies **SiLU** to
its output gate, whereas the retained publisher
[`config.json`](../../own-xpu-runtime/stage2/packet1/metadata/config.json)
specifies **`output_gate_type: sigmoid`**. The retained implementation of
`QwenGatedDeltaNetAttention` reads that field. This is an output-changing
arithmetic choice, not a performance setting. The owner has been asked which
authority to use; elapsed time is not approval. The command requires an explicit
choice and neither variant is silently certified.

This is the separate Unsloth UD-IQ3_XXS quantized compressed model, revision
`766911a6b7369840a91dbcd95f9f997acaab6cd6`. Its authority must be its exact
published bytes and a frozen, accepted CPU arithmetic identity. llama.cpp
comparisons are informational, and FP8 output differences are not a tolerance
gate. This preparation does not alter packet 1b or the FP8 lane.

[`qualification.json`](qualification.json) passes all **156 retained real
weight windows**, bit for bit against packet 1's scalar-loader fixtures, plus
**160 synthetic quantized blocks** including negative and signed-zero scales.
The norm and GDN decay storage adapters match the original reference on their
operator fixtures. Stored/original head-order permutations round-trip exactly.
All twelve prompts round-trip through the tokenizer and match the independent
`tokenizers` BPE implementation, using authenticated GGUF vocabulary and merge
arrays. The incident prompt has **87 tokens**. Its count and all other prompt
counts match the baseline runner. The isolated [PLE binding test](ple-binding-test.json)
also matches batched and serial outputs/state bit for bit on four synthetic
hidden rows using real PLE weights, crossing its dilation-three boundary.
This is not a complete-model fixture. The rendered files also match the actual
`/home/steve/build/flash-next-iq3-baseline-20261010/window-inputs/` files byte for
byte. They were generated by the unchanged baseline `prepare-prompts.py`;
the requested AutoRound suite and the baseline's rapid-model suite have the
same twelve prompt IDs and prompt bytes despite different suite metadata.

[`reference_gguf.py`](reference_gguf.py) vendors the lab's stage2 packet1b math.
[`reference-gguf.patch`](reference-gguf.patch) lists every change, and
[`arithmetic-decision.json`](arithmetic-decision.json) binds source hashes.
GGUF stores `1+w` norm gains and negative `exp(A_log)` decay controls, so the
adapter uses those values directly rather than adding one or taking an inverse
logarithm. F32 controls stay exact. The GDN value-head layout is reordered back
from GGUF `[3,16,D]` to the reference's `[16,3,D]`; output projection inputs are
reordered back to stored column order. The pending gate has explicit `silu`
and `sigmoid` choices; all other inherited operator math is retained.

The CPU reduction identity uses packet1b's FP32 adjacent-pair trees, its
32-lane/four-product GDN dot order, ascending convolution taps, and selected
expert order. Linear adapters dequantize to **FP32 without a weight BF16
rounding**, then use the reference's 128-output-row FP32 CPU matmul tiles and
BF16 output boundary. Every input row is an M1 matmul, including prefill, so
batch size does not choose a different matmul path. CPU build, ISA capability,
thread counts and code hashes belong to each run's receipt; cross-build
bit-identical BLAS/transcendentals are not asserted. Persistent GDN state
rounds BF16 after each row. QSA retains full BF16 K/V and its architecture's
four-key pooling. Routing is top ten with stable lowest-ID ties, logical
selection-order accumulation, and the shared expert. The head evaluates all
248,320 rows, rounds its output BF16 as packet1b does, widens to FP32 for
logging, and resolves tied maxima by lowest token ID.

Packet1b did not implement the full PLE injection. The added binding at
`layers.1` uses its existing `ple_ids`, norm/tree and chronological convolution
primitives: read sixteen actual IQ4_NL rows, concatenate into H2560, project
key/value, normalize each HC stream, signed-square-root sigmoid gate, grouped
norm and dilation-three convolution, SiLU, then residual addition. Explicit
BF16 eager boundaries are recorded in `Model.ple`; convolution accumulation
and elementary operations use FP32. The GGUF PLE table already includes its
published scaling, so no official FP8 scale is reapplied. Its full integration
has **not** been exercised by a real-model forward yet. The mathematical and
storage-format research sources, including the missing PLE path and converter
layout, are pinned in [`research-sources.json`](research-sources.json); none
of those external runtimes is imported or used as the code base.

[`oracle.py`](oracle.py) opens admitted files read-only, verifies their recorded
inode/device/size/mtime/ctime, reconciles parsed tensor descriptors, and carries
packet 1's complete shard SHA256 receipts into the run receipt. It does not
pretend a new full-file hash was computed. Each packed row tile uses a bounded
read-only mmap that is closed immediately, leaving shared host page cache
alone. There is no whole-shard mapping, whole-expert-bank load, persistent
weight cache or checkpoint copy. Only each row's ten selected experts are
decoded; no expert cache survives even an expert call. State/KV persist only
within that prompt. A 38 GB address-space cap and RSS guard leave margin below
the owner's 40 GB RSS ceiling. Run at nice 19, eight numeric threads, one
interop thread; all preparation uses two threads. No GPU, server, Docker,
systemd, device node, port 8188, LTX unit or host setting was accessed.

**Measured runtime cost:** full-model seconds/token is **not measured**.

The first incident prompt is processed in full, followed by eight generated
tokens unless EOS arrives earlier. After seven decode forwards, mean measured
decode cost must be below 600 s/token to extend to 64 and subsequent prompts.
The runner respects immediate end-of-text and end-of-message tokens, without
padding or retrying. It saves per-layer progress, every completed token's ID,
top-five IDs/logits and timing, and atomic receipts. The four-hour guard and
SIGTERM/SIGINT are checked between layers and selected experts. Completed
tokens survive a stop; unfinished forward state is not resumable. A stopped
prefill can leave partial layer fixtures, which must never be called a complete
prompt oracle. No scratch is retained; all files here are deliberate evidence.

For generated step 1 (the prediction at the final prompt position), the run
will write `PROMPT/step1/layer-00.bf16` through `layer-47.bf16`, each 20,480 bytes
with shape `[1,4,2560]`, plus `layers.jsonl` with hashes. Each prompt also gets
`input.json`, `progress.jsonl`, `tokens.jsonl` and `result.json`; the run gets
`receipt.json` and `baseline-comparison.json`. The baseline comparator strips
only the CLI's documented trailing framing and re-tokenizes visible text;
it reports token and character agreement and first divergence. Detokenized
output cannot recover the precise EOS ID and can merge a truncated last token,
so those limits remain explicit.

Device bring-up must match each covered prompt's token IDs bit for bit under
the accepted arithmetic identity, including its EOS decision. It must also
match the per-layer step-1 BF16 bytes/hashes to localize errors, then pass
same-process and fresh-process deterministic repeats. No CPU full-model repeat
has run yet, and these preparation tests do not pass that gate. A changed
arithmetic identity requires a newly named oracle and receipts; baseline
agreement or speed cannot substitute for those checks.
