## Top three changes

1. **Have this recurring audit run `git rev-parse --is-shallow-repository`
   and, if true, `git fetch --unshallow` before computing any metric.**
   Evidence: this run's first pass, on a shallow clone, read commit
   `9ad6d4f2`'s blank `%P` as a parentless root commit and its diff against
   an empty tree at the boundary (36,076 files, 44.9M insertions) as a
   history-destroying squash; `git cat-file -p 9ad6d4f2` shows a real
   parent. Saving: removes a class of false "history destroyed" verdicts.
   Generalizes: every git-timestamp metric is wrong the same way from a
   fresh shallow clone until this check exists.
2. **Extend the metrics script's campaign glob to also match
   `experiments/*/data/*/preregistration.json`.** Evidence: the real window
   added 11 files matching `*prereg*.json`, but the top-level-only glob
   counted 4; the other 7 (e.g. `ltx25-b70/data/metadata-dispatch-cpu-01/
   preregistration.json`) are invisible to every metric here. Expected
   saving: restores real campaign-throughput visibility. Generalizes: any
   lane using the per-campaign-subdirectory convention is undercounted
   every week.
3. **Fix the closure scanner's path regex to handle brace-expansion
   (`{a,b}`) instead of truncating at `{`.** Evidence:
   `repro/qwen38-27b-autoround-int4-b70/README.md:96` references
   `onednn-qwen38-w4a16-{strategy-override-dump-r220,fixed-k-two-tier-r221}-...patch`,
   both halves tracked, but the scanner reports the truncated prefix as a
   blocking `missing_path` (one of `qwen35-4b-w4a16-b70`'s 8). Saving:
   removes false GAPS so real ones aren't lost in noise. Generalizes: any
   guide crediting a paired patch this way hits the same false positive.
