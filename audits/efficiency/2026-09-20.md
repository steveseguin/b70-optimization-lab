## Top three changes

1. **Never launch a new GPU campaign on this host after a note declares it
   corrupting data, until the memtest that note demands actually runs.**
   Evidence: packet 83 found byte-level corruption on two boots, naming
   memtest86+ "ahead of every software lever"; packets 84-86 reloaded
   three more times on that unconfirmed boot (`58ae370e`), leaving
   packet 84's "provisional" pass unverified. Saving: stops GPU time on
   untrustworthy results. Generalizes: hardware corruption needs a hard
   gate.
2. **Run this audit's metrics scripts against a clean checkout of the
   endpoint commit, after unshallowing — never the audit's own branch.**
   Evidence: this run misread shallow clone `9ad6d4f2` as a squash
   (665/327/338 vs 660/323/337, since revised to 715/368/347 above).
   Saving: removes a repeatable false-metrics class. Generalizes:
   every run risks it.
3. **Redesign campaign discovery in the metrics script — a glob edit alone
   won't fix it.** Evidence: the top-level glob counted 4 of 11 JSON
   pregs; still mislabels the lane, can't pair a nested preg, and
   misses `*-prereg.md` under `notes/`. Saving: restores throughput
   visibility. Generalizes: every lane is undercounted.
