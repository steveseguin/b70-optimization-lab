  bird clip" work used a replay harness (`cc83d673`) instead of blind
  bisection, in the rule's spirit.
- Oracle bound to kernel identity: compliant — each encoder-shard change
  (packets 82/83) was re-verified bitwise against the current baseline.
- No speed verdict from <2 servers: no violation; packet 84's "1.9% gain"
  logged interim, not promoted.

  still pending.

  (5/5), not grinding on.

  adaLN fusion) continued offline while the host waited.
- One lane per host: compliant — LTX on `steve-b70s`, MiniMax-H3/Qwen-FP8
  on `steve-TURIND8-2L2T`. Why the second host's idleness isn't explained
  by the first host's fault.

## Top three changes

1. **Every lane-halt note must state which other lanes/hosts are *not*
   blocked.** Evidence: the 09-20 halt note lists four user-held items for
   `steve-b70s` but says nothing about `steve-TURIND8-2L2T`, which had no
   dependency on them and sat untouched 8 days. Saving: recovers idle time
   on any unaffected host during a future halt. Generalizes: rule 8 already
   forces one-lane-per-host isolation; a halt note should say so explicitly.
2. **Surface halt/blocked state at the top of `CURRENT.md`, per lane.**
   Evidence: the banner (2026-09-19 23:55 UTC) predates the halt and buries
   it ~400 lines down, in the file AGENTS.md's "First Read" requires every
   agent read first. Saving: minutes of ramp-up per session; avoids
   restarting campaigns on a still-blocked host unnoticed. Generalizes: a
   format fix to the one cross-lane authority file.
3. **Give user-held blocking items a standing "still open" marker.**
   Evidence: memtest86+, the BIOS setting, the cmdline change, and the PSU
   check sat 8 days with no record anyone re-flagged them. Saving: closes
   the gap between "still deciding" and "forgot this was pending."
   Generalizes: any future physical/BIOS action only the user can take
   shouldn't depend on them rediscovering a note file.
