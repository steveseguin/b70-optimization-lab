## Top three changes

1. **Give the hosted server a tracked handback line now that its timeout is gone.** Evidence:
   `LIFETIME_H` went 47→0 (101d5e3cc); `CURRENT.md` sets no revisit date. Last week's audit flagged the
   same hosting at 41 hours with a timer still running; it is now open-ended past 5 days. Saving: a
   one-line "hosting started/next check" entry turns an invisible stall into a dated owner decision.
   Generalizes: any lane that replaces a self-timeout with resident hosting, on either host, needs this
   line every time it hosts.
2. **Rotate attention to the two-card host's stale active lanes.** Evidence: `qwen38-27b-b70` (16.3
   days) and `minimax-h3-b70` (29.5 days) are idle while that host is otherwise free. Saving: two B70
   cards are producing zero optimization while fully available. Generalizes: whenever one host is
   consumed by a single lane or by hosting, check the other host's active-lane list before calling the
   week's throughput complete.
3. **Mark deliberately campaign-free weeks so a zero is legible.** Evidence: `campaigns_total`=0 and
   `n`=0 this week is correct (no campaign ran), but identical in the JSON to a stalled week; only the
   notes distinguish them. Saving: one `CURRENT.md` line naming the reason removes a full note read-
   through for every future auditor. Generalizes: a bare zero needs a reason attached, since it can mean
   either a script blind spot (last week) or a deliberate pause (this week).
