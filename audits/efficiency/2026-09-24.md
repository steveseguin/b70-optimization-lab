## Top three changes

1. **Write one fault-classification runbook the human follows, not an
   automated runner** — the stability constraints ban host-controlled
   benchmark wrappers outright, so rule 4's runner-owns-every-stage design
   doesn't apply, whoever aborts or reboots. Packets 77–90 each cost a
   human investigation (VAE-gate latch, freeze, muxer error, capture
   refusal) before the next packet launched; a written symptom→next-packet
   decision tree cuts that time with zero automation — generalizes to any
   host under a similar no-wrapper constraint.
2. **Extend the metrics script's scan to notes files, and its cohort
   selection to event dates, not bulk-import commit dates.** It scans a
   result JSON's `status`/`decision`/`classification`, never `notes/*.md`
   (rows 26–27), and treats every file the import commit adds as
   "this week's" regardless of the experiment's actual date — the cause
   of this table's own bulk-import contamination.
3. **Run the closure scanner on a candidate before it accumulates more
   evidence.** The 12 packages above carry `host_path_hardcoded` or
   `missing_release_asset` findings — cheaper now than at promotion time.
