## Top three changes

1. **Add `watchdog:.*hard LOCKUP` to the shared GPU-fault fast-fail regex.**
   Evidence: two identical in-server hard lockups 09-15
   (`xe-lockup-incident-01.md`), one undetected since the pattern only
   matches `Fault response|CAT error|engine reset|GPU HANG|GuC.*reset|
   coredump` plus RCU/soft-lockup forms. Saving: faster detection *only*
   during an active launcher/runner, as in both 09-15 events — not the
   09-17 idle freeze (zero GPU process running; needs a host-level
   monitor instead). Generalizes to every lane's launcher.
2. **Make prereg discovery recursive and deduplicated by campaign id;
   add a shallow-clone guard.** Evidence: undercounted campaigns 4 vs
   ≤9 real ones (7 files invisible to the flat glob, 2 of which
   duplicate an existing id rather than adding one); the shallow clone
   separately fabricated `commits_total`/`campaigns_total`/latency,
   reported every audit `2026-09-03`–`2026-09-12`, unfixed 6+ runs.
   Saving: no manual re-derivation each week. Generalizes to every
   future week.
3. **Have the script resolve each campaign's actual outcome artifact,
   not one filename pattern.** Evidence: line 113 globs only
   `{stem}*result*.json`, missing `stability-01/summary.json` (`status`
   present) and `encoder-screen-01`, whose outcome is `progress.json`
   (`status: failed`) — not `summary.json` at all, so one extra pattern
   would still miss it. Saving: recovers real latency/outcome data
   across heterogeneous layouts. Generalizes to every non-`result.json`
   lane.
