## Top three changes

1. **Unshallow (or verify clone depth) before every scheduled audit.** Evidence:
   this clone was shallow; `campaigns_total` was 421 at 0h/0h latency, all
   misattributed to the boundary commit, versus 4 / n=0 after
   `git fetch --unshallow`. Saving: stops future reports from publishing
   fabricated throughput/latency. Generalizes to any lane, any fresh checkout.
2. **Widen `efficiency-audit-metrics.py`'s campaign glob** to also match nested
   `experiments/*/data/*/preregistration.json`, **and** fix lane extraction with
   it: `lane = prereg.parts[-3]` resolves to `data` (wrong) for that layout —
   widening the glob alone would silently mislabel every nested campaign. Derive
   lane from the path segment after `experiments/` instead. Evidence: `git log
   --diff-filter=A` in-window shows 7+ preregistrations under the nested layout
   the glob misses. Saving: correct per-lane visibility, not an undercount
   traded for mislabeled counts. Generalizes to every lane using that layout.
3. **Teach `public-closure-scanner.py` to recognize docker-env-only paths and
   overridable Dockerfile `ARG` defaults before treating output as a gate.**
   Evidence: both GAPS flags on `qwen38-27b-fp8-vllm-tp1-b70` are false
   positives (above). Saving: without this, gating publication on the scanner
   would block reproducible packages; the other 10 unverified GAPS candidates
   need the same patterns ruled out first. Generalizes to any package with an
   in-container env path or overridable base-image `ARG`.
