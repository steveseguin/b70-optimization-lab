## Top three changes

1. **Promote the new fault-signature preflight to every lane, not just this one.**
   `stable-mode/preflight.sh`'s 12-signature journal grep (`fault response`, `gt reset`,
   `Machine check`, `watchdog: BUG`, …) only existed from 2026-11-15, after ~14 resets were already
   diagnosed by hand in `CURRENT.md` prose. Move it into the shared probe path (`docs/local-ops.md` /
   `scripts/check-qwen36-xpu-xccl-health.sh`) so a new lane's bring-up starts fast-fail on day one.
   Saves each future lane's first-dozen-faults narration cost; generalizes to either host.
2. **Teach `infra_event_files` to read `CURRENT.md`, not only `experiments/*/notes/`.** This week's
   ~15 resets are almost all recorded in `CURRENT.md`, which the script does not scan for fault
   keywords; it reported 3 note files instead. Without this, "infrastructure tax" has to be
   hand-counted from `git log -p -- CURRENT.md` every audit, as this one did. Generalizes, since
   `CURRENT.md` is the one file AGENTS.md requires every lane to update.
3. **Extend campaign discovery to a lane's own arm ledger, not only `prereg.md`/`summary.json`.**
   `own-xpu-runtime` produced ~60 gated arms this week and `campaigns_total` read 0 — new evidence,
   beyond triage row 3's LTX gap, that discovery misses a second, now-dominant lane convention
   (`tpNNN`/`tgNNN ... gated/identical` lines). Without it, throughput and latency metrics cannot
   see the lab's busiest lane.
