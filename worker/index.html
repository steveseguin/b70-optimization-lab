Give your local AI a coding job

Describe a bug. The worker reads the code, edits a copy, runs tests, and returns a patch you can review.

  1. 1. Read the issue

This version uses Qwen3.8 27B FP8 on two Intel Arc Pro B70s. Model requests stay on the local machine. Coding commands run in an isolated copy of the repository, with network access disabled.

What it needs

A working FP8 model server, Docker, and a clean Git repository. The included coding environment supports Python standard-library and Node.js tasks. Jobs needing extra dependencies require a prepared environment.

Each task has a 20-minute limit and a 28,000-token input budget. If a task exceeds its limits or a model request fails, it stops and keeps the evidence.

Reading and writing speed

Prefill measures how fast the model reads a prompt. Decode measures how fast it writes a response. Coding prompts grow as the worker reads files and test output, so these task timings are separate from the fixed-length model benchmarks.

See the FP8 model’s measured reading and writing speeds. The test packet also records each coding request’s input size, reading speed, writing speed, and wait for the first token.
