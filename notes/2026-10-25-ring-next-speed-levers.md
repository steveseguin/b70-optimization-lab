# Speed work after depth-two ownership qualification

The quiescent actual-provider gate passed all 32 outputs, 2,065 target buffers,
73 canonical draft allocations, 117 true pairs and 32 actual recursive proposals.
The pending-target gate remains the next prerequisite. Both are correctness
experiments; neither measures a faster four-card conversation. Existing draft
weights remain unchanged and training is prohibited.

## Measure the rolling path first

After the pending-target gate, integrate actual asynchronous proposals with the
bounded ring coordinator. Preserve immutable issued guesses, ordered canonical
draft advancement, final-event ownership and complete rejection barriers. Compare
full state before running a persistent cold twelve-prompt performance suite.
The current two-card reference is 47.97 tok/s; the earlier depth-one four-stage
path measured 42.31 tok/s. Their timing observation layers remain disclosed.
Do not promote another single-prompt diagnostic as a replacement record.

## Candidate tuning order

1. **Rebalance stages using the new measured work.** The current 13/12/12/11
   layer split predates a second draft pass. Stage zero now owns both canonical
   and recursive draft work, plus its target checkpoint work. Record native
   stage timings and dependency waits from actual rolling execution, then choose
   a separately hashed placement policy. Packed-weight balance alone does not
   balance execution time. Preserve the current cut and every rejected cut.

2. **Investigate placing draft work on another stage owner.** This is a new
   ownership experiment, not an implemented capability or predicted speedup.
   A downstream owner could potentially compute guesses while stage zero processes
   the next verified input. Establish from the rolling trace whether that idle
   interval exists and is large enough. Current native admission deliberately
   requires a first-stage provider and a locally accepted seed. Moving it would
   require independently bound seed and final-parent records, separate state
   ownership, available weight/KV/checkpoint memory, and full reference replay.
   Do not delete those checks or duplicate the arithmetic executor. This could
   also make provider placement reusable across future topology profiles.

3. **Change checkpoint transport only if its measured cost warrants it.** The
   existing provider uses checked copies for its canonical inventory. A flattened
   descriptor copy already exists for target checkpoints and is a possible later
   implementation. Its descriptors must be explicitly provider-private and
   allocated before the target census freezes. Keep the ordinary copy version
   and validate every byte against it.

The [quiescent diagnostic timing](../experiments/own-xpu-runtime/research/continuation-2026-10-25/ring-live-depth2-diagnostic-timing.json)
records 32 head-enabled pairs: median canonical and recursive wall times were
2.045 and 2.007 ms; capture was 0.465 ms. The 10.051 ms median restore includes
full state readbacks for verification and is **not production restore cost**.
The first canonical head call is a large outlier; its cause was not isolated.
These observations do not predict rolling acceptance or end-to-end throughput.

Keep prompt-reading throughput as a separate lane: prompt inputs are already
known, so their scheduling constraints differ from generated speculative inputs.
Any improvement still needs batched-versus-sequential full state parity and cold
prompt timing. Do not mix it into a decode tok/s result.
