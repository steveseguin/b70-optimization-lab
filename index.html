Cookbooks and where to start

Pick your card count and model family. Every link lands on exact pins — image digests, commits, patch order — not vibes.

One B70, quick win

Start with the intel-arc-pro-b70-inference-cookbook: pinned vLLM XPU image, Qwen3.6/Qwen3.8 launchers, tool-calling flags included. Or a single-card llama.cpp lane like Gemma-4-26B at 124.98 tok/s.

Two to four B70s

TP2/TP4 lanes live in the lab's results index and model recipes — MiniMax INT4 TP4, Laguna INT4 + DFlash, DeepSeek-V4 FP4/FP8, Qwen3.6 dense TP2.

Understand before you run

The optimization timeline shows how each lane got fast; the performance index explains the metrics; the model optimization guide is the playbook for a new model.

Adjacent ecosystems

Apple Silicon users: the mlx.fast Qwen3.8-27B challenge ran 26 → 87.9 tok/s on MLX with editable MTP heads — methodology and ideas tracked in our field reports.

Contribute

Record-setting results are not required — careful negative results and quality checks are valuable too. Contributions enter as community-reported and are promoted only after reference-lab reproduction. That boundary is about evidence provenance, not trust.

  1. Pick up the checklist. GPU model/count/VRAM and PCIe details; OS, kernel, driver, runtime versions; exact model revision and quantization; engine commits; full command and environment; prompt/output lengths, batch, concurrency; cache and speculative policy; quality gate outcome; metric definition with repeats/variance; result JSON/logs or durable links; closest known-good run and exactly what changed. The full list is in CONTRIBUTING.md.
  2. Choose the right lane. Runnable recipes, patches, and configs go to community/ with a filled STATUS.md. Measurements or observations without runnable assets belong in community/field-reports/.
  3. Open a pull request against steveseguin/b70-optimization-lab. Keep changes focused, preserve failed-experiment evidence, and never silently replace an old result.
  4. Expect the eight-step validation. The lab reruns runnable entries on reference hardware when GPUs are free, per docs/contribution-verification.md. Evidence labels (B70-verified B70-tested community-reported) track exactly what was checked. Negative results are recorded as evidence, not deleted.
Never submit model weights, API keys, access tokens, or private data. Absolute paths like /mnt/fast-ai/... in recipes are the lab host's layout — substitute your own; see reference lab storage.
